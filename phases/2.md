# Phase 2: Field System

## Goal
Implement the complete field type system in Rust, mirroring every Django field with proper column type mapping across all three databases. Fields are descriptors that carry metadata (type, constraints, defaults) used by both the model layer and the migration engine.

## Scope
- `FieldDef` Rust struct as the canonical field descriptor
- All scalar, temporal, and special field types
- All relational fields (`ForeignKey`, `OneToOneField`, `ManyToManyField`)
- Field options: `null`, `blank`, `default`, `choices`, `max_length`, `unique`, `db_index`, `db_column`, `editable`, `primary_key`
- Python-facing `Field` subclass hierarchy via PyO3 — these are the *only* field types exported
- `to_column_def()` method: `FieldDef` → sea-query `ColumnDef` (for DDL generation)

## Relational Fields

```
ForeignKey(to, on_delete, related_name, null, db_index)
OneToOneField(to, on_delete, related_name, null)
ManyToManyField(to, through, related_name, db_table)
```

Relational fields do **not** map directly to a `ColumnDef` — they produce:
- `ForeignKey` → column `{field_name}_id` + FK constraint
- `OneToOneField` → same as FK + UNIQUE constraint
- `ManyToManyField` → separate junction table definition (resolved at model registration)

## Rust Core Types

```rust
// ormpi-core/src/fields/mod.rs
pub struct FieldDef {
    pub name: String,              // Python attribute name
    pub db_column: Option<String>, // override column name
    pub field_type: FieldType,
    pub null: bool,
    pub blank: bool,
    pub default: Option<DefaultValue>,
    pub unique: bool,
    pub db_index: bool,
    pub primary_key: bool,
    pub editable: bool,
    pub choices: Option<Vec<(String, String)>>,
    pub validators: Vec<ValidatorKind>,
}

pub enum DefaultValue {
    None,
    Value(sea_query::Value),
    CurrentTimestamp,   // for auto_now / auto_now_add
    Callable,           // Python callable — stored as flag, called at runtime
}

pub enum FieldType { ... }  // all variants above
```

## Python Export (ormpi-py)

```python
# What users import:
from ormpi import (
    AutoField, BigAutoField, SmallAutoField,
    IntegerField, BigIntegerField, SmallIntegerField, PositiveIntegerField,
    FloatField, DecimalField,
    CharField, TextField, SlugField, EmailField, URLField,
    BooleanField,
    DateField, TimeField, DateTimeField, DurationField,
    UUIDField, JSONField, BinaryField,
    IPAddressField, GenericIPAddressField,
    ForeignKey, OneToOneField, ManyToManyField,
)
```

Each is a PyO3 `#[pyclass]` that holds a `FieldDef` internally. They are **descriptors**: define `__get__`/`__set__`/`__delete__` so that accessing `instance.name` reads from the instance's internal value dict, while `MyModel.name` returns the field object itself.

## Key Design Constraint
Fields are **immutable after class creation**. Once a model class is created, its field list is frozen in the Rust registry. Field objects exposed to Python are read-only from the user's perspective (no mutation after `__init__`).

## Deliverables
1. All field classes instantiable in Python with correct kwargs.
2. `field.to_column_def()` Python method returning a string description (for debugging).
3. `field.contribute_to_class(cls, name)` — called by the Model metaclass machinery to register the field.
4. Unit tests for every field type's `to_column_def()` output across all three backends.
