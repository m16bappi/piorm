# Phase 12 — Modular Python Package & Python 3.12+ Type System

## Motivation

The current Python layer has two problems:

**1. Flat import namespace**
Everything is exported from `ormpi` root: fields, exceptions, aggregates, Q objects, and
on_delete constants all live in `ormpi.__init__`. This creates noise when auto-completing,
pollutes `from ormpi import *`, and makes it hard to see the structure of the library.
The idiomatic pattern for a library with many symbols is sub-module grouping:

```python
# Before — everything at root
from ormpi import CharField, Q, Count, CASCADE, atomic, DoesNotExist

# After — grouped by concept
from ormpi import Model
from ormpi.fields import CharField, ForeignKey, CASCADE
from ormpi.expr import Q, Count, F
from ormpi.transaction import atomic
from ormpi.exceptions import DoesNotExist
```

Users can also import the sub-module itself and use it as a namespace:
```python
from ormpi import fields, expr, transaction, exceptions
```

**2. Stubs use Python 3.8-era typing conventions**
All stubs use `from __future__ import annotations`, `TypeVar("M", ...)`, `Generic[M]`,
and `Union[X, None]` patterns. Python 3.12 ships PEP 695 (new type-parameter syntax),
`type` statement for aliases, `override`, `TypeIs`, `LiteralString`, and more.
ormpi targets Python 3.12+ so stubs should use these features for accuracy and IDE clarity.

## New Package Layout

```
python/ormpi/
├── __init__.py          # configure, close, Model + re-exports of sub-modules
├── __init__.pyi
├── py.typed             # PEP 561 marker
├── _core.pyi            # Rust extension — internal stubs (not public API)
│
├── fields.py            # All field classes + on_delete constants
├── fields.pyi
│
├── expr.py              # Q, F, aggregates (Count/Sum/Avg/Max/Min)
├── expr.pyi
│
├── transaction.py                # atomic(), begin(), Transaction
├── transaction.pyi
│
├── db.py                # connections proxy, DatabaseWrapper, configure/close helpers
├── db.pyi               # (was db/__init__.py — flatten to single file)
│
├── exceptions.py               # Full exception hierarchy
├── exceptions.pyi
│
├── models.py            # Model base class Python layer
├── models.pyi
│
├── query.pyi            # QuerySet / Manager — stubs only (impl in Rust)
│
├── routers.py           # DatabaseRouter ABC
└── routers.pyi
```

Files removed:
- `db/__init__.py` and `db/` sub-package → replaced by flat `db.py`
- `aggregates.py` and `aggregates.pyi` → deleted; aggregates now live in `expr.py` / `expr.pyi`
- `query.pyi` → content merged into `_core.pyi`; `query.pyi` deleted (duplication)
- `_core.pyi` field declarations → removed; canonical field stubs are in `fields.pyi`

## Goals

- `from ormpi import Model, fields, expr` works
- `from ormpi.fields import CharField, ForeignKey, CASCADE` works
- `from ormpi.expr import Q, Count, F` works
- `from ormpi.transaction import atomic, begin` works
- `from ormpi.exceptions import DoesNotExist` works
- The most commonly used symbols (`Q`, `F`, `Model`, `configure`, `close`) are re-exported at root as a convenience — everything else is accessed through sub-modules
- No shim files; no support for old flat import paths
- Stubs use `type` aliases, PEP 695 `[T]` generics, `LiteralString`, `override`, `dataclass_transform`, and other 3.12+ features
- `mypy --strict --python-version 3.12` passes with zero errors
- `pyright` passes in strict mode
