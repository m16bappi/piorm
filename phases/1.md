# Phase 1: Foundation & Project Setup

## Goal
Establish the Cargo workspace, build toolchain, async runtime bridge, and raw database connection pool abstraction. By the end of this phase, Python code can import `ormpi`, connect to SQLite/MySQL/Postgres, and execute a raw SQL string asynchronously.

## Scope
- Cargo workspace with three crates: `ormpi-core`, `ormpi-py`, `ormpi-cli`
- Maturin-based build pipeline (`pyproject.toml`, `Cargo.toml`)
- `DatabaseBackend` enum + sea-query builder dispatch
- `OrmpiPool` connection pool abstraction over sqlx pools
- Async bridge: tokio runtime embedded in the extension, `pyo3-async-runtimes` for coroutine conversion
- Configuration loader: `DATABASES` dict → `DatabaseConfig` structs
- Minimal Python-facing API: `configure(databases: dict)`, `get_connection(alias: str)`

## Architecture Decisions

### Crate Layout
```
ormpi/
  ormpi-core/        # Pure Rust: field types, query building, pool, migrations engine
  ormpi-py/          # PyO3 extension module (.so / .pyd)
  ormpi-cli/         # clap CLI binary
  sea-query/         # vendored (already present)
  pyproject.toml
  Cargo.toml         # workspace root
```

### Async Strategy
- Embed a single `tokio::runtime::Runtime` (multi-thread) inside the extension, created once at `configure()` time.
- Use `pyo3-async-runtimes` crate to convert `async fn` results into Python awaitables (`asyncio.Future`).
- All public async Python methods return `PyCoroutine` — never block the GIL.
- Sync execution path available internally for the CLI (blocking `block_on`).

### Pool Abstraction
```rust
pub enum OrmpiPool {
    Sqlite(sqlx::Pool<sqlx::Sqlite>),
    Mysql(sqlx::Pool<sqlx::MySql>),
    Postgres(sqlx::Pool<sqlx::Postgres>),
}
```
Each variant wraps the typed sqlx pool. A `HashMap<String, OrmpiPool>` inside a `Arc<RwLock<DatabaseRegistry>>` stores all configured databases keyed by alias (`"default"`, `"replica"`, etc.).

### sea-query Builder Dispatch
```rust
pub enum QueryBackend {
    Sqlite(SqliteQueryBuilder),
    Mysql(MysqlQueryBuilder),
    Postgres(PostgresQueryBuilder),
}
impl QueryBackend {
    pub fn build(&self, stmt: &SelectStatement) -> (String, Values) { ... }
}
```
This thin wrapper means every query builder call goes through a single dispatch point, keeping the rest of the code backend-agnostic.

## Deliverables
1. Compilable workspace — `cargo build` succeeds for all crates.
2. `maturin develop` installs `ormpi` as a Python package.
3. `python -c "import ormpi; ormpi.configure({'default': {'ENGINE': 'sqlite', 'NAME': ':memory:'}})"` succeeds.
4. Integration test: open connection → execute `SELECT 1` → return result row.
