# Phase 5: Multi-Database Routing & Connection Management

## Goal
Implement Django-style multi-database support: multiple database aliases, a router protocol, `using()` on QuerySet, per-request/per-operation database selection, and read/write replica splitting. This phase also hardens the connection pool with configurable options and health checks.

## Scope
- `DATABASES` configuration dict parsing into typed `DatabaseConfig` structs
- `DatabaseRegistry` — thread-safe map of alias → pool
- `DatabaseRouter` Python protocol / abstract class
- Router chain evaluation (try each router in order)
- `using(alias)` on `QuerySet`, `save()`, and `delete()`
- Connection pool configuration: `CONN_MAX_AGE`, `OPTIONS` (max_connections, min_connections, connect_timeout, idle_timeout)
- `TEST` database settings for test isolation
- `close_old_connections()` / `reset_queries()` utilities

## Configuration Format

```python
DATABASES = {
    "default": {
        "ENGINE": "ormpi.backends.sqlite",   # or mysql / postgres
        "NAME": "db.sqlite3",
    },
    "analytics": {
        "ENGINE": "ormpi.backends.postgres",
        "HOST": "localhost",
        "PORT": 5432,
        "USER": "app",
        "PASSWORD": "secret",
        "NAME": "analytics_db",
        "CONN_MAX_AGE": 60,
        "OPTIONS": {
            "max_connections": 20,
            "min_connections": 2,
            "connect_timeout": 5,
            "idle_timeout": 300,
        },
        "TEST": {
            "NAME": "test_analytics_db",
        },
    },
    "replica": {
        "ENGINE": "ormpi.backends.postgres",
        "HOST": "replica.host",
        "NAME": "main_db",
    },
}
```

## Engine Name → DatabaseBackend Mapping

```rust
pub fn engine_to_backend(engine: &str) -> Result<DatabaseBackend> {
    match engine {
        "ormpi.backends.sqlite" | "sqlite" | "sqlite3" => Ok(DatabaseBackend::Sqlite),
        "ormpi.backends.mysql"  | "mysql"  | "mariadb" => Ok(DatabaseBackend::Mysql),
        "ormpi.backends.postgres" | "postgres" | "postgresql" => Ok(DatabaseBackend::Postgres),
        other => Err(OrmpiError::UnknownBackend(other.to_string())),
    }
}
```

## DatabaseRouter Protocol

```python
# Python ABC that users implement:
class DatabaseRouter:
    def db_for_read(self, model: type, **hints) -> str | None:
        """Return alias for read operations or None to defer to next router."""
        return None

    def db_for_write(self, model: type, **hints) -> str | None:
        """Return alias for write operations or None to defer to next router."""
        return None

    def allow_relation(self, obj1, obj2, **hints) -> bool | None:
        return None

    def allow_migrate(self, db: str, app_label: str, model_name: str, **hints) -> bool | None:
        return None
```

Configured via:
```python
ormpi.configure(
    databases=DATABASES,
    database_routers=["myapp.routers.PrimaryReplicaRouter"],
)
```

## Router Resolution (Rust Side)

```rust
pub struct RouterChain {
    routers: Vec<PyObject>,  // Python router instances
}

impl RouterChain {
    pub fn db_for_read(&self, model_name: &str, hints: &Hints) -> String {
        for router in &self.routers {
            // Call router.db_for_read(model_cls, **hints) via PyO3
            if let Some(alias) = call_router_method(router, "db_for_read", model_name, hints) {
                return alias;
            }
        }
        "default".to_string()  // fallback
    }
}
```

The `RouterChain` is called from `QuerySet.evaluate()` (for reads) and `save()`/`delete()` (for writes) when no explicit `using()` is set.

## QuerySet.using()

```python
# Explicit database selection overrides router
articles = await Article.objects.using("replica").filter(published=True)
await article.save(using="default")
await article.delete(using="default")
```

`using()` stores the alias in `QueryState.database`, which bypasses the router chain entirely.

## Connection Pool Options Mapping

```rust
pub struct PoolOptions {
    pub max_connections: u32,        // default: 10
    pub min_connections: u32,        // default: 0
    pub connect_timeout: Duration,   // default: 30s
    pub idle_timeout: Option<Duration>,
    pub max_lifetime: Option<Duration>,
    pub acquire_timeout: Duration,   // default: 30s
}
```

These map directly to `sqlx::pool::PoolOptions` setters.

## Connection URL Construction

```rust
pub fn build_connection_url(config: &DatabaseConfig) -> String {
    match config.backend {
        DatabaseBackend::Sqlite  => format!("sqlite://{}", config.name),
        DatabaseBackend::Mysql   => format!("mysql://{}:{}@{}:{}/{}",
            config.user, config.password, config.host, config.port, config.name),
        DatabaseBackend::Postgres => format!("postgres://{}:{}@{}:{}/{}",
            config.user, config.password, config.host, config.port, config.name),
    }
}
```

## Test Database Support

When running under pytest, `ormpi.test.override_settings` creates in-memory SQLite databases for all aliases, skipping real connections. The `TEST.NAME` setting maps to the test database name.

## Utility Functions Exported to Python

## Deliverables
1. `ormpi.configure(databases=DATABASES)` creates pools for all aliases.
2. Custom router controls which alias is selected for read/write.
3. `using("alias")` on QuerySet overrides router.
4. Connection pool options respected.
5. `connections["alias"]` API working.
