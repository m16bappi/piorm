# Phase 3: Model System

## Goal
Implement the Django-style `Model` base class. Subclassing `Model` automatically registers the model in the Rust `ModelRegistry`, introspects field definitions, resolves the table name, and attaches a default `Manager` (`objects`). Model instances support `save()`, `delete()`, `refresh_from_db()`, and full attribute access through field descriptors.

## Scope
- `ModelRegistry` in Rust: stores `ModelDef` (field list, table name, pk field, indexes, constraints)
- Python `Model` base class using `__init_subclass__` to trigger Rust registration
- `ModelMeta` inner class parsing (`class Meta`)
- Model instance lifecycle: `__init__`, `save()`, `delete()`, `refresh_from_db()`
- `pk` alias property
- `Manager` class attached as `Model.objects`
- Deferred field loading (for `only()` / `defer()` in QuerySet)
- `clean()` / `full_clean()` validation hooks (Python-side)

## Architecture

### ModelRegistry (Rust)
```rust
// ormpi-core/src/model/registry.rs
pub struct ModelDef {
    pub app_label: String,
    pub model_name: String,          // lowercase class name
    pub table_name: String,          // resolved: app_label_model_name or Meta.db_table
    pub fields: Vec<FieldDef>,
    pub pk_field: String,            // name of the primary key field
    pub ordering: Vec<OrderExpr>,
    pub unique_together: Vec<Vec<String>>,
    pub indexes: Vec<IndexDef>,
    pub constraints: Vec<ConstraintDef>,
    pub m2m_fields: Vec<M2MFieldDef>, // junction table definitions
}

pub struct ModelRegistry {
    models: HashMap<String, ModelDef>,  // key: "app_label.ModelName"
}
```

The registry is a `once_cell::sync::Lazy<Arc<RwLock<ModelRegistry>>>` global — thread-safe, initialized once.

### __init_subclass__ Flow
When the user writes:

```python
class Article(Model):
    title = CharField(max_length=200)
    body = TextField()

    class Meta:
        db_table = "articles"
        ordering = ["-created_at"]
```

PyO3 triggers `Model.__init_subclass__` which:
1. Iterates over class `__dict__` to collect `Field` instances.
2. Calls `field.contribute_to_class(cls, name)` on each field — this sets `field.name` and `field.attname`.
3. Parses the `Meta` inner class for `db_table`, `ordering`, `unique_together`, `indexes`, `app_label`, `abstract`.
4. Calls into Rust: `ModelRegistry::register(model_def)`.
5. Attaches `cls.objects = Manager(model_name)`.
6. Replaces field class attributes with descriptor instances.

### Model Instance Storage
Each model instance holds a `PyDict`-like inner dict (`_state: InstanceState`) in Rust:

```rust
pub struct InstanceState {
    pub db: Option<String>,        // which database alias this came from
    pub adding: bool,              // True if not yet saved (INSERT vs UPDATE)
    pub fields_cache: HashMap<String, PyObject>,  // deferred field cache
    pub values: HashMap<String, Value>,  // raw DB values
}
```

Python attribute access (`instance.title`) goes through the field descriptor:
- `__get__` on the field object: reads from `instance._ormpi_state.values["title"]`, converts `Value` → Python object.
- `__set__` on the field object: validates and writes into `instance._ormpi_state.values["title"]`.

### save() Logic
```
async def save(self, using="default", force_insert=False, force_update=False, update_fields=None):
    1. Call full_clean() if not skipping validation
    2. If self._state.adding or force_insert → INSERT query via sea-query InsertStatement
       Else → UPDATE query via sea-query UpdateStatement (only dirty fields or update_fields)
    3. After INSERT: set pk from RETURNING clause (Postgres) or last_insert_id (MySQL/SQLite)
    4. self._state.adding = False
```

### delete() Logic
```
async def delete(self, using="default"):
    1. Collect related objects via CASCADE/SET_NULL rules (read from ForeignKey on_delete)
    2. Execute DELETE via sea-query DeleteStatement WHERE pk = self.pk
    3. Return (count, {model_label: count}) like Django
```

### Manager
```python
# Rust-backed, Python-facing
class Manager:
    def get_queryset(self) -> QuerySet: ...
    # All QuerySet methods forwarded:
    def all(self) -> QuerySet: ...
    def filter(self, **kwargs) -> QuerySet: ...
    def exclude(self, **kwargs) -> QuerySet: ...
    def get(self, **kwargs) -> Awaitable[Model]: ...
    def create(self, **kwargs) -> Awaitable[Model]: ...
    # ... etc
```

`Manager` is a thin Python shim that calls `self.get_queryset().method(...)`. Custom managers are supported by subclassing `Manager` and overriding `get_queryset()`.

## Abstract Models
If `Meta.abstract = True`, the model is **not** registered in `ModelRegistry` and no table is created. Its fields are inherited by concrete subclasses. Implemented by checking the abstract flag during `__init_subclass__` and skipping registration.

## Model Inheritance
- **Concrete inheritance**: child model gets its own table + OneToOneField parent link (like Django MTI).
- **Proxy models**: `Meta.proxy = True` — shares parent table, no new columns.
- Abstract models: field definitions copied to child.

## Python Export
```python
from ormpi import Model
```
`Model` is the only exported class for this layer (managers are accessed via `Model.objects`, not imported directly).

## Deliverables
1. `class MyModel(Model)` with fields registers correctly in Rust registry.
2. `MyModel(title="hello")` creates instance with correct field values.
3. `await instance.save()` executes correct INSERT/UPDATE SQL.
4. `await instance.delete()` executes correct DELETE SQL.
5. `MyModel.objects` is a `Manager` instance.
6. `Meta` options (`db_table`, `ordering`) respected in registry.
