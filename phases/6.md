# Phase 6: Transaction Management

## Goal
Implement Django-equivalent transaction management: explicit `begin`/`commit`/`rollback`, the `atomic()` context manager with savepoint nesting, and per-database transaction routing. All operations are async-first. The three symbols exported to Python are `begin`, `rollback`, and `atomic`.

## Scope
- `Transaction` Rust struct wrapping `sqlx::Transaction`
- `begin(using="default")` → async → `Transaction`
- `commit()` / `rollback()` on `Transaction`
- `atomic(using="default")` → async context manager
- Nested `atomic()` uses savepoints automatically
- `on_commit(fn)` hooks: callbacks run after outermost `atomic` commits
- `set_autocommit()` / `get_autocommit()` for manual control
- Transaction-aware QuerySet: `QuerySet.filter(...).using_transaction(txn)`

## Transaction Struct (Rust)

```rust
pub struct OrmpiTransaction {
    inner: TransactionInner,
    depth: u32,              // 0 = real transaction, >0 = savepoint
    db_alias: String,
    on_commit_callbacks: Vec<PyObject>,
    state: TransactionState,
}

enum TransactionInner {
    Sqlite(sqlx::Transaction<'static, sqlx::Sqlite>),
    Mysql(sqlx::Transaction<'static, sqlx::MySql>),
    Postgres(sqlx::Transaction<'static, sqlx::Postgres>),
}

enum TransactionState {
    Open,
    Committed,
    RolledBack,
}
```

The `'static` lifetime is managed via `Pin<Box<>>` to allow the transaction to be held in a PyO3 struct.

## Python-Facing API

### Exported Functions
```python
from ormpi import begin, rollback, atomic
```

### begin()
```python
txn = await begin(using="default")
try:
    await MyModel.objects.filter(id=1).using_transaction(txn).update(name="new")
    await txn.commit()
except Exception:
    await txn.rollback()
    raise
```

### atomic() Context Manager
```python
async with atomic() as txn:
    obj = await MyModel.objects.create(name="test")
    await obj.save()
    # Auto-commit on exit, auto-rollback on exception

# With explicit alias
async with atomic(using="secondary") as txn:
    ...

# Nested → uses SAVEPOINT automatically
async with atomic() as outer:
    await do_outer_work()
    async with atomic() as inner:  # SAVEPOINT sp_1
        await do_inner_work()
        # raises → ROLLBACK TO SAVEPOINT sp_1
    # outer continues
```

### on_commit()
```python
async with atomic() as txn:
    await MyModel.objects.create(name="test")
    txn.on_commit(lambda: send_email())
# send_email() called only after transaction commits
```

## Savepoint Implementation

Savepoint names are generated as `sp_{depth}_{random_hex}`:

```rust
impl OrmpiTransaction {
    pub async fn create_savepoint(&mut self) -> Result<String> {
        let name = format!("sp_{}_{}", self.depth, random_hex());
        let sql = format!("SAVEPOINT {}", name);
        self.execute_raw(&sql).await?;
        self.depth += 1;
        Ok(name)
    }

    pub async fn release_savepoint(&mut self, name: &str) -> Result<()> {
        let sql = format!("RELEASE SAVEPOINT {}", name);
        self.execute_raw(&sql).await?;
        self.depth -= 1;
        Ok(())
    }

    pub async fn rollback_to_savepoint(&mut self, name: &str) -> Result<()> {
        let sql = format!("ROLLBACK TO SAVEPOINT {}", name);
        self.execute_raw(&sql).await?;
        Ok(())
    }
}
```

SQLite supports savepoints. MySQL supports `SAVEPOINT`. Postgres supports `SAVEPOINT`. All three backends are covered.

## Transaction-Aware QuerySet

```python
# Pass transaction to any QuerySet operation
async with atomic() as txn:
    results = await MyModel.objects.filter(active=True).using_transaction(txn)
    await MyModel.objects.filter(id__in=[1,2,3]).using_transaction(txn).update(active=False)
```

`using_transaction(txn)` stores the `OrmpiTransaction` reference in `QueryState.transaction`. When the QuerySet executes, it uses the transaction's connection instead of acquiring one from the pool.

## Thread Safety / Async Safety

- `OrmpiTransaction` is NOT `Send` + `Sync` by default (sqlx transactions are not).
- The PyO3 wrapper uses `#[pyclass(unsendable)]` to prevent sending across threads.
- Users must `await` the transaction within the same async task.
- The GIL is released during all async SQL operations.

## Error Handling

```python
from ormpi import TransactionError, IntegrityError, DatabaseError

# Raised when trying to use a committed/rolled-back transaction
txn = await begin()
await txn.commit()
await txn.commit()  # raises TransactionError("Transaction already committed")
```
