# Phase 10: Testing, Benchmarks & Packaging

## Goal
Deliver a production-ready package: comprehensive integration tests across all three backends, performance benchmarks, CI/CD pipeline, proper versioning, and publishable distribution to PyPI. Ensure correctness, performance parity with established ORMs, and a smooth developer experience.

## Scope
- Integration test suite using `pytest` + `pytest-asyncio`
- Backend-specific test fixtures (SQLite in-memory, Docker-based Postgres and MySQL)
- Unit tests for Rust core (`cargo test`)
- Performance benchmarks (criterion for Rust, pytest-benchmark for Python)
- GitHub Actions CI matrix (Python 3.9–3.13, Linux/macOS/Windows)
- maturin-based wheel builds for all platforms
- PyPI publishing workflow
- Example project demonstrating all features
- Changelog and versioning (`CHANGELOG.md`, semantic versioning)

### Shared Test Models
```python
# tests/conftest.py
import pytest
import ormpi
from ormpi import Model, CharField, IntegerField, ForeignKey, DateTimeField, JSONField

class Author(Model):
    name = CharField(max_length=100)
    email = CharField(max_length=200, unique=True)

    class Meta:
        app_label = "test"

class Article(Model):
    title = CharField(max_length=200)
    body = TextField()
    author = ForeignKey(Author, on_delete="CASCADE")
    published_at = DateTimeField(null=True)
    metadata = JSONField(null=True)
    views = IntegerField(default=0)

    class Meta:
        app_label = "test"
        ordering = ["-published_at"]

@pytest.fixture
async def db():
    ormpi.configure({
        "default": {"ENGINE": "sqlite", "NAME": ":memory:"}
    })
    await ormpi.migrate()
    yield
    await ormpi.close()
```

## Integration Test Coverage Requirements

### CRUD (per backend)
- [ ] `Model.objects.create(**kwargs)` → correct INSERT
- [ ] `await instance.save()` INSERT path (new instance)
- [ ] `await instance.save()` UPDATE path (existing instance, only dirty fields)
- [ ] `await instance.delete()` → correct DELETE, returns count
- [ ] `await Model.objects.get(pk=n)` → correct instance
- [ ] `Model.objects.get(pk=9999)` → raises `DoesNotExist`
- [ ] `Model.objects.filter(...).get(...)` → raises `MultipleObjectsReturned` if >1 result

### QuerySet
- [ ] All 20+ field lookups produce correct results
- [ ] `Q(a=1) | Q(b=2)` correct results
- [ ] `~Q(x=3)` correct NOT
- [ ] `order_by("-field")` descending order
- [ ] `distinct()` deduplicates
- [ ] `values()` returns list of dicts
- [ ] `values_list("field", flat=True)` returns list of scalars
- [ ] Slicing `[:10]` applies LIMIT correctly
- [ ] `count()` returns correct integer
- [ ] `exists()` returns bool
- [ ] `bulk_create([...])` inserts multiple rows efficiently

### Relations
- [ ] `ForeignKey` field stores `{field}_id` column
- [ ] `instance.related` (forward access) fetches related object
- [ ] `related_set.all()` (reverse access) works
- [ ] `select_related("author")` produces single JOIN query
- [ ] `prefetch_related("articles")` produces exactly 2 queries
- [ ] `on_delete=CASCADE` deletes related objects
- [ ] `on_delete=SET_NULL` nullifies FK column

### Transactions
- [ ] `atomic()` commits on success
- [ ] `atomic()` rolls back on exception
- [ ] Nested `atomic()` uses savepoints
- [ ] `on_commit` fires after outermost commit only
- [ ] `on_commit` does NOT fire after rollback

### Migrations
- [ ] Initial migration creates correct tables
- [ ] `AddField` migration adds column
- [ ] `RemoveField` migration drops column
- [ ] `migrate app zero` reverses all migrations
- [ ] Migration recorded in `ormpi_migrations` table
- [ ] Failed migration leaves DB unchanged

## Performance Benchmarks

Target: within 2× of raw sqlx performance for single-row operations.

```python
# benchmarks/bench_insert.py
@pytest.mark.benchmark
async def test_bulk_insert_10k(benchmark, db):
    async def do_insert():
        await Author.objects.bulk_create([
            Author(name=f"Author {i}", email=f"a{i}@test.com")
            for i in range(10_000)
        ])
    await benchmark(do_insert)
    # Target: < 500ms for 10k rows on SQLite
```

Rust benchmarks (criterion):
- Query building time (no DB): `SelectStatement` with 10 filters
- Migration operation SQL generation
- `ProjectState` diff computation

## CI Pipeline (GitHub Actions)

```yaml
# .github/workflows/ci.yml
jobs:
  test-sqlite:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.9", "3.10", "3.11", "3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4
      - uses: PyO3/maturin-action@v1
      - run: pip install -e ".[test]"
      - run: pytest tests/integration/sqlite/ -v

  test-postgres:
    services:
      postgres:
        image: postgres:16
        env: { POSTGRES_PASSWORD: test }
    runs-on: ubuntu-latest
    steps:
      - run: pytest tests/integration/postgres/ -v

  test-mysql:
    services:
      mysql:
        image: mysql:8
        env: { MYSQL_ROOT_PASSWORD: test }
    runs-on: ubuntu-latest
    steps:
      - run: pytest tests/integration/mysql/ -v

  build-wheels:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    steps:
      - uses: PyO3/maturin-action@v1
        with:
          command: build
          args: --release --out dist
```
