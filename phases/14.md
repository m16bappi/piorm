# Phase 14 — Low-Overhead Instance Layout: `__slots__` + Bitmask Dirty Tracking

## Motivation

Every ormpi model instance currently allocates **4 Python containers** purely for
bookkeeping, before any field data is stored:

```
instance.__dict__        ← ~72B (always exists)
  ├── "_ormpi_values"    ← dict: field values              ~72B + entries
  ├── "_ormpi_dirty"     ← set:  dirty field names         ~216B base
  └── "_ormpi_state"     ← dict: {"adding": bool, "db": str|None}  ~72B + entries
```

**~330B overhead per instance** before any user data is stored. At 1 million instances
that is ~330 MB of pure infrastructure overhead.

This phase replaces that layout with a single dict (`_values`) in `__slots__`, and
replaces the dirty-tracking set with an integer bitmask (`_dirty`). This is the same
approach used internally by Pony ORM — the only other Python ORM that uses `__slots__` +
bitmask tracking.

---

## Research: ORM Instance Overhead Comparison

| ORM | Field Storage | `__slots__` | Dirty Tracking | Est. Overhead |
|-----|--------------|-------------|----------------|---------------|
| GINO | `__values__` dict | No | None | ~150B |
| Tortoise | `__dict__` directly | No | None | ~200B |
| **Pony** | `_vals_` dict in slot | **Yes** | `_wbits_` bitmask | **~100B** |
| Peewee | `__data__` dict + `_dirty` set | No | `_dirty` set | ~280B |
| **ormpi (before)** | `_ormpi_values` + set + dict | No | `_ormpi_dirty` set | **~330B** |
| Django | `__dict__` + `_state` object | No | O(N) compare on save | ~380B |
| SQLAlchemy | `__dict__` + `InstanceState` | No | `committed_state` dict | ~600B |

After this phase, ormpi's overhead drops to **~72B** — lighter than Pony.

## Proposed Instance Layout

```python
class Model:
    __slots__ = ("_values", "_dirty", "_adding", "_db", "__weakref__")
    _field_bits: ClassVar[dict[str, int]]   # {"title": 1, "views": 2, ...}
```

```
Model Instance (proposed)
├── _values     → dict            ← ONLY heap allocation (~72B + entries)
│    ├── "id"        → 1
│    ├── "title"     → "Hello"
│    └── "views"     → 42
│
├── _dirty      → int (bitmask)   ← 0 bytes extra (stored in slot)
├── _adding     → bool            ← 0 bytes extra (stored in slot)
├── _db         → str | None      ← 0 bytes extra (stored in slot)
└── __weakref__                   ← required by __slots__

Total overhead: ~72B (one dict)
```

### Class-level bit assignment (set during `_register_model_class`)

```python
class Article(Model):
    _field_bits = {
        "id":        1 << 0,   # 1
        "title":     1 << 1,   # 2
        "views":     1 << 2,   # 4
        "author_id": 1 << 3,   # 8
    }
```

### Bitmask operations

```
Field write:     _dirty |= _field_bits["title"]     →  _dirty = 0b0010
Another write:   _dirty |= _field_bits["views"]     →  _dirty = 0b0110
Any dirty?       _dirty != 0                        →  True
Field dirty?     _dirty & _field_bits["title"]      →  2  (truthy)
Get dirty names: [n for n, b in _field_bits.items() if _dirty & b]  →  ["title", "views"]
Clear on save:   _dirty = 0                         →  0b0000
```

Python `int` is arbitrary-precision, so models with more than 64 fields simply get a
larger integer — still O(1) per operation.

## Before vs After

### Memory per instance

```
BEFORE (4 containers):                   AFTER (1 container):
────────────────────────                 ────────────────────────
__dict__       ~72B                      __slots__     0B  (eliminated)
_ormpi_values  ~72B  (dict)              _values       ~72B (dict — only alloc)
_ormpi_dirty   ~216B (set)               _dirty        0B  (int in slot)
_ormpi_state   ~72B  (dict)              _adding       0B  (bool in slot)
                                          _db           0B  (ref in slot)
────────────────────────                 ────────────────────────
Total: ~330B, 4 allocs                   Total: ~72B, 1 alloc
```

### At scale

| Instances | Before | After | Saved |
|-----------|--------|-------|-------|
| 10,000 | 3.3 MB | 0.72 MB | 2.6 MB (79%) |
| 100,000 | 33 MB | 7.2 MB | 26 MB (79%) |
| 1,000,000 | 330 MB | 72 MB | **258 MB (79%)** |

### CPU per operation

| Operation | Before | After |
|-----------|--------|-------|
| Field write | `_ormpi_dirty.add(name)` — hash + set insert | `_dirty \|= bit` — single OR |
| Field read | `_ormpi_values[name]` — 2 lookups | `_values[name]` — 1 lookup (slot → dict) |
| Is anything dirty? | `len(_ormpi_dirty) > 0` | `_dirty != 0` — integer compare |
| Is field dirty? | `name in _ormpi_dirty` — hash lookup | `_dirty & bit` — integer AND |
| Get dirty fields | `list(_ormpi_dirty)` | comprehension over `_field_bits` |
| Clear on save | `_ormpi_dirty.clear()` — set clear | `_dirty = 0` — integer write |
| Hydrate from row | 3 container allocations | 1 container allocation |

## PyO3 `frozen` Requirement

PyO3 injects a hidden `RefCell` tracking slot into every non-frozen `#[pyclass]`. Python's
`__slots__` memory-layout mechanism conflicts with this extra space, causing Python
subclasses that declare `__slots__` to silently fall back to `__dict__` — defeating the
entire optimization.

The fix is `#[pyclass(name = "Model", subclass, frozen)]`. Since `PyModel` holds no mutable
Rust fields (all state lives on the Python side in `_values`, `_dirty`, etc.), `frozen` is
correct and safe. The Python-level `__setattr__` override handles mutation tracking.

## Migration Map

All changes touch only **private** attributes — zero public API breakage.

| Old | New |
|-----|-----|
| `instance._ormpi_values` | `instance._values` |
| `instance._ormpi_dirty` (set) | `instance._dirty` (int bitmask) |
| `"title" in instance._ormpi_dirty` | `bool(instance._dirty & Model._field_bits["title"])` |
| `instance._ormpi_dirty.add("title")` | `instance._dirty \|= Model._field_bits["title"]` |
| `instance._ormpi_dirty.clear()` | `instance._dirty = 0` |
| `instance._ormpi_state["adding"]` | `instance._adding` |
| `instance._ormpi_state["db"]` | `instance._db` |

## Acceptance Criteria

- [ ] `Model.__slots__` contains `("_values", "_dirty", "_adding", "_db", "__weakref__")`
- [ ] `Model().__dict__` raises `AttributeError` (no `__dict__` on slotted instances)
- [ ] After `instance.title = "x"`, `instance._dirty & Model._field_bits["title"]` is truthy
- [ ] After `instance.save()`, `instance._dirty == 0` and `instance._adding == False`
- [ ] `row_to_instance` makes exactly 1 heap allocation (the `_values` dict)
- [ ] Memory benchmark: 100K instances use ≤ 10 MB overhead (vs ~33 MB before)
- [ ] `sys.getsizeof` reports no `__dict__` attribute on model instances
- [ ] All existing CRUD tests (`__tests__/crud/`) pass unchanged
- [ ] `pyright --pythonversion 3.12 python/ormpi/` — zero errors after stub updates
- [ ] `mypy --strict --python-version 3.12 python/ormpi/` — zero errors after stub updates
