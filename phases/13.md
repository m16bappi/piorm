# Phase 13 — Precise Typed Descriptors & Self-Typed Model API

## Motivation

Phase 12 rewrote all stubs to use Python 3.12+ type syntax (PEP 695 generics, `type` aliases,
`LiteralString`, `@final`). However, three critical typing gaps remain that cause IDEs and type
checkers to fall back to `Any` in the most common usage patterns:

### Gap 1 — `objects: ClassVar[Manager[Any]]`

```python
# Current — pyright/mypy see Any everywhere
author = await Author.objects.get(pk=1)
# (variable) author: Any   ← IDE shows Any, not Author
```

`Model.objects` is declared as `Manager[Any]` because the base `Model` class cannot refer to
its concrete subclass type. Every `get`, `create`, `first`, `filter`, etc. returns `Any` as a
result. The fix is `ClassVar[Manager[Self]]` which pyright resolves correctly per subclass.

### Gap 2 — Field descriptors return `Any`

```python
class Author(Model):
    name = CharField(max_length=100)        # (variable) name: CharField
    bio  = TextField(null=True)             # (variable) bio:  TextField

author = await Author.objects.get(pk=1)
reveal_type(author.name)   # Any   ← should be str
reveal_type(author.bio)    # Any   ← should be str | None
```

`Field.__get__` currently returns `Any`. Type checkers cannot infer what Python type a field
attribute holds, nor whether `null=True` widens the type to include `None`.

### Gap 3 — `from_db` and constructor not typed

```python
author = Author.from_db(...)   # returns Model, not Author
Author(name="Alice")           # __init__ accepts **Any — no parameter checking
```

`from_db` should return `Self`. The `Model.__init__` should accept only the field names
declared on the concrete class, with the correct Python types for each field.

## Python 3.12+ Features Used

| Feature | PEP | Where used |
|---------|-----|-----------|
| Generic classes `class Foo[T]:` | PEP 695 | `Field[T]`, all concrete fields |
| Generic type aliases `type X[T] = ...` | PEP 695 | `Choices[T]` |
| `Self` | PEP 673 | `objects`, `from_db`, field `__get__` |
| `@overload` on `__new__` | PEP 484 | null-aware field construction |
| `Literal[True]` / `Literal[False]` | PEP 586 | `null=True` branch in `__new__` |
| `@dataclass_transform` | PEP 681 | `Model` base class for `__init__` inference |
| `Never` | PEP 673 | `__get__` guard when `obj is None` |

## Design: Generic Field Descriptors

Fields are made generic on their **Python-level value type** `T`.  The key insight is that
the `null` parameter at construction time determines `T`:

```
CharField(max_length=100)              →  CharField[str]
CharField(max_length=100, null=True)   →  CharField[str | None]
IntegerField()                         →  IntegerField[int]
IntegerField(null=True)                →  IntegerField[int | None]
BooleanField()                         →  BooleanField[bool]
DateTimeField(null=True)               →  DateTimeField[datetime | None]
```

This is encoded via `@overload` on `__new__` (which can specify return type per overload),
paired with a generic `__get__` that returns `T` on instance access and `Self` on class access.

### `Field[T]` base descriptor pattern

```python
class Field[T]:
    @overload
    def __get__(self, obj: None, objtype: type | None = None) -> Self: ...
    @overload
    def __get__(self, obj: object, objtype: type | None = None) -> T: ...
    def __set__(self, obj: object, value: T) -> None: ...
```

- **Class access** (`Author.name`): returns `Self` — the descriptor object itself. This
  preserves introspection and is consistent with how Django descriptors work.
- **Instance access** (`author.name`): returns `T` — the actual Python value.
- **`__set__`** takes `T` — this is what `@dataclass_transform` reads to synthesize the
  `__init__` parameter type.

### `__new__` overloads for nullability

```python
class CharField[T = str]:
    @overload
    def __new__(cls, max_length: int, *, null: Literal[True],  ...) -> CharField[str | None]: ...
    @overload
    def __new__(cls, max_length: int, *, null: Literal[False] = ..., ...) -> CharField[str]: ...
    @overload
    def __new__(cls, max_length: int, *, null: bool = ...,    ...) -> CharField[str]: ...
```

Type checkers resolve these at call-site based on the literal value of `null`. When `null` is
a non-literal `bool` variable the third overload applies and the type is `CharField[str]`
(the conservative non-None default — safe for the common case).

## Design: `@dataclass_transform` on `Model`

`@dataclass_transform` (PEP 681) tells type checkers to synthesize a typed `__init__` for
every `Model` subclass. The `field_specifiers` parameter names the descriptor base class so
type checkers know which class-body assignments count as ORM fields:

```python
from typing import dataclass_transform

@dataclass_transform(
    eq_default=True,
    field_specifiers=(Field,),   # anything that inherits Field is an ORM field
)
class Model:
    objects: ClassVar[Manager[Self]]
    ...
```

With this, pyright synthesizes for:
```python
class Author(Model):
    name = CharField(max_length=100)         # CharField[str]
    bio  = TextField(null=True)              # TextField[str | None]
    age  = IntegerField(null=True)           # IntegerField[int | None]
```

The inferred `__init__`:
```python
def __init__(self, *, name: str, bio: str | None, age: int | None) -> None: ...
```

### `ClassVar[Manager[Self]]`

`Self` inside a class body refers to the eventual concrete subclass. Pyright resolves
`Author.objects` as `Manager[Author]`, so `Author.objects.get(pk=1)` returns
`Coroutine[Any, Any, Author]`, not `Coroutine[Any, Any, Any]`.

Mypy's support for `Self` in `ClassVar` is partial — it may require `objects: ClassVar[Manager[Any]]`
for mypy strict mode to pass. Task 13.2 provides both variants and a `mypy.ini` note.

## Goals

- `Author.objects.get(pk=1)` → IDE / type checker infers `Author`, not `Any`
- `author.name` → infers `str` (not `Any`)
- `author.bio` where `bio = TextField(null=True)` → infers `str | None`
- `Author(name="Alice", age=25)` → type-checked; unknown kwargs are errors
- `Author.from_db(...)` → infers `Author`, not `Model`
- All stubs remain `mypy --strict --python-version 3.12` clean
- All stubs remain `pyright --pythonversion 3.12` strict-mode clean
