# Phase 8: CLI Tool

## Goal
Build the `ormpi` CLI binary using `clap` that exposes all migration management commands plus database inspection utilities. The CLI discovers user models by importing the Python project, running `ormpi.configure()`, and then invoking the Rust migration engine. It is packaged as a Python console script entry point via maturin.

## Scope
- `ormpi-cli` crate with `clap` command structure
- Python project discovery (find `settings.py` / `ormpi_settings.py` or env var `ORMPI_SETTINGS_MODULE`)
- Migration commands: `makemigrations`, `migrate`, `showmigrations`, `sqlmigrate`, `squashmigrations`
- Database commands: `dbshell`, `inspectdb`
- Shell integration: colorized output, progress indicators
- Exit codes following Unix conventions (0 = success, 1 = error, 2 = no changes)
- Installed as `ormpi` console script: `pip install ormpi` → `ormpi migrate`

## Command Structure

```
ormpi [OPTIONS] <COMMAND>

Options:
  --settings <MODULE>    Python settings module (overrides ORMPI_SETTINGS_MODULE)
  --database <ALIAS>     Target database alias [default: default]
  --no-color             Disable colored output
  -v, --verbosity <N>    Verbosity level 0-3 [default: 1]
  -h, --help             Print help

Commands:
  makemigrations    Detect model changes and create migration files
  migrate           Apply or reverse migrations
  showmigrations    List all migrations and their status
  sqlmigrate        Print SQL for a specific migration without running it
  squashmigrations  Squash multiple migrations into one
  dbshell           Open an interactive database shell
  inspectdb         Introspect existing database and output model definitions
  version           Print ormpi version
```

## Command Details

### makemigrations
```
ormpi makemigrations [APP_LABEL...] [OPTIONS]

Options:
  --name <NAME>     Custom migration name suffix
  --empty           Create an empty migration file
  --dry-run         Show what would be created without writing files
  --check           Exit with non-zero if changes detected (CI use)
  --merge           Merge divergent migration histories
```

Behavior:
1. Import Python models via `pyo3` embedded interpreter.
2. Build `to_state` from current model definitions (via `ModelRegistry`).
3. Build `from_state` by replaying existing migration files.
4. Run `AutoDetector::detect_changes()`.
5. If changes found: generate TOML file in `migrations/` directory.
6. If `--dry-run`: print operations to stdout without writing.
7. If `--check`: exit code 1 if changes detected (for CI pipelines).

### migrate
```
ormpi migrate [APP_LABEL [MIGRATION_NAME]] [OPTIONS]

Options:
  --fake            Mark migrations as applied without running SQL
  --fake-initial    Fake the initial migration if tables already exist
  --run-sync-db     Synchronize models without migrations (dangerous)
  --plan            Show the migration plan without executing
  --database <ALIAS>
```

Behavior:
- No args → apply all pending migrations across all apps.
- `APP_LABEL` only → apply all pending for that app.
- `APP_LABEL MIGRATION_NAME` → migrate forward/backward to that specific version.
- `APP_LABEL zero` → roll back all migrations for the app.
- `--plan` → print ordered list of migrations that would run.

Output format:
```
Applying users.0001_initial... OK
Applying users.0002_add_bio... OK
  (0.023s)
```

### showmigrations
```
ormpi showmigrations [APP_LABEL...] [OPTIONS]

Options:
  --list (-l)       Show list format (default)
  --plan (-p)       Show dependency plan format
  --database <ALIAS>
```

Output (list format):
```
users
 [X] 0001_initial
 [X] 0002_add_bio
 [ ] 0003_add_avatar

blog
 [X] 0001_initial
 [ ] 0002_add_tags
```

### sqlmigrate
```
ormpi sqlmigrate <APP_LABEL> <MIGRATION_NAME> [OPTIONS]

Options:
  --backwards       Show the SQL for reversing the migration
  --database <ALIAS>
```

Output: Raw SQL statements that would be executed, without running them.

### squashmigrations
```
ormpi squashmigrations <APP_LABEL> [START_MIGRATION] <SQUASH_MIGRATION> [OPTIONS]

Options:
  --no-optimize    Skip operation optimization pass
  --squashed-name  Name for the squashed migration
```

### inspectdb
```
ormpi inspectdb [TABLE...] [OPTIONS]

Options:
  --database <ALIAS>
  --include-views   Include database views
```

Introspects existing database tables and outputs Python model class definitions. Useful for brownfield projects.

### dbshell
```
ormpi dbshell [OPTIONS]

Options:
  --database <ALIAS>
```

Opens the native database CLI tool: `sqlite3`, `mysql`, or `psql` with connection parameters pre-filled.

## Settings Discovery

```rust
fn discover_settings(explicit: Option<&str>) -> Result<OrmpiSettings> {
    // 1. Use --settings if provided
    // 2. Check ORMPI_SETTINGS_MODULE env var
    // 3. Look for ormpi_settings.py in CWD
    // 4. Look for settings.py in CWD
    // 5. Error if nothing found
}
```

Settings file is a Python file with `DATABASES` dict (and optionally `DATABASE_ROUTERS`, `INSTALLED_APPS`, `DEFAULT_AUTO_FIELD`). The CLI uses PyO3's embedded Python interpreter to import and evaluate the settings module.

## Output Formatting

```rust
pub struct CliOutput {
    verbosity: u8,
    color: bool,
}

impl CliOutput {
    pub fn success(&self, msg: &str)  // green [OK]
    pub fn warning(&self, msg: &str)  // yellow
    pub fn error(&self, msg: &str)    // red, to stderr
    pub fn info(&self, msg: &str)     // only if verbosity >= 2
    pub fn sql(&self, sql: &str)      // syntax highlighted SQL
}
```

## Packaging as Console Script

In `pyproject.toml`:
```toml
[project.scripts]
ormpi = "ormpi._cli:main"

# ormpi/_cli.py — thin shim that calls the Rust binary
def main():
    import sys
    from ormpi._core import run_cli
    sys.exit(run_cli(sys.argv[1:]))
```

The `run_cli` function is a PyO3-exported function in `ormpi-py` that invokes the `clap` CLI with the given args and returns an exit code.

## Deliverables
1. `ormpi makemigrations` creates correct TOML files.
2. `ormpi migrate` applies migrations with formatted output.
3. `ormpi showmigrations` shows applied/pending status.
4. `ormpi sqlmigrate` prints correct SQL.
5. `ormpi inspectdb` generates valid Python model code from existing tables.
6. `pip install ormpi` → `ormpi` command available in PATH.
