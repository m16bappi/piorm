# Task 4: Unify `row_to_json_*` and `extract_*_value` in `executor.rs`

## Problem

`ormpi-core/src/executor.rs` contains three structurally identical `row_to_json_*` functions (lines 77–165) and three nearly identical `extract_*_value` functions (lines 88–165). The `row_to_json_*` functions are byte-for-byte identical — only the row type differs. The `extract_*_value` functions share the same waterfall logic; Postgres adds one extra `try_get::<i32>` check.

Additionally, three public thin-wrapper functions (`fetch_row_sqlite`, `fetch_row_mysql`, `fetch_row_postgres` at lines 65–75) do nothing except delegate to the private `row_to_json_*` functions. These are dead code once call sites migrate to `OrmpiPool` helpers (see Task 2).


## Fix

### Step 1 — Add a `ToJsonPairs` trait in `executor.rs`

Define a trait that any sqlx Row type can implement to produce JSON pairs. This eliminates the three `row_to_json_*` clones:

```rust
/// Converts a database row into an ordered list of (column_name, JSON value) pairs.
trait ToJsonPairs {
    fn to_json_pairs(&self) -> Vec<(String, serde_json::Value)>;
}
```

### Step 2 — Extract a shared `extract_json_numeric` helper

The i64/f64/String/bool waterfall is identical across all three backends. Extract it as a free function operating on `impl sqlx::Row`:

```rust
/// Common waterfall used by all backends: try i64 → f64 → String → bool → Null.
/// Postgres callers may prepend an i32 check before calling this.
fn try_extract_common<R>(row: &R, col: &str) -> serde_json::Value
where
    R: sqlx::Row,
    i64: for<'r> sqlx::Decode<'r, R::Database>,
    f64: for<'r> sqlx::Decode<'r, R::Database>,
    String: for<'r> sqlx::Decode<'r, R::Database>,
    bool: for<'r> sqlx::Decode<'r, R::Database>,
    sqlx::types::Text<i64>: for<'r> sqlx::Type<R::Database>,
    // ... bounds as required by sqlx
{
    if let Ok(v) = row.try_get::<i64, _>(col) {
        return serde_json::Value::Number(v.into());
    }
    if let Ok(v) = row.try_get::<f64, _>(col) {
        if let Some(n) = serde_json::Number::from_f64(v) {
            return serde_json::Value::Number(n);
        }
    }
    if let Ok(v) = row.try_get::<String, _>(col) {
        return serde_json::Value::String(v);
    }
    if let Ok(v) = row.try_get::<bool, _>(col) {
        return serde_json::Value::Bool(v);
    }
    serde_json::Value::Null
}
```

> **Note**: If the generic bounds become too complex (sqlx Database bounds differ per backend), use a macro instead — `macro_rules! extract_common_value!(row, col)` — which expands to the same waterfall inline. The macro approach avoids generic complexity at the cost of monomorphisation being explicit.

### Step 3 — Implement `ToJsonPairs` for each backend row

```rust
impl ToJsonPairs for sqlx::sqlite::SqliteRow {
    fn to_json_pairs(&self) -> Vec<(String, serde_json::Value)> {
        self.columns().iter().map(|col| {
            let name = col.name().to_string();
            let val = try_extract_common(self, col.name()); // or macro
            (name, val)
        }).collect()
    }
}

impl ToJsonPairs for sqlx::mysql::MySqlRow {
    fn to_json_pairs(&self) -> Vec<(String, serde_json::Value)> {
        self.columns().iter().map(|col| {
            let name = col.name().to_string();
            let val = try_extract_common(self, col.name());
            (name, val)
        }).collect()
    }
}

impl ToJsonPairs for sqlx::postgres::PgRow {
    fn to_json_pairs(&self) -> Vec<(String, serde_json::Value)> {
        self.columns().iter().map(|col| {
            let name = col.name().to_string();
            // Postgres-specific: try i32 first (INT4 columns)
            let val = if let Ok(v) = self.try_get::<i32, _>(col.name()) {
                serde_json::Value::Number(v.into())
            } else {
                try_extract_common(self, col.name())
            };
            (name, val)
        }).collect()
    }
}
```

### Step 4 — Simplify `fetch_one_raw` and remove dead wrappers

```rust
pub async fn fetch_one_raw(
    pool: &OrmpiPool,
    sql: &str,
) -> crate::Result<Vec<(String, serde_json::Value)>> {
    match pool {
        OrmpiPool::Sqlite(p) => Ok(sqlx::query(sql).fetch_one(p).await?.to_json_pairs()),
        OrmpiPool::Mysql(p)  => Ok(sqlx::query(sql).fetch_one(p).await?.to_json_pairs()),
        OrmpiPool::Postgres(p) => Ok(sqlx::query(sql).fetch_one(p).await?.to_json_pairs()),
    }
}
```
