# Task 21.5 — Replace `unwrap()` in Production Code Paths

## Problem

Several `unwrap()` calls appear in production (non-test) code. Each is a latent panic:

### A — Lock-poisoning panics across all registries

```rust
// model/registry.rs, registry.rs, query/evaluate.rs, model/executor.rs, etc.
let guard = reg.read().unwrap();   // panics if any thread panicked while holding the write lock
```

`RwLock::read()` returns `Err(PoisonError)` only when another thread panicked while
holding the write lock. That scenario is vanishingly rare in practice, but `.unwrap()`
turns it into a process crash instead of a recoverable error.

### B — Decimal → f64 precision loss silently coerces to NaN

```rust
// value.rs
OrmpiValue::Decimal(d) => sea_query::Value::Double(Some(
    d.to_f64().unwrap_or(f64::NAN),  // ← silent precision loss + NaN silently injected
)),
```

`rust_decimal::Decimal::to_f64()` returns `None` when the value overflows f64. The
current code injects `NaN` silently — SQL drivers treat NaN as an error or store garbage.
This is a footgun. `Decimal` should be serialized as a string (VARCHAR) or kept as-is
(if the sea-query version supports it) rather than coerced to f64.

### C — `.unwrap()` on PyO3 type-name extraction

```rust
// ormpi-py/src/model/instance.rs
let type_name = obj.get_type().name()
    .map(|n| n.extract::<String>().unwrap_or_default())  // unwrap_or_default is fine
    .unwrap_or_default();
```

This specific case is already safe (`.unwrap_or_default()`), but it reads like there's
a hidden unwrap — leave as-is and add a comment confirming it's intentional.

## Fix

### Fix A — Propagate lock-poisoning as `OrmpiError`

Define a helper in `error.rs` or as a free function near the registry:

```rust
// ormpi-core/src/error.rs (or a small helper module)
pub(crate) fn lock_read<T>(
    lock: &std::sync::RwLock<T>,
) -> crate::Result<std::sync::RwLockReadGuard<'_, T>> {
    lock.read().map_err(|_| OrmpiError::Other(
        "Registry lock poisoned — a previous write panicked".to_string(),
    ))
}

pub(crate) fn lock_write<T>(
    lock: &std::sync::RwLock<T>,
) -> crate::Result<std::sync::RwLockWriteGuard<'_, T>> {
    lock.write().map_err(|_| OrmpiError::Other(
        "Registry lock poisoned — a previous write panicked".to_string(),
    ))
}
```

Replace every `reg.read().unwrap()` with `lock_read(&reg)?` (or `.map_err(...)`) in
all files. Non-async callers that can't return `Result` can use
`reg.read().unwrap_or_else(|e| e.into_inner())` which recovers from poisoned locks by
returning the inner guard.

Key locations:
- `model/registry.rs` (global registry read/write in `ModelRegistry::global()` callers)
- `registry.rs` (DatabaseRegistry)
- `query/evaluate.rs` (model registry reads during query execution)
- `model/executor.rs`

### Fix B — Decimal serialization

Option 1 (preferred): Serialize `Decimal` as a string-based `sea_query::Value`:

```rust
OrmpiValue::Decimal(d) => sea_query::Value::String(Some(d.to_string())),
```

This preserves precision. The database column type is `DECIMAL/NUMERIC`, so passing a
string-form decimal is portable and sqlx handles the coercion.

Option 2: If sea-query 1.0 supports a `Decimal` variant (check `sea-query/src/value.rs`),
use it directly:

```rust
// Only if sea_query::Value::Decimal(Option<Decimal>) exists
OrmpiValue::Decimal(d) => sea_query::Value::Decimal(Some(d)),
```

Remove `use rust_decimal::prelude::ToPrimitive` import if it is no longer needed after
this change.

### Fix C — Add a `// SAFETY` comment for the `unwrap_or_default` pattern

```rust
// `get_type().name()` returns PyResult<&str>; `.unwrap_or_default()` gives ""
// which falls through to the bytes-extraction path below. Intentional.
let type_name = obj.get_type().name()
    .map(|n| n.extract::<String>().unwrap_or_default())
    .unwrap_or_default();
```

## Acceptance Criteria

- [ ] Zero `rwlock.read().unwrap()` or `rwlock.write().unwrap()` calls in non-test code
- [ ] `OrmpiValue::Decimal` no longer coerces to `f64` / no longer produces `NaN`
- [ ] `ToPrimitive` import removed from `value.rs` if no longer needed
- [ ] All tests pass
- [ ] `cargo clippy -- -D clippy::unwrap_used` passes in non-test targets (or suppressions
      documented with `#[expect(...)]` and justification comments)
