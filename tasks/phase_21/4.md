# Task 21.4 — Implement `FromStr` for `Lookup`; Add `Copy` to `FExprOp`

## Problem A — `Lookup::from_str` custom method instead of `std::str::FromStr`

```rust
// query/filter.rs — current
impl Lookup {
    pub fn from_str(s: &str) -> Option<Self> { ... }
}
```

This duplicates functionality that `std::str::FromStr` already provides as a standard
trait. Callers cannot use `s.parse::<Lookup>()`, `str::parse`, or `?` propagation.
The trait should be implemented instead of an inherent method.

## Fix A

### Step 1 — Replace the inherent method with `FromStr`

```rust
use std::str::FromStr;

impl FromStr for Lookup {
    type Err = ();

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s {
            "exact"       => Ok(Self::Exact),
            "iexact"      => Ok(Self::IExact),
            "contains"    => Ok(Self::Contains),
            "icontains"   => Ok(Self::IContains),
            "startswith"  => Ok(Self::StartsWith),
            "istartswith" => Ok(Self::IStartsWith),
            "endswith"    => Ok(Self::EndsWith),
            "iendswith"   => Ok(Self::IEndsWith),
            "in"          => Ok(Self::In),
            "gt"          => Ok(Self::Gt),
            "gte"         => Ok(Self::Gte),
            "lt"          => Ok(Self::Lt),
            "lte"         => Ok(Self::Lte),
            "range"       => Ok(Self::Range),
            "isnull"      => Ok(Self::IsNull),
            "regex"       => Ok(Self::Regex),
            "iregex"      => Ok(Self::IRegex),
            "date"        => Ok(Self::Date),
            "year"        => Ok(Self::Year),
            "month"       => Ok(Self::Month),
            "day"         => Ok(Self::Day),
            "hour"        => Ok(Self::Hour),
            "minute"      => Ok(Self::Minute),
            "second"      => Ok(Self::Second),
            "week"        => Ok(Self::Week),
            "weekday"     => Ok(Self::WeekDay),
            "quarter"     => Ok(Self::Quarter),
            _             => Err(()),
        }
    }
}
```

### Step 2 — Update callers

Replace `Lookup::from_str(s)` → `s.parse::<Lookup>().ok()` at every call site in
`query/filter.rs` and `query/evaluate.rs`.

## Problem B — `FExprOp` should derive `Copy`

```rust
// value.rs — current
#[derive(Debug, Clone, PartialEq)]
pub enum FExprOp {
    Add,
    Sub,
    Mul,
    Div,
    Mod,
}
```

`FExprOp` has 5 unit variants with no heap data. It fits all `Copy` requirements:
- All fields are `Copy` (no fields at all)
- Enum size ≤ 1 byte (5 variants fits in a `u8`)
- Pure data, no ownership

Callers frequently match on it and pass it around — Copy avoids unnecessary moves and
makes the semantics clearer (this is an operator tag, not a resource).

## Fix B

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub enum FExprOp {
    Add,
    Sub,
    Mul,
    Div,
    Mod,
}
```

Add `Eq` and `Hash` at the same time (they have no cost and are needed for any future
map/set use).

## Problem C — `DatabaseBackend::from_engine` allocates unnecessarily

```rust
// backend.rs — current
pub fn from_engine(engine: &str) -> crate::Result<Self> {
    match engine.to_lowercase().as_str() {   // ← allocates a new String
        "sqlite" | "sqlite3" | ... => ...
    }
}
```

`to_lowercase()` allocates a `String` on every call to `from_engine`, which runs at
startup for each database alias. The fix is to compare case-insensitively without
allocation:

```rust
pub fn from_engine(engine: &str) -> crate::Result<Self> {
    // Iterate the lowercase bytes only — no heap allocation
    let engine_lower = engine.to_ascii_lowercase(); // stack if short, or keep as-is
    match engine_lower.as_str() { ... }
}
```

Actually `to_ascii_lowercase()` still allocates for non-ASCII. The best zero-alloc
approach is `unicase::UniCase` or a manual `eq_ignore_ascii_case` match:

```rust
pub fn from_engine(engine: &str) -> crate::Result<Self> {
    if engine.eq_ignore_ascii_case("sqlite")
        || engine.eq_ignore_ascii_case("sqlite3")
        || engine.eq_ignore_ascii_case("ormpi.backends.sqlite")
    {
        return Ok(Self::Sqlite);
    }
    if engine.eq_ignore_ascii_case("mysql")
        || engine.eq_ignore_ascii_case("mariadb")
        || engine.eq_ignore_ascii_case("ormpi.backends.mysql")
    {
        return Ok(Self::Mysql);
    }
    if engine.eq_ignore_ascii_case("postgres")
        || engine.eq_ignore_ascii_case("postgresql")
        || engine.eq_ignore_ascii_case("ormpi.backends.postgres")
        || engine.eq_ignore_ascii_case("ormpi.backends.postgresql")
    {
        return Ok(Self::Postgres);
    }
    Err(crate::OrmpiError::UnknownBackend(engine.to_string()))
}
```

This is zero-allocation for the successful path.
