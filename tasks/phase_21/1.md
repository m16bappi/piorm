# Task 21.1 — Rename `OrmpiValue::to_sea_value` → `into_query_value(self)`

## Problem

`OrmpiValue::to_sea_value(&self) -> sea_query::Value` has two issues:

1. **Naming leaks a dependency**: `to_sea_value` bakes the `sea-query` crate name into the
   public API. If the SQL builder ever changes (or the method is read cold), the name is
   meaningless outside the implementation context. A generic name like `into_query_value`
   communicates intent without coupling to a vendor library.

2. **Unnecessary clones on every query binding**: Because the method takes `&self`, the
   `Text(String)`, `Bytes(Vec<u8>)` and `Json(JsonValue)` variants must clone their heap
   data on every single parameter binding — hot path in every query.

```rust
// current — clones String on every query parameter
OrmpiValue::Text(s) => sea_query::Value::String(Some(s.clone())),
OrmpiValue::Bytes(b) => sea_query::Value::Bytes(Some(b.clone())),
OrmpiValue::Json(j)  => sea_query::Value::Json(Some(Box::new(j.clone()))),
```

## Fix

### Step 1 — Change signature to consume `self`

```rust
// ormpi-core/src/value.rs
impl OrmpiValue {
    /// Convert into a `sea_query::Value` for use in query parameters.
    pub fn into_query_value(self) -> sea_query::Value {
        match self {
            OrmpiValue::Null           => sea_query::Value::Int(None),
            OrmpiValue::Bool(b)        => sea_query::Value::Bool(Some(b)),
            OrmpiValue::Int(i)         => sea_query::Value::BigInt(Some(i)),
            OrmpiValue::Float(f)       => sea_query::Value::Double(Some(f)),
            OrmpiValue::Text(s)        => sea_query::Value::String(Some(s)),   // no clone
            OrmpiValue::Bytes(b)       => sea_query::Value::Bytes(Some(b)),    // no clone
            OrmpiValue::Date(d)        => sea_query::Value::ChronoDate(Some(d)),
            OrmpiValue::Time(t)        => sea_query::Value::ChronoTime(Some(t)),
            OrmpiValue::DateTime(dt)   => sea_query::Value::ChronoDateTime(Some(dt)),
            OrmpiValue::DateTimeTz(dt) => sea_query::Value::ChronoDateTimeUtc(Some(dt)),
            OrmpiValue::Uuid(u)        => sea_query::Value::Uuid(Some(u)),
            OrmpiValue::Json(j)        => sea_query::Value::Json(Some(Box::new(j))), // no clone
            OrmpiValue::Decimal(d)     => sea_query::Value::Double(Some(
                d.to_f64().unwrap_or(f64::NAN),
            )),
            OrmpiValue::List(_)  => sea_query::Value::Bytes(None),
            OrmpiValue::FExpr(_) => sea_query::Value::Bytes(None),
        }
    }
}
```

### Step 2 — Update all call sites

Search for every `.to_sea_value()` call in `ormpi-core/src/` and replace with
`.into_query_value()`. Key locations:

| File | Pattern |
|------|---------|
| `query/evaluate.rs` | building `Values` for SELECT/INSERT/UPDATE parameters |
| `model/executor.rs` | INSERT/UPDATE parameter binding |
| `query/filter.rs`   | lookup_to_expr value binding |

Because `into_query_value` consumes the value, callers that previously did
`val.to_sea_value()` on a reference must either clone before calling or restructure
to consume. Look for `&val.to_sea_value()` or iterators that call it on borrowed items
and adjust appropriately (typically `val.clone().into_query_value()` is the right fix,
but look for cases where ownership can be transferred directly to avoid the clone entirely).

### Step 3 — Update tests in `value.rs`

```rust
#[test]
fn test_null_roundtrip() {
    let v = OrmpiValue::Null;
    assert!(matches!(v.into_query_value(), sea_query::Value::Int(None)));
}

#[test]
fn test_text_no_clone() {
    let s = "hello".to_string();
    let v = OrmpiValue::Text(s);
    // Value moves the String — no allocation
    assert!(matches!(
        v.into_query_value(),
        sea_query::Value::String(Some(t)) if t == "hello"
    ));
}
```

## Acceptance Criteria

- [ ] `OrmpiValue::to_sea_value` is deleted; `into_query_value(self)` replaces it everywhere
- [ ] No new `.clone()` calls introduced at call sites where ownership can be transferred
- [ ] All existing value tests pass under the new name
- [ ] `cargo clippy` reports no `redundant_clone` warnings in `value.rs`
