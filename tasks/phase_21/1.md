# Task 21.1 — Eliminate `unsafe transmute` in `OrmpiTransaction::begin()`

## Severity

**CRITICAL** — Undefined behavior. Memory safety violation.

## Problem

`ormpi-core/src/transaction.rs:34-48` transmutes a `sqlx::Transaction<'_, DB>` to
`sqlx::Transaction<'static, DB>`:

```rust
let txn: sqlx::Transaction<'static, sqlx::Sqlite> =
    unsafe { std::mem::transmute(txn) };
```

The SAFETY comment claims the pool lives for the process lifetime, but this is unsound:

1. `OrmpiPool::close()` exists and can be called while a transaction is active.
2. If the pool is dropped (test teardown, reconnect, connection lost), the transaction
   holds a reference to freed memory.
3. This violates Rust's aliasing rules — UB by definition.

## Fix

### Option A — Store `Arc<Pool>` inside the transaction (recommended)

Replace the lifetime-dependent `Transaction` with a pattern where the pool is cloned
as `Arc` and the transaction carries its own reference:

```rust
pub enum OrmpiPool {
    Sqlite(Arc<Pool<Sqlite>>),
    Mysql(Arc<Pool<MySql>>),
    Postgres(Arc<Pool<Postgres>>),
}
```

`sqlx::Pool` is already `Clone` (internally `Arc`-wrapped), so wrapping in `Arc` is
redundant — just clone the pool. The transaction can then be managed as an opaque
handle that doesn't need `'static`:

- Move transaction management to a wrapper that owns a cloned `Pool` and holds an
  `Option<Transaction>` behind a `Mutex`.
- The `begin()` call returns an owned value; no lifetime extension needed.

### Option B — Scoped lifetime

Restructure so the caller holds both the pool reference and transaction:

```rust
pub async fn begin<'a>(
    pool: &'a OrmpiPool,
    alias: &str,
) -> crate::Result<OrmpiTransaction<'a>> {
    // Transaction lifetime tied to pool — no transmute needed
}
```

This requires changing `OrmpiTransaction` to `OrmpiTransaction<'a>` and propagating
the lifetime through all callers. More invasive but fully safe.

### Option C — `Box<dyn Any>` erasure

Store the transaction as `Box<dyn Any + Send>` and downcast on each operation.
This avoids lifetime issues at the cost of runtime type checking.
