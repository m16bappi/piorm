# Task 21.2 — Remove Redundant `columns: Vec<String>` from `OrmpiRow`

## Problem

`OrmpiRow` stores the same data twice:

```rust
pub struct OrmpiRow {
    pub columns: Vec<String>,                 // ← redundant
    pub values: IndexMap<String, OrmpiValue>, // ← already preserves insertion order
}
```

`IndexMap` guarantees insertion-order iteration, so `columns` is always identical to
`values.keys()` collected into a `Vec`. Every row conversion in `row.rs` pays an extra
`name.clone()` + `Vec::push` for every column on every row — purely to maintain a field
that adds no information.

```rust
// row.rs — in every backend's conversion loop
columns.push(name.clone());   // ← clone to keep columns in sync
values.insert(name, value);   // ← name moved here
```

## Fix

### Step 1 — Remove `columns` from `OrmpiRow`

```rust
// ormpi-core/src/row.rs
#[derive(Debug, Clone)]
pub struct OrmpiRow {
    pub values: IndexMap<String, OrmpiValue>,
}

impl OrmpiRow {
    /// Returns column names in insertion order.
    pub fn columns(&self) -> impl Iterator<Item = &str> {
        self.values.keys().map(String::as_str)
    }

    pub fn get(&self, column: &str) -> Option<&OrmpiValue> {
        self.values.get(column)
    }

    pub fn get_required(&self, column: &str) -> crate::Result<&OrmpiValue> {
        self.values.get(column).ok_or_else(|| OrmpiError::FieldError {
            model: "?".to_string(),
            field: column.to_string(),
            message: format!("Column '{column}' not found in result row"),
        })
    }
}
```

### Step 2 — Simplify all three backend row-conversion loops

Remove the `columns` variable and the `clone()` from every conversion function:

```rust
// Before
let mut values = IndexMap::new();
let mut columns = Vec::new();
for col in row.columns() {
    let name = col.name().to_string();
    // ... compute value ...
    columns.push(name.clone());  // ← remove this
    values.insert(name, value);
}
Ok(OrmpiRow { columns, values })  // ← update this

// After
let mut values = IndexMap::new();
for col in row.columns() {
    let name = col.name().to_string();
    // ... compute value ...
    values.insert(name, value);
}
Ok(OrmpiRow { values })
```

Apply the same simplification to:
- `sqlite_row_to_ormpi`
- `mysql_row_to_ormpi`
- `postgres_row_to_ormpi`

### Step 3 — Update callers of `row.columns`

Anywhere code accesses `row.columns` as a field, replace with `row.columns()` method
call. Common patterns to search for:

```rust
// Before
for col in &row.columns { ... }
row.columns.len()
row.columns.iter()

// After
for col in row.columns() { ... }
row.values.len()
row.columns()
```

Key files to check: `query/evaluate.rs`, `executor.rs`, `ormpi-py/src/query/queryset.rs`.

- [ ] All three backend row functions no longer call `name.clone()`
