# Task 21.2 — DRY Backend Dispatch: Extract Common Pool Operations

## Severity

**HIGH** — ~500+ lines of near-identical code across 6 files.

## Problem

Nearly every async function that touches the database duplicates this pattern:

```rust
match pool {
    OrmpiPool::Sqlite(p) => {
        let args = sqlite_arguments(sea_vals);
        let rows = sqlx::query_with(&sql, args).fetch_all(p).await?;
        rows.iter().map(sqlite_row_to_ormpi).collect()
    }
    OrmpiPool::Mysql(p) => { /* identical */ }
    OrmpiPool::Postgres(p) => { /* identical */ }
}
```

Files affected:
- `executor.rs` — 3 match blocks + 3 near-identical `extract_*_value` functions
- `bind.rs` — 3 functions that are 95% identical
- `row.rs` — 3 `*_row_to_ormpi` functions
- `model/executor.rs` — 8+ match blocks (save, update, delete, fetch)
- `query/evaluate.rs` — 10+ match blocks (evaluate, count, aggregate, bulk_*)
- `migration/executor.rs` — 6+ match blocks (apply, unapply, recorder methods)

Adding a 4th backend requires touching 15+ functions.

## Fix

### Step 1 — Add methods to `OrmpiPool`

```rust
impl OrmpiPool {
    pub async fn execute_with(&self, sql: &str, args: DynArguments) -> Result<u64> { ... }
    pub async fn fetch_all_with(&self, sql: &str, args: DynArguments) -> Result<Vec<DynRow>> { ... }
    pub async fn fetch_one_with(&self, sql: &str, args: DynArguments) -> Result<DynRow> { ... }
}
```

The internal `match` lives in exactly one place per operation. Callers become:

```rust
// BEFORE: 12 lines per call site
// AFTER: 1-2 lines
let rows = pool.fetch_all_with(&sql, args).await?;
rows.iter().map(row_to_ormpi).collect()
```

### Step 2 — Abstract the bind layer

```rust
pub fn bind_values(backend: DatabaseBackend, values: Values) -> DynArguments {
    match backend {
        DatabaseBackend::Sqlite => DynArguments::Sqlite(sqlite_arguments(values)),
        DatabaseBackend::Mysql => DynArguments::MySql(mysql_arguments(values)),
        DatabaseBackend::Postgres => DynArguments::Postgres(postgres_arguments(values)),
    }
}
```

Or better: have `OrmpiPool::fetch_all_with` accept `sea_query::Values` directly and
do the binding internally.

### Step 3 — Consolidate row conversion

Replace the three `*_row_to_ormpi` functions with a single generic:

```rust
fn sqlx_row_to_ormpi(row: &dyn sqlx::Row) -> Result<OrmpiRow> {
    // Use TypeInfo::name() to dispatch per-column (already done per-backend)
}
```

This may require a small trait abstraction since `SqliteRow`, `MySqlRow`, `PgRow` all
implement `sqlx::Row` but are distinct types.

### Step 4 — Consolidate `extract_*_value` in `executor.rs`

The three `extract_sqlite_value`, `extract_mysql_value`, `extract_postgres_value`
functions are nearly identical. Merge into one parameterized function or use the
row-conversion abstraction from Step 3.

## Files Changed

|------|--------|
| `ormpi-core/src/pool.rs` | Add `execute_with`, `fetch_all_with`, `fetch_one_with` methods |

| `ormpi-core/src/row.rs` | Consolidate to single conversion function |

## Acceptance Criteria

- [ ] Each async DB operation has exactly one `match pool` at the lowest level (pool methods)
- [ ] No caller of pool methods contains a `match pool { Sqlite/Mysql/Postgres }` block
- [ ] `bind.rs` has a single dispatch entry point
- [ ] `row.rs` has a single conversion entry point
- [ ] All existing tests pass without behavioral changes
- [ ] Line count reduction of ≥300 lines across the affected files
