# Task 21.7 — Consolidate `bind.rs` Duplication with a Shared Trait

## Problem

`bind.rs` has three nearly-identical private helpers — `bind_sqlite`, `bind_mysql`,
`bind_postgres` — each matching all 22 `sea_query::Value` variants and calling
`args.add(v)`. The only differences are:

1. The `args` type (`SqliteArguments`, `MySqlArguments`, `PgArguments`)
2. A handful of variant-specific transformations (e.g. Postgres maps `TinyUnsigned` to
   `i16`, MySQL stores `ChronoDateTimeWithTimeZone` as a UTC string)

This is ~120 lines of structural duplication. Adding a new `Value` variant means
updating all three functions independently.

## Root Cause

`sqlx::Arguments` is a generic trait parameterised over a `Database` associated type,
so the three argument types cannot share a single generic path without fighting the
type system.

## Fix — Macro-based deduplication

A declarative macro can express the common binding logic once and expand it per backend:

```rust
/// Binds a sea_query Value to an sqlx Arguments impl.
///
/// Shared arms handle the common case; per-backend overrides handle dialect differences.
macro_rules! bind_value {
    // Common arms shared by all backends
    ($args:expr, $value:expr $(, $override:tt)* ) => {
        match $value {
            Value::Bool(v)        => { let _ = $args.add(v); }
            Value::TinyInt(v)     => { let _ = $args.add(v); }
            Value::SmallInt(v)    => { let _ = $args.add(v); }
            Value::Int(v)         => { let _ = $args.add(v); }
            Value::BigInt(v)      => { let _ = $args.add(v); }
            Value::Float(v)       => { let _ = $args.add(v); }
            Value::Double(v)      => { let _ = $args.add(v); }
            Value::String(v)      => { let _ = $args.add(v); }
            Value::Char(v)        => { let _ = $args.add(v.map(|c| c.to_string())); }
            Value::Bytes(v)       => { let _ = $args.add(v); }
            Value::ChronoDate(v)  => { let _ = $args.add(v); }
            Value::ChronoTime(v)  => { let _ = $args.add(v); }
            Value::ChronoDateTime(v)    => { let _ = $args.add(v); }
            Value::ChronoDateTimeUtc(v) => { let _ = $args.add(v); }
            Value::Uuid(v)        => { let _ = $args.add(v); }
            // variants with overrides supplied by caller:
            $($override)*
        }
    };
}
```

However, `declarative macros` cannot elegantly express "shared arms with per-backend
overrides". A cleaner approach for this use case is a **helper closure** pattern:

### Preferred approach — split common and dialect-specific binding

Identify the ~4 variant arms that differ between backends and extract them:

```rust
fn bind_common_value<A>(args: &mut A, value: Value)
where
    A: sqlx::Arguments<'static>,
    // bound for each primitive type:
    Option<bool>: sqlx::Encode<'static, A::Database> + sqlx::Type<A::Database>,
    // ... etc (this gets verbose)
```

This runs into trait-bound verbosity quickly. The **most pragmatic** fix is:

### Pragmatic fix — shared `match` table extracted to constants + per-backend divergences documented

Since the functions are private and already well-structured, the minimum viable change is:

1. Add a single `// ── Common binding logic ─────` comment block noting the shared
   structure to prevent silent divergence
2. Extract the 3 divergent arms for each backend into clearly-named private helpers:
   - `sqlite_bind_unsigned_big(args, v)` — converts `BigUnsigned` to `i64::MAX`
   - `postgres_bind_unsigned(args, tinyunsigned, smallunsigned, unsigned, bigunsigned)` — maps unsigned to signed
   - `mysql_bind_tz_datetime(args, v)` — serializes to UTC string

3. Add a `#[cfg(test)] fn assert_all_value_variants_handled()` compile-time exhaustiveness
   check to guarantee new variants can't be silently skipped

```rust
// Compile-time check: this will fail to compile if a new Value variant is added
// without updating all three bind_* functions
#[cfg(test)]
#[allow(dead_code)]
fn all_variants_are_handled(v: sea_query::Value) {
    let mut dummy_sqlite = sqlx::sqlite::SqliteArguments::default();
    bind_sqlite(&mut dummy_sqlite, v);
}
```
