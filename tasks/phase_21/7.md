# Task 21.7 — Apply Type State Pattern to `OrmpiTransaction`

## Severity

**LOW** — Runtime checks that could be compile-time.

## Problem

`OrmpiTransaction` tracks state at runtime via `TransactionState`:

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum TransactionState {
    Open,
    Committed,
    RolledBack,
}
```

`commit()` and `rollback()` check `self.state != TransactionState::Open` at runtime:

```rust
pub async fn commit(self) -> crate::Result<()> {
    if self.state != TransactionState::Open {
        return Err(OrmpiError::TransactionError("Transaction is not open".into()));
    }
    // ...
}
```

This means you can write code that attempts to commit an already-committed transaction
and only discover the bug at runtime. The type state pattern (Chapter 7) moves this
check to compile time.

## Fix

### Step 1 — Define state marker types

```rust
use std::marker::PhantomData;

pub struct Open;
pub struct Committed;
pub struct RolledBack;

pub struct OrmpiTransaction<S> {
    pub handle: TransactionHandle,
    pub alias: String,
    _state: PhantomData<S>,
}
```

### Step 2 — Only implement `commit`/`rollback` for `Open` state

```rust
impl OrmpiTransaction<Open> {
    pub async fn begin(pool: &OrmpiPool, alias: &str) -> crate::Result<Self> {
        // ... existing begin logic ...
        Ok(OrmpiTransaction {
            handle,
            alias: alias.to_string(),
            _state: PhantomData,
        })
    }

    pub async fn commit(self) -> crate::Result<OrmpiTransaction<Committed>> {
        // ... commit handle ...
        Ok(OrmpiTransaction {
            handle: self.handle,
            alias: self.alias,
            _state: PhantomData,
        })
    }

    pub async fn rollback(self) -> crate::Result<OrmpiTransaction<RolledBack>> {
        // ... rollback handle ...
        Ok(OrmpiTransaction {
            handle: self.handle,
            alias: self.alias,
            _state: PhantomData,
        })
    }

    pub async fn execute_raw(&mut self, sql: &str) -> crate::Result<()> {
        // ... only available on Open transactions ...
    }
}
```

### Step 3 — Update callers

The Python layer (`ormpi-py/src/transaction.rs`) currently stores the transaction as
`Option<OrmpiTransaction>` with a `state` field check. Update to use the type-state:

```rust
#[pyclass]
pub struct PyTransaction {
    inner: Arc<Mutex<Option<ErasedTransaction>>>,
}

// Use trait-object erasure or an enum wrapper to store any state:
enum ErasedTransaction {
    Open(OrmpiTransaction<Open>),
    Committed(OrmpiTransaction<Committed>),
    RolledBack(OrmpiTransaction<RolledBack>),
}
```

### Step 4 — Remove `TransactionState` enum

No longer needed — the state is encoded in the type parameter.

## Files Changed

| File | Change |
|------|--------|
| `ormpi-core/src/transaction.rs` | Add `Open`/`Committed`/`RolledBack` marker types; parameterize `OrmpiTransaction<S>` |
| `ormpi-py/src/transaction.rs` | Update `PyTransaction` to use `ErasedTransaction` enum |
| `ormpi-py/src/lib.rs` | Update savepoint callers to match new API |

- [ ] `rollback()` is only callable on `OrmpiTransaction<Open>` — compile error otherwise
