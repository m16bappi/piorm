# Task 21.6 — Remove Dead Code and Unused Implementations

## Problem

Carrying unused code increases compile times, confuses readers, and creates maintenance
surface. This task systematically removes anything unused in `ormpi-core`.

## Audit Checklist

Run the following before starting to get the full picture:

```bash
# In the workspace root
RUSTFLAGS="-D dead_code -D unused_imports -D unused_variables" \
    cargo check -p ormpi-core 2>&1 | grep "warning:"

cargo clippy -p ormpi-core --all-targets -- \
    -W clippy::unused_imports \
    -W clippy::dead_code \
    2>&1 | grep "warning:"
```

### Known dead code targets

#### 1 — `PlaceholderStyle` enum is defined but barely used

```rust
// backend.rs
pub enum PlaceholderStyle {
    QuestionMark,
    Numbered,
}
```

`DatabaseBackend::placeholder_style()` returns it, but callers in the codebase seem to
switch on `DatabaseBackend` directly. Audit all callers: if `PlaceholderStyle` is
unreferenced outside its own definition, remove both the enum and the method.

#### 2 — `ModelRegistry::get_all_for_app` — verify it is called

```rust
// model/registry.rs
pub fn get_all_for_app(&self, app_label: &str) -> Vec<&ModelDef> { ... }
```

Check whether this is called outside tests. If only in tests, keep it but move it
under `#[cfg(test)]`.

#### 3 — `ModelRegistry::count` — verify usage

```rust
pub fn count(&self) -> usize { self.models.len() }
```

Same audit as above. Keep if used; gate under `#[cfg(test)]` if test-only.

#### 4 — Unused `HashMap` imports in files using `IndexMap`

Several files import `std::collections::HashMap` but use `indexmap::IndexMap` for
main data structures. Confirm no actual `HashMap` usage and remove the import.

#### 5 — `OrmpiRow::get` vs `OrmpiRow::get_required`

Both methods are kept. Verify `get` (the Option-returning variant) has live callers;
remove if only `get_required` is used.

#### 6 — `bind.rs` — `let _ = args.add(...)` pattern

All binding calls discard the `Result`:

```rust
Value::Bool(v) => { let _ = args.add(v); }
```

`sqlx::Arguments::add` returns `Result<(), BoxDynError>`. Discarding it silently drops
binding errors. Change to:

```rust
Value::Bool(v) => args.add(v)?,
```

This requires changing the `bind_*` helper signatures to `-> crate::Result<()>` and
propagating with `?`. This is not dead-code removal per se, but it eliminates 60+
silent error discards that are functionally dead error-handling.

#### 7 — Temporal types unused in SQLite and MySQL bindings

`bind.rs` handles `ChronoDateTimeLocal` and `ChronoDateTimeWithTimeZone` for SQLite
and MySQL even though `OrmpiValue::into_query_value()` (after task 21.1) only ever
emits `ChronoDate`, `ChronoTime`, `ChronoDateTime`, and `ChronoDateTimeUtc`. Audit
whether `ChronoDateTimeLocal` and `ChronoDateTimeWithTimeZone` arms in `bind_sqlite`
and `bind_mysql` are reachable; add a `// SAFETY: unreachable via OrmpiValue::into_query_value`
comment or remove the arms if `sea_query::Value` can be exhaustively proven to never
carry those variants in this codebase.

## Fix Process

1. Run the audit commands above
2. Remove or gate each identified dead item
3. Add `#[expect(dead_code)]` with justification for any item intentionally kept unused
   (e.g., public API exported for downstream crates)

## Acceptance Criteria

- [ ] `cargo check -p ormpi-core` emits zero `dead_code` / `unused_imports` warnings
- [ ] `bind_*` helpers return `Result` and propagate binding errors with `?`
- [ ] Any test-only registry helpers moved under `#[cfg(test)]`
- [ ] No regressions in existing tests
