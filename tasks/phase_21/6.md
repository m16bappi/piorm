# Task 21.6 — Remove Duplicate `MigrationFile` Struct and Global Mutable Singletons

## Severity

**MEDIUM** — Code confusion and test fragility.

## Problem 1 — Duplicate `MigrationFile`

Two separate `MigrationFile` structs exist:

1. `migration/file.rs:13` — the canonical version with `MigrationMeta`:
   ```rust
   pub struct MigrationFile {
       pub migration: MigrationMeta,
       pub operations: Vec<StoredOperation>,
   }
   ```

2. `migration/operations.rs:738` — a legacy version:
   ```rust
   pub struct MigrationFile {
       pub name: String,
       pub dependencies: Vec<String>,
       pub operations: Vec<StoredOperation>,
   }
   ```

The one in `operations.rs` is marked "legacy, used in state.rs" but `state.rs` actually
imports from `file.rs`. This duplicate causes confusion and may lead to using the wrong one.

## Problem 2 — Global Mutable Singletons

Two global singletons hold mutable state behind `RwLock`:

- `registry.rs:10` — `static REGISTRY: OnceCell<Arc<RwLock<DatabaseRegistry>>>`
- `model/registry.rs:8` — `static MODEL_REGISTRY: Lazy<Arc<RwLock<ModelRegistry>>>`

Issues:
- Tests sharing the global registry can interfere with each other (test ordering matters)
- `RwLock` panics on poison — if one test panics, subsequent tests may fail
- Cannot create isolated instances for parallel testing
- `registry.rs:49` — `.unwrap()` on write lock panics on poison
- `model/registry.rs` — multiple `.unwrap()` calls on read/write locks

## Fix

### Part A — Remove duplicate `MigrationFile`

1. Delete the `MigrationFile` struct in `operations.rs:738-744`
2. Search for any import of `migration::operations::MigrationFile` and redirect to
   `migration::file::MigrationFile`
3. Verify `state.rs` already uses the correct import

### Part B — Make registries injectable

Replace global singletons with an explicitly passed context:

```rust
pub struct OrmpiContext {
    db_registry: Arc<RwLock<DatabaseRegistry>>,
    model_registry: Arc<RwLock<ModelRegistry>>,
}

impl OrmpiContext {
    pub fn new() -> Self { ... }
    pub fn global() -> &'static OrmpiContext { ... }  // for convenience
}
```

Short-term fix (less invasive):
1. Replace `.unwrap()` on `RwLock` with `.map_err(|_| OrmpiError::Other("lock poisoned".into()))`
   everywhere
2. Add a `clear()` method for test teardown
3. Wrap in a test helper that resets state between tests

```rust
// Safe lock access helper
fn read_registry<T>(lock: &RwLock<T>) -> crate::Result<RwLockReadGuard<'_, T>> {
    lock.read().map_err(|_| OrmpiError::Other("registry lock poisoned".into()))
}

fn write_registry<T>(lock: &RwLock<T>) -> crate::Result<RwLockWriteGuard<'_, T>> {
    lock.write().map_err(|_| OrmpiError::Other("registry lock poisoned".into()))
}
```
