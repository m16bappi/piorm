# Task 9: Extract `get_pool_for_alias` Helper to Eliminate Repeated Registry Lookup

## Problem

The following 4-line pattern appears **7 times** across `ormpi-py/src/lib.rs` and `ormpi-py/src/model/instance.rs`:

```rust
let pool = {
    let registry = ormpi_core::registry::DatabaseRegistry::global();  // or reg / reg_guard
    let guard = registry.read().unwrap();
    guard.get_pool(&alias).map_err(ormpi_err)?.clone()
};
```

Exact locations:
- `lib.rs:execute_sql` (lines 202–206)
- `lib.rs:execute_raw` (lines 229–233)
- `lib.rs:create_table` (lines 323–327)
- `lib.rs:create_all_tables` (lines 381–385)
- `lib.rs:configure` (lines 139–143) — same but with `map_err(ormpi_err)`
- `instance.rs:save` (lines 187–191)
- `instance.rs:delete` (lines 250–254)
- `instance.rs:refresh_from_db` (lines 299–303)

Each location acquires the read lock, looks up the pool by alias, maps the error, and clones. The alias variable is sometimes `&str`, sometimes `String`, sometimes `&alias`.

## Fix

Add a free function `get_pool_for_alias` to `ormpi-py/src/lib.rs` (or a new `ormpi-py/src/db/util.rs`):

```rust
/// Look up a pool by alias from the global registry.
/// Converts OrmpiError into PyErr so it can be used with `?` in PyResult contexts.
pub(crate) fn get_pool_for_alias(alias: &str) -> PyResult<ormpi_core::pool::OrmpiPool> {
    let registry = ormpi_core::registry::DatabaseRegistry::global();
    let guard = registry.read().unwrap();
    guard.get_pool(alias).map_err(ormpi_err).map(|p| p.clone())
}
```

### Updated call sites in `lib.rs`

**`execute_sql` (lines 202–206):**
```rust
// Before:
let pool = {
    let registry = ormpi_core::registry::DatabaseRegistry::global();
    let guard = registry.read().unwrap();
    guard.get_pool(&alias).map_err(ormpi_err)?.clone()
};
// After:
let pool = get_pool_for_alias(&alias)?;
```

**`execute_raw` (lines 229–233):** same replacement.

**`create_table` (lines 323–327):** same replacement inside the `async move` block:
```rust
// Before (inside async move):
let pool = {
    let guard = registry.read().unwrap();
    guard.get_pool(&alias).map_err(ormpi_err)?.clone()
};
// After:
let pool = Python::with_gil(|_| get_pool_for_alias(&alias))?;
```

**`create_all_tables` (lines 381–385):** same.

**`configure` (lines 139–143):** same.

### Updated call sites in `instance.rs`

Since `instance.rs` functions run outside an `async move` block (they set up the async and then move data into it), the pool lookup happens before the future:

**`save` (lines 187–191):**
```rust
// Before:
let pool = {
    let reg = ormpi_core::registry::DatabaseRegistry::global();
    let guard = reg.read().unwrap();
    guard.get_pool(&using).map_err(crate::ormpi_err)?.clone()
};
// After:
let pool = crate::get_pool_for_alias(&using)?;
```

**`delete` (lines 250–254):** same.

**`refresh_from_db` (lines 299–303):** same.
