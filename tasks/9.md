# Task 9 — Python-Side `on_commit` Hook Management

## Background

`PyTransaction` in `ormpi-py/src/transaction.rs` already supports registering
`on_commit` callbacks, but they fire from Rust after `commit()` completes by
re-acquiring the GIL:

```rust
Python::with_gil(|py| {
    for cb in &callbacks {
        if let Err(e) = cb.bind(py).call0() {
            tracing::warn!("on_commit callback failed: {:?}", e);
        }
    }
    Ok::<_, PyErr>(py.None())
})
```

This has several limitations:

1. **Async callbacks are not supported.** Callbacks must be zero-argument
   synchronous callables. Any coroutine function silently fails (the
   `call0()` returns the coroutine object without awaiting it).
2. **Errors are silently swallowed.** `tracing::warn!` is invisible to Python
   callers; exceptions in callbacks should be surfaced, not suppressed.
3. **No Python-level API for registering hooks after `atomic()` enters.**
   The `on_commit` method is on `Transaction` directly but `atomic()` yields
   the `Transaction` to the caller without a convenience wrapper.
4. **No support for hooks on the ambient transaction.** Callers inside a
   nested `atomic()` block cannot register hooks on the outer transaction
   without holding a reference to it explicitly.

The doc references Django's `on_commit` as inspiration:

> `robust=True` — for on-commit hooks where errors should not abort the whole
> chain (Django's model for deferred side effects like sending emails).

## Design

### Module-level `on_commit(callback, using="default", robust=False)`

```python
async def on_commit(
    callback: Callable[[], Awaitable[None] | None],
    *,
    using: str = "default",
    robust: bool = False,
) -> None:
    """Register a callback to be called after the current transaction commits.

    If no transaction is active, the callback is called immediately.

    Args:
        callback: A zero-argument sync or async callable.
        using:    Database alias to look up the ambient transaction.
        robust:   If True, exceptions in the callback are logged but not
                  re-raised (useful for non-critical side effects like emails).
    """
    txn = _get_current_transaction(using)
    if txn is None or not txn.is_open:
        await _invoke(callback, robust=robust)
        return
    txn.on_commit(_wrap_callback(callback, robust=robust))
```

### Async-safe callback wrapper

The Rust `on_commit` method fires sync callbacks. To support async callbacks,
wrap them at the Python layer before passing to Rust:

```python
def _wrap_callback(cb, robust: bool) -> Callable[[], None]:
    """Return a sync zero-arg callable that schedules `cb` on the event loop."""
    import asyncio, inspect

    def sync_wrapper():
        if inspect.iscoroutinefunction(cb):
            loop = asyncio.get_event_loop()
            task = loop.create_task(cb())
            if not robust:
                task.add_done_callback(
                    lambda t: t.result() if not t.cancelled() else None
                )
        else:
            try:
                cb()
            except Exception:
                if not robust:
                    raise

    return sync_wrapper
```

### Error surfacing

Remove the `tracing::warn!` silent swallow in Rust. Instead, propagate
`on_commit` errors as `PyRuntimeError` and let the Python layer decide
whether to suppress them (via `robust=True`).

## Test Cases

### Tests — `__tests__/transactions/test_on_commit.py`

**TC-9.1 — `on_commit` callback fires after commit**
```python
@pytest.mark.asyncio
async def test_on_commit_fires_after_commit():
    fired = []

    async with ormpi.transaction.atomic() as txn:
        txn.on_commit(lambda: fired.append("fired"))

    assert fired == ["fired"]
```

**TC-9.2 — `on_commit` callback does NOT fire after rollback**
```python
@pytest.mark.asyncio
async def test_on_commit_not_fired_on_rollback():
    fired = []

    with pytest.raises(ValueError):
        async with ormpi.transaction.atomic() as txn:
            txn.on_commit(lambda: fired.append("fired"))
            raise ValueError("rollback")

    assert fired == []
```

**TC-9.3 — Multiple `on_commit` callbacks fire in registration order**
```python
@pytest.mark.asyncio
async def test_on_commit_order():
    order = []

    async with ormpi.transaction.atomic() as txn:
        txn.on_commit(lambda: order.append(1))
        txn.on_commit(lambda: order.append(2))
        txn.on_commit(lambda: order.append(3))

    assert order == [1, 2, 3]
```

**TC-9.4 — Module-level `on_commit()` uses ambient transaction**
```python
@pytest.mark.asyncio
async def test_module_level_on_commit_uses_ambient():
    from ormpi.transaction import on_commit

    fired = []

    async with ormpi.transaction.atomic():
        await on_commit(lambda: fired.append("ambient"))

    assert fired == ["ambient"]
```

**TC-9.5 — Module-level `on_commit()` fires immediately when no transaction**
```python
@pytest.mark.asyncio
async def test_on_commit_fires_immediately_outside_transaction():
    from ormpi.transaction import on_commit

    fired = []
    await on_commit(lambda: fired.append("immediate"))
    assert fired == ["immediate"]
```

**TC-9.6 — Async callback is awaited (not just created)**
```python
@pytest.mark.asyncio
async def test_async_on_commit_callback():
    import asyncio
    fired = []

    async def async_hook():
        await asyncio.sleep(0)
        fired.append("async")

    async with ormpi.transaction.atomic() as txn:
        txn.on_commit(async_hook)

    # Give the scheduled task a chance to run
    await asyncio.sleep(0.05)
    assert fired == ["async"]
```

**TC-9.7 — `robust=True` callback error is not re-raised**
```python
@pytest.mark.asyncio
async def test_robust_on_commit_suppresses_error():
    from ormpi.transaction import on_commit

    def failing_hook():
        raise RuntimeError("hook failed")

    async with ormpi.transaction.atomic():
        await on_commit(failing_hook, robust=True)
    # No exception should propagate
```

**TC-9.8 — Non-robust callback error IS raised**
```python
@pytest.mark.asyncio
async def test_non_robust_on_commit_raises():
    from ormpi.transaction import on_commit

    def failing_hook():
        raise RuntimeError("hook failed")

    with pytest.raises(RuntimeError, match="hook failed"):
        async with ormpi.transaction.atomic():
            await on_commit(failing_hook, robust=False)
```

**TC-9.9 — `on_commit` on consumed transaction raises `RuntimeError`**
```python
@pytest.mark.asyncio
async def test_on_commit_on_consumed_transaction_raises():
    txn = await ormpi.begin()
    await txn.commit()

    with pytest.raises(RuntimeError, match="not open"):
        txn.on_commit(lambda: None)
```

**TC-9.10 — Nested `atomic()` callbacks fire with outer commit, not savepoint release**
```python
@pytest.mark.asyncio
async def test_nested_on_commit_fires_with_outer():
    fired = []

    async with ormpi.transaction.atomic() as outer:
        outer.on_commit(lambda: fired.append("outer"))
        async with ormpi.transaction.atomic() as inner:
            # inner is outer (same txn for nested) — but hook tied to outer
            pass  # savepoint released, NOT committed yet

        assert fired == []  # not yet — outer not committed

    assert fired == ["outer"]
```

## Acceptance Criteria

- [ ] `Transaction.on_commit(callback)` accepts both sync and async callables.
- [ ] Async callbacks are scheduled via `asyncio.get_event_loop().create_task()`.
- [ ] `on_commit` errors propagate by default (`robust=False`).
- [ ] `robust=True` suppresses callback errors (logs via `warnings.warn`).
- [ ] Module-level `ormpi.transaction.on_commit(callback, using=…, robust=…)`
  registered and exported.
- [ ] `on_commit` registered on no-transaction context fires immediately.
- [ ] TC-9.1 through TC-9.10 all pass under `pytest`.
- [ ] Rust `tracing::warn!` silent suppression removed from `commit()` path.
- [ ] Type stubs updated (`transaction.pyi`).
- [ ] Mypy / pyright pass on modified files.
- [ ] Existing `__tests__/` suite remains green.
