# Task 16.1 — Fix `__in` and `__range` Lookups (Always Return 0 Results)

## Failing Tests

```
TestFilterLookups::test_in_list
TestFilterLookups::test_range
TestQuerySetDelete::test_delete_with_in_lookup
TestQuerySetUpdateFiltered::test_update_with_in_lookup
TestBulkDelete::test_delete_by_pk_in
TestQuerySetUpdateBasic::test_update_returns_correct_count  (uses pk__in)
```

Errors:
```python
assert len(results) == 2    # actual: 0
assert count == 2            # actual: 0
assert count == 3            # actual: 0
```

## Root Cause

`ormpi-core/src/query/evaluate.rs` has a `TODO` stub for `Lookup::In` that treats it as
an equality check instead of a SQL `IN (...)` clause:

```rust
Lookup::In => {
    // TODO: handle list values — for now treat single value as eq
    Expr::col(col).eq(sea_val)
}
```

And `Lookup::Range` falls into the `_ => Expr::col(col).eq(sea_val)` default arm, which
is also wrong.

Additionally, `OrmpiValue` currently stores a single scalar. For `__in` to work, the
value must be a `List` variant, and for `__range` it must carry two bounds.

## Fix Part 1 — Add `List` variant to `OrmpiValue`

**File:** `ormpi-core/src/value.rs`

```rust
pub enum OrmpiValue {
    Null,
    Bool(bool),
    Int(i64),
    Float(f64),
    Text(String),
    Bytes(Vec<u8>),
    List(Vec<OrmpiValue>),    // ← NEW: for __in lookups
}
```

Add `to_sea_value()` arm for `List` (unused in scalar context, panic or return Null):

```rust
OrmpiValue::List(_) => sea_query::Value::Bytes(None), // placeholder; list is handled specially
```

## Fix Part 2 — Deserialise list values in Python → `OrmpiValue` conversion

**File:** `ormpi-py/src/model/instance.rs`, function `py_to_ormpi_value`

When the Python object is a `list` or `tuple`, collect each element recursively:

```rust
if let Ok(list) = obj.downcast::<pyo3::types::PyList>() {
    let items = list.iter()
        .map(|item| py_to_ormpi_value(&item))
        .collect::<PyResult<Vec<_>>>()?;
    return Ok(OrmpiValue::List(items));
}
if let Ok(tup) = obj.downcast::<pyo3::types::PyTuple>() {
    let items = tup.iter()
        .map(|item| py_to_ormpi_value(&item))
        .collect::<PyResult<Vec<_>>>()?;
    return Ok(OrmpiValue::List(items));
}
```

Place these checks **before** the `String` fallback.

## Fix Part 3 — Build `IN (...)` and `BETWEEN` SQL expressions

**File:** `ormpi-core/src/query/evaluate.rs`, `apply_lookup` function

Replace the `Lookup::In` and `Lookup::Range` arms:

```rust
Lookup::In => {
    match value {
        OrmpiValue::List(items) => {
            let sea_vals: Vec<sea_query::Value> = items
                .iter()
                .map(|v| v.to_sea_value())
                .collect();
            Expr::col(col).is_in(sea_vals)
        }
        single => Expr::col(col).eq(single.to_sea_value()),
    }
}
Lookup::Range => {
    // value is a List of exactly two items: [low, high]
    match value {
        OrmpiValue::List(ref bounds) if bounds.len() == 2 => {
            let lo = bounds[0].to_sea_value();
            let hi = bounds[1].to_sea_value();
            Expr::col(col.clone()).gte(lo).and(Expr::col(col).lte(hi))
        }
        _ => Expr::col(col).eq(sea_val),
    }
}
```

`sea_query::Expr::is_in` accepts `IntoIterator<Item = Into<Value>>`.
