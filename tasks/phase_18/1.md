# Task 18.1 — Fix FK Column Naming in CREATE / INSERT (author → author_id)

## Failing Tests

```
TestCreate::test_create_with_fk
TestCreate::test_create_with_null_fk
TestCascadeDelete::test_cascade_removes_child_on_parent_instance_delete
TestCascadeDelete::test_cascade_removes_multiple_children
TestCascadeDelete::test_cascade_via_queryset_delete
TestCascadeDelete::test_delete_child_does_not_affect_parent
TestCascadeDelete::test_cascade_only_affects_related_children
TestEdgeCases::test_filter_on_null_fk
TestDelete::test_cascade_delete_removes_children
```

Error:
```
RuntimeError: Database error: error returned from database: (code: 1)
table articles has no column named author
```

## Root Cause

When the user calls:
```python
article = await Article.objects.create(title="My Post", author=author_instance)
```

Python passes `author=<Author instance>` as a keyword argument. In `create()` the
key-value pairs are collected as `(String, OrmpiValue)`. For ForeignKey fields, the
Python attribute name is `author`, but the database column name is `author_id`.

The `create_row()` function in `evaluate.rs` looks up the field by `field_name`:
```rust
let col_name = if let Some(f) = model_def.fields.get(field_name.as_str()) {
    f.column_name()   // returns "author_id" via attname
} else {
    field_name.clone()  // falls back to "author" — WRONG for FK fields
};
```

The lookup `model_def.fields.get("author")` returns `None` because the field is stored
under `"author"` as a `FieldType::ForeignKey`, but `column_name()` returns `"author_id"`.
The field IS in the map under the key `"author"`, so the lookup should succeed. BUT the
`OrmpiValue` for the field is extracted by calling `py_to_ormpi_value` on the Author
model instance, which falls back to JSON string representation (not the PK integer).

## Two Bugs

### Bug A — `py_to_ormpi_value` on a model instance returns string, not PK

When `author=author_instance` is passed to `create()`, `py_to_ormpi_value(author_instance)`
tries `bool` → `int` → `float` → `str` conversions and falls back to `str(author_instance)`
which gives `"<Author: pk=5>"` — a string, not an integer.

**Fix:** In `py_to_ormpi_value` check if the object has a `pk` attribute and use that:

```rust
// ormpi-py/src/model/instance.rs, py_to_ormpi_value
// Try model instance → extract pk value
if let Ok(pk) = obj.getattr("pk") {
    if !pk.is_none() {
        if let Ok(i) = pk.extract::<i64>() {
            return Ok(OrmpiValue::Int(i));
        }
    } else {
        return Ok(OrmpiValue::Null);  // null FK
    }
}
```

Add this check after the `bytes` check and before the JSON fallback.

### Bug B — FK field is stored in `model_def.fields` under `"author"` but INSERT needs `"author_id"`

`create_row()` correctly calls `f.column_name()` to get the DB column. So if the field
is found in the map under key `"author"`, it returns `"author_id"`. This part is correct.

The real issue is Bug A: the value is a string representation of the model instance, not
the integer PK. So even though the column name resolves correctly, the value is wrong.

Fixing Bug A alone resolves the `create()` failures.

## Fix — `ormpi-py/src/model/instance.rs`

In `py_to_ormpi_value`, add a check for model instances **before** the string fallback:

```rust
pub(crate) fn py_to_ormpi_value(obj: &Bound<'_, PyAny>) -> PyResult<OrmpiValue> {
    if obj.is_none() {
        return Ok(OrmpiValue::Null);
    }
    if let Ok(b) = obj.extract::<bool>() {
        return Ok(OrmpiValue::Bool(b));
    }
    if let Ok(i) = obj.extract::<i64>() {
        return Ok(OrmpiValue::Int(i));
    }
    if let Ok(f) = obj.extract::<f64>() {
        return Ok(OrmpiValue::Float(f));
    }
    if let Ok(s) = obj.extract::<String>() {
        return Ok(OrmpiValue::Text(s));
    }
    if let Ok(b) = obj.extract::<Vec<u8>>() {
        return Ok(OrmpiValue::Bytes(b));
    }
    // ── NEW: model instance → use pk value ────────────────────────────
    // Handles ForeignKey fields where the user passes a model instance
    // instead of a raw integer pk (e.g. create(author=author_obj)).
    if let Ok(pk_attr) = obj.getattr("pk") {
        if pk_attr.is_none() {
            return Ok(OrmpiValue::Null);
        }
        if let Ok(i) = pk_attr.extract::<i64>() {
            return Ok(OrmpiValue::Int(i));
        }
    }
    // ── Fallback: JSON string ──────────────────────────────────────────
    let json_str = obj.str()?.extract::<String>()?;
    Ok(OrmpiValue::Text(json_str))
}
```
