## Bug 1 — `filter_on_null_fk`

### Expected behaviour

```python
results = await Article.objects.filter(author__isnull=True)
assert len(results) == 1
```

### Root Cause

Cross-table lookups like `author__isnull=True` require resolving the FK field to its
column name (`author_id`) and applying `IS NULL` to that column in the WHERE clause.

`parse_filter_kwarg` in `queryset.rs` splits `author__isnull` into `["author", "isnull"]`.
When looking up the field path, if `author` is a FK field, the filter should be applied to
the column `author_id` in the current table (for IS NULL checks), not via a JOIN.

**Fix:** In `parse_filter_kwarg` (or `resolve_column`), when the last segment before
a lookup (`isnull`, `exact`) refers to a FK field name, resolve to `field.column_name()`
(`author_id`) rather than treating it as a relation traversal.

## Bug 2 — `select_related` Not Loading FK Objects

### Expected behaviour

```python
article = await Article.objects.select_related("author").get(pk=pk)
assert article.author.name == "Alice"   # FK object populated
```

### Investigation needed

Read `queryset.rs` lines around `select_related` and the `row_to_instance` function to
understand how joined rows are mapped back to nested instances.

The likely issue: after the JOIN query fetches columns like `author__name`, `author__id`,
etc., `row_to_instance` does not detect and populate a nested `Author` instance on
`article.author`.

**Fix approach:**
1. After a `select_related` fetch, group the flat row columns by prefix (`author__*`).
2. For each related field prefix, create a new model instance and populate its `_values`
   from the prefixed columns.
3. Set `article._values["author"] = populated_author_instance` (the Python instance,
   not the raw PK integer).

This requires changes in `ormpi-core/src/query/evaluate.rs` or the result-mapping layer
in `ormpi-py/src/query/queryset.rs`.

## Fix Outline

### `filter_on_null_fk`

In `ormpi-core/src/query/filter.rs` or `evaluate.rs`, the path-resolution for a field
like `author` (a FK field name) with a lookup like `isnull` should:

1. Find `author` in `model_def.fields`
2. If it is a FK field, resolve to `author_id` as the column
3. Apply the lookup to `author_id` directly (no JOIN needed for IS NULL / exact pk checks)

### `select_related`

After a JOIN query, the result rows contain flat columns like:
```
id, title, author_id, authors__id, authors__name, authors__email, ...
```

Hydration logic must:
1. Detect columns with `<prefix>__` pattern
2. Group them by prefix
3. Create a nested model instance for each prefix
4. Assign the nested instance to `article._values["author"]`

### `prefetch_related`

Ensure the separate-query fetch uses the correct FK column (`author_id` not `author`)
when matching parent rows to child rows.

## Files Changed

| File | Change |
|------|--------|
| `ormpi-core/src/query/filter.rs` or `evaluate.rs` | Resolve FK field names to column names for IS NULL / exact filters |
| `ormpi-core/src/query/evaluate.rs` or `ormpi-py/src/query/queryset.rs` | `select_related` row hydration: build nested instances from prefixed columns |
| `ormpi-py/src/query/queryset.rs` | `prefetch_related`: fix FK column reference in matching query |
