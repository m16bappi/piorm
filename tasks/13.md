# Task 13: Extract `resolve_model_def` Helper and Unify FieldDef Constructor Macros

## Problem

### Part A — Repeated model-lookup + error in `instance.rs`

The pattern of looking up a model def and mapping the `None` to a Python error appears three times in `ormpi-py/src/model/instance.rs` with slightly different error messages:

```rust
// instance.rs:save — lines 175–180
let model_def = get_model_def_by_name(&class_name).ok_or_else(|| {
    pyo3::exceptions::PyRuntimeError::new_err(format!(
        "Model '{}' is not registered — did you forget to inherit from Model?",
        class_name
    ))
})?;

// instance.rs:delete — lines 235–239
let model_def = get_model_def_by_name(&class_name).ok_or_else(|| {
    pyo3::exceptions::PyRuntimeError::new_err(format!(
        "Model '{}' is not registered",
        class_name
    ))
})?;

// instance.rs:refresh_from_db — lines 286–290
let model_def = get_model_def_by_name(&class_name).ok_or_else(|| {
    pyo3::exceptions::PyRuntimeError::new_err(format!(
        "Model '{}' is not registered",
        class_name
    ))
})?;
```

The inconsistent messages ("…did you forget to inherit from Model?" vs plain) also mean `save()` gives a better hint than `delete()`.

### Part B — `FieldDef` struct construction repeated in two macros

`impl_simple_field!` (fields/mod.rs lines 162–217) and `impl_integer_field!` (lines 222–279) both construct a `FieldDef` struct with 15 fields. The only differences are:
1. `impl_integer_field!` adds an `auto_increment` parameter and sets it from the arg
2. `impl_simple_field!` hard-codes `auto_increment: false`

// Both macros have this identical block (14/15 fields identical):
ormpi_core::fields::FieldDef {

    null,
    unique,
    db_index,
    primary_key,
    editable,
    default: crate::fields::parse_default(py, default)?,

    auto_now: false,

## Fix

### Part A — Add `resolve_model_def` helper in `instance.rs`

Replace `get_model_def_by_name` (which returns `Option<ModelDef>`) with a new `resolve_model_def` that returns `PyResult<ModelDef>` directly with a consistent, helpful error message:

```rust
/// Look up the ModelDef for a Python class name, returning a helpful PyRuntimeError if not found.
pub(crate) fn resolve_model_def(class_name: &str) -> PyResult<ormpi_core::model::def::ModelDef> {
    get_model_def_by_name(class_name).ok_or_else(|| {
        pyo3::exceptions::PyRuntimeError::new_err(format!(
            "Model '{class_name}' is not registered. \
             Ensure it inherits from Model and is imported before configure() is called."
        ))
    })
}
```

**Update `save` (lines 175–180):**
```rust
// Before:
let model_def = get_model_def_by_name(&class_name).ok_or_else(|| {
    pyo3::exceptions::PyRuntimeError::new_err(format!(
        "Model '{}' is not registered — did you forget to inherit from Model?",
        class_name
    ))
})?;
// After:
let model_def = resolve_model_def(&class_name)?;
```

**Update `delete` (lines 235–239):** same.

**Update `refresh_from_db` (lines 286–290):** same.

Keep `get_model_def_by_name` as the internal `Option`-returning helper (used by `resolve_model_def`). It may also be used in queryset.rs — check and update those call sites too.

### Part B — Unify FieldDef construction with `make_field_def!` macro in `fields/mod.rs`

Add a helper macro before `impl_simple_field!`:

```rust
/// Build a `FieldDef` with all standard fields.
/// `$auto_increment` is an expression, e.g. `false` or the `auto_increment` variable.
macro_rules! make_field_def {
    ($field_type_expr:expr, $auto_increment:expr, $py:expr, $null:expr, $default:expr,
     $unique:expr, $db_index:expr, $primary_key:expr, $editable:expr,
     $db_column:expr, $verbose_name:expr) => {
        ormpi_core::fields::FieldDef {
            name:          String::new(),
            attname:       String::new(),
            db_column:     $db_column,
            field_type:    $field_type_expr,
            null:          $null,
            unique:        $unique,
            db_index:      $db_index,
            primary_key:   $primary_key,
            editable:      $editable,
            default:       crate::fields::parse_default($py, $default)?,
            choices:       vec![],
            auto_increment: $auto_increment,
            auto_now:      false,
            auto_now_add:  false,
            max_length:    None,
            validators:    vec![],
            verbose_name:  $verbose_name,
            related_name:  None,
        }
    };
}
```

**Update `impl_simple_field!` constructor body:**
```rust
fn new(py, null, default, unique, db_index, primary_key, editable, db_column, verbose_name) -> PyResult<Self> {
    Ok(Self {
        inner: make_field_def!(
            $field_type_expr, false,
            py, null, default, unique, db_index, primary_key, editable, db_column, verbose_name
        ),
    })
}
```

**Update `impl_integer_field!` constructor body:**
```rust
fn new(py, null, default, unique, db_index, primary_key, editable, db_column, verbose_name, auto_increment) -> PyResult<Self> {
    Ok(Self {
        inner: make_field_def!(
            $field_type_expr, auto_increment,
            py, null, default, unique, db_index, primary_key, editable, db_column, verbose_name
        ),
    })
}
```

The 15-field `FieldDef { ... }` literal now appears exactly once.
