## Root Cause

`select_for_update()` is a standard ORM feature that appends `FOR UPDATE` (or `FOR UPDATE
NOWAIT` / `FOR UPDATE SKIP LOCKED`) to a `SELECT` statement. It is absent entirely from
`ormpi`. Without it, concurrent writes to the same row inside long transactions cannot be
safely serialized — the classic "lost update" problem.

Django API:
```python
# Acquires a row-level write lock; blocks until the lock is available
authors = await Author.objects.select_for_update().filter(pk=pk).all()

# Raises DatabaseError immediately if any selected row is already locked
authors = await Author.objects.select_for_update(nowait=True).filter(pk=pk).all()

# Skips locked rows instead of blocking
authors = await Author.objects.select_for_update(skip_locked=True).filter(pk=pk).all()
```

## Fix

### Step 1 — Add `ForUpdateMode` to `QueryState` (`ormpi-core/src/query/state.rs`)

```rust
/// Controls row-level locking appended to SELECT statements.
#[derive(Debug, Clone, PartialEq)]
pub enum ForUpdateMode {
    None,
    ForUpdate,         // SELECT … FOR UPDATE
    ForUpdateNoWait,   // SELECT … FOR UPDATE NOWAIT
    ForUpdateSkipLocked, // SELECT … FOR UPDATE SKIP LOCKED
}

impl Default for ForUpdateMode {
    fn default() -> Self { ForUpdateMode::None }
}
```

Add the field to `QueryState`:
```rust
pub struct QueryState {
    // ... existing fields ...
    pub for_update: ForUpdateMode,
}
```

`QueryState::new()` already derives `Default` for sub-fields; set `for_update:
ForUpdateMode::None` in the constructor.

### Step 2 — Emit `FOR UPDATE` SQL in the evaluator (`ormpi-core/src/query/evaluate.rs`)

After building the `SELECT` statement (via sea-query), append the `FOR UPDATE` clause
depending on `state.for_update`. sea-query does not natively support `FOR UPDATE` locking;
append it manually to the SQL string after rendering:

```rust
pub async fn evaluate_query(
    state: &QueryState,
    pool: &OrmpiPool,
    backend: &QueryBackend,
    model_def: &ModelDef,
) -> Result<Vec<OrmpiRow>> {
    let (mut sql, values) = build_select_sql(state, backend, model_def)?;

    // Append FOR UPDATE clause (not supported by sea-query directly).
    match &state.for_update {
        ForUpdateMode::None => {}
        ForUpdateMode::ForUpdate => sql.push_str(" FOR UPDATE"),
        ForUpdateMode::ForUpdateNoWait => {
            match pool {
                OrmpiPool::Sqlite(_) => {
                    // SQLite does not support FOR UPDATE NOWAIT — raise an error.
                    return Err(OrmpiError::TransactionError(
                        "select_for_update(nowait=True) is not supported on SQLite".into(),
                    ));
                }
                _ => sql.push_str(" FOR UPDATE NOWAIT"),
            }
        }
        ForUpdateMode::ForUpdateSkipLocked => {
            match pool {
                OrmpiPool::Sqlite(_) => {
                    return Err(OrmpiError::TransactionError(
                        "select_for_update(skip_locked=True) is not supported on SQLite".into(),
                    ));
                }
                _ => sql.push_str(" FOR UPDATE SKIP LOCKED"),
            }
        }
    }

    fetch_rows(pool, &sql, &values).await
}
```

SQLite uses `BEGIN EXCLUSIVE` / `BEGIN IMMEDIATE` for locking, not `FOR UPDATE` — raise a
clear error for unsupported modes.

### Step 3 — Add `select_for_update()` to `PyQuerySet` (`ormpi-py/src/query/queryset.rs`)

```rust
/// Lock selected rows for update (SELECT … FOR UPDATE).
///
/// Must be called within an active transaction. Options:
///   nowait=True      → FOR UPDATE NOWAIT (error if locked)
///   skip_locked=True → FOR UPDATE SKIP LOCKED (skip locked rows)
#[pyo3(signature = (nowait = false, skip_locked = false))]
fn select_for_update(
    slf: Bound<'_, Self>,
    nowait: bool,
    skip_locked: bool,
) -> PyResult<PyObject> {
    let py = slf.py();
    let mut state = slf.borrow().state.clone();
    let model_class = clone_model_class(py, &slf.borrow().model_class);
    let transaction_arc = slf.borrow().transaction_arc.clone();

    use ormpi_core::query::state::ForUpdateMode;
    state.for_update = if nowait {
        ForUpdateMode::ForUpdateNoWait
    } else if skip_locked {
        ForUpdateMode::ForUpdateSkipLocked
    } else {
        ForUpdateMode::ForUpdate
    };

    Ok(Py::new(py, PyQuerySet { state, model_class, transaction_arc })?.into_py(py))
}
```

Propagate `for_update` through all chainable methods (filter, exclude, order_by, etc.)
because `QueryState` is already cloned in each — no additional changes needed there.

### Step 4 — Validate that `select_for_update()` is called inside a transaction

Django raises `TransactionManagementError` if `select_for_update()` is called outside a
transaction. Add the same guard in the evaluate path:

```rust
// In evaluate_query, before emitting FOR UPDATE:
if state.for_update != ForUpdateMode::None && txn_arc.is_none() {
    return Err(OrmpiError::TransactionError(
        "select_for_update() cannot be used outside of a transaction. \
         Wrap your query in atomic() or pass a transaction via using_transaction().".into(),
    ));
}
```

The evaluate function receives `Option<TxnArc>` from the queryset; the guard checks it.

### Step 5 — Register `ForUpdateMode` in `QueryState` clone

`QueryState` derives `Clone` — `ForUpdateMode` must also derive `Clone` (already specified
in Step 1).

## New Tests to Add (`__tests__/crud/test_transaction.py`)

```python
class TestSelectForUpdate:

    @pytest.mark.asyncio
    async def test_select_for_update_basic(self):
        """select_for_update() returns rows and holds a write lock inside a transaction."""
        author = await Author.objects.create(name="Alice", email="alice@test.com")

        async with atomic() as txn:
            locked = await (
                Author.objects
                .using_transaction(txn)
                .select_for_update()
                .filter(pk=author.pk)
            )
            assert len(locked) == 1
            assert locked[0].name == "Alice"

    @pytest.mark.asyncio
    async def test_select_for_update_outside_transaction_raises(self):
        """select_for_update() outside a transaction raises TransactionManagementError."""
        await Author.objects.create(name="Alice", email="alice@test.com")

        with pytest.raises(RuntimeError, match="outside of a transaction"):
            await Author.objects.select_for_update().filter(name="Alice")

    @pytest.mark.asyncio
    async def test_select_for_update_updates_visible_in_same_txn(self):
        """Rows locked with select_for_update() can be updated within the same txn."""
        author = await Author.objects.create(name="Alice", email="alice@test.com")

        async with atomic() as txn:
            qs = Author.objects.using_transaction(txn)
            await qs.select_for_update().filter(pk=author.pk)
            await qs.filter(pk=author.pk).update(name="Alice-Locked")

        refreshed = await Author.objects.get(pk=author.pk)
        assert refreshed.name == "Alice-Locked"
```
