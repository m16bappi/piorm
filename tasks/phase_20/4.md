## Bug 1 — Savepoint Name Collision (Non-deterministic Race Condition)

### Root Cause

`create_savepoint` in `ormpi-py/src/lib.rs` derives savepoint names from subsecond
nanoseconds:

```rust
let nanos = SystemTime::now()
    .duration_since(UNIX_EPOCH)
    .map(|d| d.subsec_nanos())
    .unwrap_or(0);
let sp_name = format!("sp_{:08x}", nanos);
```

`subsec_nanos()` cycles from 0 to 999_999_999 every second. Two savepoints created within
the same nanosecond (easily triggered in unit tests running on fast machines) produce
identical names, causing the database to error with "SAVEPOINT already exists".

### Fix — Global Atomic Counter (`ormpi-py/src/lib.rs`)

Replace wall-clock nanos with a process-wide monotonically increasing counter:

```rust
use std::sync::atomic::{AtomicU64, Ordering};

static SAVEPOINT_COUNTER: AtomicU64 = AtomicU64::new(1);

#[pyfunction]
fn create_savepoint(py: Python<'_>, txn: &transaction::PyTransaction) -> PyResult<PyObject> {
    let sp_id = SAVEPOINT_COUNTER.fetch_add(1, Ordering::Relaxed);
    let sp_name = format!("sp_{sp_id}");
    let sql = format!("SAVEPOINT {sp_name}");
    let arc = txn.inner_arc();

    let future = async move {
        let mut guard = arc.lock().await;
        let inner = guard.as_mut().ok_or_else(|| {
            pyo3::exceptions::PyRuntimeError::new_err("Transaction already consumed")
        })?;
        inner.execute_raw(&sql, &[]).await.map_err(ormpi_err)?;
        Ok(sp_name)
    };
    pyo3_async_runtimes::tokio::future_into_py(py, future).map(|b| b.into())
}
```

Counter starts at 1. Wraps around at u64::MAX (18 quintillion increments) — effectively
never in practice.

## Bug 2 — `_transaction_local.py` Memory Leak on Task Cancellation

### Root Cause

`_CURRENT` maps `id(task) → {alias: Transaction}`. The entry is removed only when
`_clear_current_transaction()` is explicitly called (which `atomic().__aexit__` does on
clean commit/rollback). If a task is cancelled or crashes before `__aexit__` runs, the
entry is never removed.

Worse: Python reuses integer task IDs after a task is garbage-collected, so a stale entry
for a completed task can be mistakenly read by a new task that happens to get the same ID.

### Fix — Register `done_callback` in `_set_current_transaction()` (`python/ormpi/_transaction_local.py`)

```python
def _set_current_transaction(using: str, txn: Any) -> None:
    task = asyncio.current_task()
    if task is None:
        return
    task_id = id(task)
    _CURRENT.setdefault(task_id, {})[using] = txn

    # Register a cleanup callback so the entry is removed when the task finishes,
    # even if atomic().__aexit__ is never reached (cancellation / uncaught exception).
    def _cleanup(_task):
        _CURRENT.pop(task_id, None)

    task.add_done_callback(_cleanup)
```

`add_done_callback` is called multiple times (once per `atomic()` nesting level) but
Python's asyncio de-duplicates callbacks, so `_cleanup` runs exactly once when the task
terminates. The full `{alias: ...}` dict is removed at once, which is correct because the
outermost transaction owns the lifecycle.

## Feature — `transaction.on_commit(callback, using="default")`

### Description

Django provides a module-level `on_commit` function that registers a callback on the
currently active transaction for the given database alias. This is more ergonomic than
calling `txn.on_commit(cb)` when the transaction object is not directly in scope.

```python
from ormpi.transaction import on_commit

async def notify():
    print("committed!")

async with atomic():
    await Author.objects.create(...)
    on_commit(notify)   # fires after the atomic block exits cleanly
```

### Fix — `ormpi-py/src/lib.rs` + `python/ormpi/transaction.py`

#### Step 1 — Expose `py_on_commit` from Rust (`ormpi-py/src/lib.rs`)

Add a new `#[pyfunction]` that:
1. Reads the current task-local transaction via `_get_current_transaction(using)`.
2. Calls `txn.on_commit(callback)` on it.
3. Raises `RuntimeError` if no transaction is active.

```rust
/// on_commit(callback, using="default") — register a zero-arg callable to fire
/// after the currently active transaction commits.
#[pyfunction]
#[pyo3(signature = (callback, using = "default"))]
fn on_commit(py: Python<'_>, callback: Py<PyAny>, using: &str) -> PyResult<()> {
    let txn_local = py.import_bound("ormpi._transaction_local")?;
    let get_fn = txn_local.getattr("_get_current_transaction")?;
    let current_txn = get_fn.call1((using,))?;

    if current_txn.is_none() {
        return Err(pyo3::exceptions::PyRuntimeError::new_err(
            "on_commit() called outside of an atomic block. \
             No active transaction for the given database alias.",
        ));
    }

    // Delegate to PyTransaction.on_commit(callback).
    current_txn.call_method1("on_commit", (callback,))?;
    Ok(())
}
```

Register in the `_core` module:
```rust
m.add_function(wrap_pyfunction!(on_commit, m)?)?;
```

#### Step 2 — Re-export from `python/ormpi/transaction.py`

```python
from ormpi._core import on_commit as on_commit

__all__ = ["atomic", "begin", "on_commit", "Transaction"]
```

## New Tests to Add (`__tests__/crud/test_transaction.py`)

```python
class TestOnCommit:

    @pytest.mark.asyncio
    async def test_on_commit_fires_after_atomic_block(self):
        from ormpi.transaction import on_commit
        fired = []

        async with atomic():
            await Author.objects.create(name="Alice", email="alice@test.com")
            on_commit(lambda: fired.append(True))

        assert fired == [True]

    @pytest.mark.asyncio
    async def test_on_commit_not_fired_on_rollback(self):
        from ormpi.transaction import on_commit
        fired = []

        with pytest.raises(RuntimeError):
            async with atomic():
                await Author.objects.create(name="Alice", email="alice@test.com")
                on_commit(lambda: fired.append(True))
                raise RuntimeError("abort")

        assert fired == []

    @pytest.mark.asyncio
    async def test_on_commit_fires_once_per_registration(self):
        from ormpi.transaction import on_commit
        count = []

        async with atomic():
            on_commit(lambda: count.append(1))
            on_commit(lambda: count.append(2))

        assert count == [1, 2]

    @pytest.mark.asyncio
    async def test_on_commit_outside_transaction_raises(self):
        from ormpi.transaction import on_commit
        with pytest.raises(RuntimeError, match="outside of an atomic block"):
            on_commit(lambda: None)
```
