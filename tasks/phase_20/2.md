# Task 20.2 — `Transaction.execute_raw()` Parameterized Query Support

## Failing Tests

```
TestUsingTransaction::test_execute_raw_inside_transaction
TestUsingTransaction::test_execute_raw_rolled_back_with_transaction
```

## Error

```
TypeError: execute_raw() takes 1 positional argument but 2 were given
```

## Root Cause

The test calls `execute_raw` with a parameter list:

```python
await txn.execute_raw(
    "INSERT INTO authors (name, email, active) VALUES (?, ?, ?)",
    ["Raw Alice", "raw@test.com", 1],
)
```

But the current `PyTransaction::execute_raw` signature only accepts SQL:

```rust
// ormpi-py/src/transaction.rs — CURRENT (broken)
fn execute_raw<'py>(&self, py: Python<'py>, sql: String) -> PyResult<PyObject>
```

And the underlying core function:

```rust
// ormpi-core/src/transaction.rs — CURRENT (broken)
pub async fn execute_raw(&mut self, sql: &str) -> crate::Result<()>
```

Neither layer accepts bind parameters.

## Fix

### Step 1 — Extend `OrmpiTransaction::execute_raw` in `ormpi-core/src/transaction.rs`

Add a `params: &[OrmpiValue]` slice argument and bind each parameter to the query.

```rust
use crate::value::OrmpiValue;

pub async fn execute_raw(&mut self, sql: &str, params: &[OrmpiValue]) -> crate::Result<()> {
    use std::ops::DerefMut;
    use sqlx::query::Query;

    match &mut self.handle {
        TransactionHandle::Sqlite(t) => {
            let mut q: sqlx::query::Query<sqlx::Sqlite, _> = sqlx::query(sql);
            for p in params {
                q = bind_ormpi_value_sqlite(q, p);
            }
            q.execute(t.as_mut().deref_mut()).await?;
        }
        TransactionHandle::Mysql(t) => {
            let mut q = sqlx::query(sql);
            for p in params {
                q = bind_ormpi_value_mysql(q, p);
            }
            q.execute(t.as_mut().deref_mut()).await?;
        }
        TransactionHandle::Postgres(t) => {
            let mut q = sqlx::query(sql);
            for p in params {
                q = bind_ormpi_value_postgres(q, p);
            }
            q.execute(t.as_mut().deref_mut()).await?;
        }
    }
    Ok(())
}
```

The `bind_ormpi_value_*` helpers convert each `OrmpiValue` variant to the matching sqlx
bind type. Check if these helpers already exist in `ormpi-core/src/query/evaluate.rs` or
`ormpi-core/src/executor.rs` — reuse them rather than duplicating.

The existing savepoint callers (`execute_raw(&sql)`) must be updated to pass an empty slice:
`execute_raw(&sql, &[])`.

### Step 2 — Extend `PyTransaction::execute_raw` in `ormpi-py/src/transaction.rs`

Add an optional `params: Option<Vec<PyObject>>` argument. Convert Python objects to
`OrmpiValue` using `crate::model::instance::py_to_ormpi_value` (same helper used by the
rest of the codebase).

```rust
fn execute_raw<'py>(
    &self,
    py: Python<'py>,
    sql: String,
    params: Option<Vec<PyObject>>,
) -> PyResult<PyObject> {
    let arc = Arc::clone(&self.inner);

    // Convert params to OrmpiValue while the GIL is held.
    let ormpi_params: Vec<ormpi_core::value::OrmpiValue> = params
        .unwrap_or_default()
        .iter()
        .map(|p| crate::model::instance::py_to_ormpi_value(p.bind(py)))
        .collect::<PyResult<_>>()?;

    let future = async move {
        let mut guard = arc.lock().await;
        let txn = guard.as_mut().ok_or_else(|| {
            pyo3::exceptions::PyRuntimeError::new_err("Transaction already consumed")
        })?;
        txn.execute_raw(&sql, &ormpi_params).await.map_err(ormpi_err)?;
        Python::with_gil(|py| Ok::<_, PyErr>(py.None()))
    };

    pyo3_async_runtimes::tokio::future_into_py(py, future).map(|b| b.into())
}
```

The signature change is backward-compatible because `params` is `Option<Vec<PyObject>>`
with a default of `None` — existing callers using `txn.execute_raw(sql)` continue to work.

### Step 3 — Update savepoint callers in `ormpi-py/src/lib.rs`

`create_savepoint`, `release_savepoint`, and `rollback_to_savepoint` all call
`inner.execute_raw(&sql)`. Update each to `inner.execute_raw(&sql, &[])`.

## Files Changed

| File | Change |
|------|--------|
| `ormpi-core/src/transaction.rs` | `execute_raw`: add `params: &[OrmpiValue]` arg; bind params per backend |
| `ormpi-py/src/transaction.rs` | `PyTransaction::execute_raw`: add optional `params: Option<Vec<PyObject>>` |
| `ormpi-py/src/lib.rs` | `create_savepoint`, `release_savepoint`, `rollback_to_savepoint`: pass `&[]` to `execute_raw` |

## Acceptance Criteria

- [ ] `await txn.execute_raw(sql, [param1, param2, ...])` inserts a row inside the transaction
- [ ] The inserted row is visible within the same transaction (`using_transaction(txn).count() == 1`)
- [ ] Rolling back the transaction after `execute_raw` discards the row (count returns to 0)
- [ ] `await txn.execute_raw(sql)` (no params) still works — backward compatible
- [ ] `await txn.execute_raw(sql, None)` (explicit None) still works
- [ ] Both listed tests pass
