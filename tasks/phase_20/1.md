## Root Cause

`async with atomic() as txn:` stores the active transaction in `_transaction_local` (keyed by
asyncio task ID + database alias), but `PyQuerySet` is only transaction-aware when
`.using_transaction(txn)` is called explicitly. Without that call, every queryset operation
acquires a fresh pool connection in **autocommit mode** — completely bypassing the open transaction.

So:
```python
async with atomic():
    await Author.objects.create(...)   # <-- autocommit, NOT in the transaction
    raise ValueError("abort")
# rollback fires on the empty transaction; the create was already committed
```

The task-local store (`_CURRENT` dict in `_transaction_local.py`) is populated but never
consulted by the Rust `PyManager` when it builds a new `PyQuerySet`.

## Fix — `ormpi-py/src/model/base.rs`

### Step 1 — Auto-bind in `PyManager::get_queryset()`

`get_queryset()` is the single factory used by every Manager method (`all`, `filter`,
`create`, `get`, `count`, `exists`, `bulk_create`, `bulk_update`, `aggregate`, etc.).
Inject the current task-local transaction here so all operations automatically participate.

```rust
fn get_queryset(&self, py: Python<'_>) -> PyResult<PyObject> {
    let qs = crate::query::queryset::PyQuerySet::new_with_class(
        self.app_label.clone(),
        self.model_name.clone(),
        self.model_class.clone_ref(py),
    );
    let qs_obj = Py::new(py, qs)?.into_py(py);

    // Auto-bind the current task-local transaction if one is active.
    // Import _get_current_transaction from ormpi._transaction_local.
    let alias = "default"; // TODO: derive from routing when multi-db is wired
    let txn_local = py.import_bound("ormpi._transaction_local")?;
    let get_fn = txn_local.getattr("_get_current_transaction")?;
    let current_txn = get_fn.call1((alias,))?;

    if !current_txn.is_none() {
        // Check is_open before binding.
        let is_open: bool = current_txn.getattr("is_open")?.extract()?;
        if is_open {
            // current_txn is a PyTransaction; call qs.using_transaction(txn)
            let qs_bound = qs_obj.bind(py);
            let bound_qs = qs_bound.call_method1("using_transaction", (&current_txn,))?;
            return Ok(bound_qs.into());
        }
    }

    Ok(qs_obj)
}
```

This is a pure Rust change. The GIL is already held when `get_queryset` is called (it's a
`#[pymethods]` method), so `py.import_bound(...)` is safe and synchronous.

### Step 2 — Derive alias from QueryState

The `app_label` and `model_name` are available; the database alias is stored in
`QueryState::database` (defaults to `"default"`). Expose it via `PyManager::_db_alias()` or
read from the routing layer.

For the initial implementation, hard-code `"default"`. Multi-db routing auto-binding is a
follow-up task.

### Step 3 — Propagation through chained queryset methods

No change needed. Every chainable method in `PyQuerySet` (filter, exclude, order_by,
values, only, defer, distinct, using) already clones `transaction_arc` into the returned
queryset. Once `get_queryset()` returns a transaction-bound queryset, all chained calls
automatically preserve the binding.

### Step 4 — Model instance `.save()` and `.delete()`

Instance-level `save()` and `delete()` call back into the Manager/QuerySet. They will
automatically pick up the transaction because they go through the Manager's `get_queryset()`
or an equivalent path. Verify after Step 1 is implemented.
