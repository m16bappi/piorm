# Task 13.4 — QuerySet Evaluated Protocol (`__await__` → `QuerySet[M]`)

## Problem

`QuerySet.__await__` currently resolves to `list[M]`:

```python
def __await__(self) -> Generator[Any, None, list[M]]: ...
```

This collapses the type irreversibly: once you `await`, you get a `list` — no more chaining.

```python
results = await Author.objects.exclude(age__lt=30)
# results: list[Author]

results.filter(name="Alice")   # ✗  AttributeError — list has no .filter()
results.order_by("name")       # ✗
len(results)                   # ✓  list supports len()
for r in results: ...          # ✓  list supports iteration
```

The test pattern the user writes naturally is:

```python
results = await Author.objects.exclude(age__lt=30)
assert len(results) == 2
assert all(r.age >= 30 for r in results)

# And then in another line — chain further:
active = await results.filter(active=True)
```

This should all work with a single `results` variable. The fix is to make `await qs`
return `QuerySet[M]` itself (the evaluated/cached queryset), and add the synchronous
collection protocol (`__iter__`, `__len__`, `__bool__`, `__contains__`) to `QuerySet`
so it behaves like a list after evaluation.

---

## Design

### `__await__` returns `QuerySet[M]`, not `list[M]`

```
BEFORE:  def __await__(self) -> Generator[Any, None, list[M]]: ...
AFTER:   def __await__(self) -> Generator[Any, None, QuerySet[M]]: ...
```

`await qs` still resolves asynchronously (hits the DB) — the runtime behaviour is
unchanged. The type checker now sees the result as `QuerySet[M]`, which retains all
chaining methods AND can be iterated / measured synchronously.

### Synchronous collection protocol on `QuerySet[M]`

After `await`, the queryset holds its fetched rows in an internal cache. These methods
expose that cache synchronously:

| Method | Returns | Usage |
|--------|---------|-------|
| `__iter__` | `Iterator[M]` | `for r in results:` |
| `__len__` | `int` | `len(results)` |
| `__bool__` | `bool` | `if results:` / `assert results` |
| `__contains__` | `bool` | `author in results` |
| `__reversed__` | `Iterator[M]` | `reversed(results)` |

These methods are only valid on an **evaluated** queryset (one that has been awaited
or fully iterated via `async for`). Calling them on an unevaluated queryset raises
`RuntimeError` at runtime — but the type stub doesn't distinguish the two states, so
the type checker accepts them unconditionally (same trade-off as Django's synchronous
queryset API).

### Two usage patterns — both now typed correctly

```python
# ── Pattern 1: chain first, then await ───────────────────────────────────
qs = Author.objects.filter(active=True)     # QuerySet[Author]
qs = qs.order_by("name")                   # QuerySet[Author]
qs = qs.exclude(age__lt=18)                # QuerySet[Author]
results = await qs                         # QuerySet[Author]  ← was list[Author]

assert len(results) == 5                   # __len__   ✓
assert all(r.active for r in results)      # __iter__  ✓
assert Author(name="Alice") in results     # __contains__ ✓

# ── Pattern 2: await, then chain further ─────────────────────────────────
results = await Author.objects.exclude(age__lt=30)   # QuerySet[Author]
active  = await results.filter(active=True)          # QuerySet[Author]  ✓
assert len(active) <= len(results)                   # both support len() ✓
```

### `__getitem__` — dual overloads unchanged, but context clearer

```python
# int index: async (DB fetch by offset)
author = await qs[0]          # Coroutine[Any, Any, Author] → Author

# slice: synchronous, produces a new QuerySet with LIMIT/OFFSET applied
page = qs[10:20]              # QuerySet[Author]
```

These overloads remain as-is. The `int` path returns `Coroutine[Any, Any, M]` because
a random-access index lookup hits the DB. After `await qs` (evaluation), `results[0]`
still returns `Coroutine[Any, Any, M]` in the type system — for sync post-evaluation
access users should iterate with `for r in results` or index via `list(results)[0]`.

    Awaiting a ``QuerySet`` fetches all rows and returns the **same**

    This means the result is both inspectable synchronously and still
    chainable for further filtering.

        # Await → QuerySet (chain-able, len-able, iterable)

        assert all(r.active for r in results)
        narrowed = await results.filter(age__gte=18)

        # Async iteration (no intermediate list)
        async for author in Author.objects.order_by("name"):
            print(author.name)

        # Chain, then await
        qs = Author.objects.filter(active=True).order_by("-created_at")[:20]
        page = await qs   # QuerySet[Author]
    """

    # ── Filtering ─────────────────────────────────────────────────────────

    def exclude(self, *args: Q, **kwargs: Any) -> QuerySet[M]: ...
    def all(self) -> QuerySet[M]: ...
    def none(self) -> QuerySet[M]: ...

    @overload
    def __getitem__(self, key: int) -> Coroutine[Any, Any, M]: ...

    def __getitem__(self, key: slice) -> QuerySet[M]: ...

    # ── Terminal async ────────────────────────────────────────────────────
    def get(self, *args: Q, **kwargs: Any) -> Coroutine[Any, Any, M]: ...
    def create(self, **kwargs: Any) -> Coroutine[Any, Any, M]: ...
    def get_or_create(

        **kwargs: Any,

    def update_or_create(

        **kwargs: Any,
    ) -> Coroutine[Any, Any, tuple[M, bool]]: ...
    def update(self, **kwargs: Any) -> Coroutine[Any, Any, int]: ...
    def delete(self) -> Coroutine[Any, Any, tuple[int, dict[str, int]]]: ...
    def count(self) -> Coroutine[Any, Any, int]: ...
    def exists(self) -> Coroutine[Any, Any, bool]: ...

## Why not `list[M]`?

`list[M]` was chosen in Task 13.3 because it maps to the obvious Python mental model —
"awaiting gives you a list". The problem is that `list` is a concrete built-in with no
`.filter()`, `.exclude()`, `.order_by()`, etc. Once the type collapses to `list[M]` it
is irreversible: the query API is gone.

`QuerySet[M]` as the awaited type makes the post-await value a first-class citizen:

| Operation | `list[M]` (old) | `QuerySet[M]` (new) |
|-----------|----------------|---------------------|
| `len(results)` | ✓ | ✓ |
| `for r in results` | ✓ | ✓ |
| `if results` | ✓ | ✓ |
| `r in results` | ✓ | ✓ |
| `results.filter(...)` | ✗ | ✓ |
| `results.order_by(...)` | ✗ | ✓ |
| `await results.get(pk=1)` | ✗ | ✓ |
| `results[0:5]` (new QuerySet) | ✗ | ✓ |

The `list`-specific methods that `QuerySet` does NOT have (`.append()`, `.pop()`,
`.sort()`, `.extend()`, `.remove()`, `.index()`) are intentionally absent — the
queryset is read-only.
