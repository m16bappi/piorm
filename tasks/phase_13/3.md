# Task 13.3 — QuerySet, Manager & Expression Typing Fixes

## Objective

Fix every typing gap in `_core.pyi` (QuerySet, Manager) and `expr.pyi` (F, _FExpr, Q,
Aggregate). Six concrete problems are addressed:

| # | Problem | File(s) |
|---|---------|---------|
| A | `Q` and `Aggregate` defined in both `_core.pyi` and `expr.pyi` — type checkers see two unrelated `Q` classes, so `expr.Q` cannot be passed where `_core.Q` is expected | `_core.pyi`, `expr.pyi` |
| B | `QuerySet.__await__` returns `Any` — `await qs` infers `Any` instead of `list[M]` | `_core.pyi` |
| C | `values_list(flat=True)` vs `flat=False` not distinguished — both infer `QuerySet[Any]` | `_core.pyi` |
| D | `Manager` is missing ~12 methods that `QuerySet` has | `_core.pyi` |
| E | `_FExpr` missing all reverse and unary operators; `lhs`/`rhs` typed as `Any` | `expr.pyi` |
| F | `Aggregate` only accepts `field: str` — rejects `Count(F("pk"))` | `expr.pyi` |

---

## Problem A — Q / Aggregate duplication

After Phase 12, the canonical source for `Q`, `Aggregate`, and aggregate subclasses is
`ormpi.expr`. Users do `from ormpi.expr import Q`. But `QuerySet.filter(*args: Q)` in
`_core.pyi` references the `Q` defined in `_core.pyi` — a **different class** from
`expr.Q` in the type-checker's view.

The symptom: pyright reports an error like:
```
Argument of type "Q" cannot be assigned to parameter "*args" of type "Q"
```
because `ormpi.expr.Q` ≠ `ormpi._core.Q`.

**Fix**: Remove the `Q` and `Aggregate*` definitions from `_core.pyi` and replace them
with re-exports from `expr.pyi`, exactly as fields were handled in Task 13.2.

## Problem B — `QuerySet.__await__`

The current `def __await__(self) -> Any` allows `await qs` but makes the result `Any`.
The correct protocol for a coroutine/awaitable is:

```python
from collections.abc import Generator

def __await__(self) -> Generator[Any, None, list[M]]: ...
```

`Generator[YieldType, SendType, ReturnType]` where `ReturnType` is what the `await`
expression evaluates to. So `await Author.objects.filter(age__gt=25)` becomes `list[Author]`.

## Problem C — `values_list` flat overloads

```python
# Current — both paths return QuerySet[Any]
def values_list(self, *fields: str, flat: bool = False) -> QuerySet[Any]: ...

# Should be:
@overload
def values_list(self, *fields: str, flat: Literal[True]) -> QuerySet[Any]: ...
@overload
def values_list(self, *fields: str, flat: Literal[False] = ...) -> QuerySet[tuple[Any, ...]]: ...
@overload
def values_list(self, *fields: str, flat: bool = ...) -> QuerySet[tuple[Any, ...]] | QuerySet[Any]: ...
```

With `flat=False` (or omitted), each row is a `tuple[Any, ...]`. With `flat=True`, each
row is a single scalar `Any`.

## Problem E — `_FExpr` incomplete operators

`expr.pyi` defines `_FExpr` with only `__add__`, `__sub__`, `__mul__`. The `expr.py`
implementation has all arithmetic operators. The stub must match:

Missing: `__radd__`, `__rsub__`, `__rmul__`, `__truediv__`, `__rtruediv__`,
`__mod__`, `__rmod__`, `__neg__`, `__pos__`

Also, `lhs: Any` and `rhs: Any` should be typed as `F | _FExpr | int | float | str | None`
so type checkers understand what operands are valid.

## Problem F — `Aggregate` rejects `F` expressions

```python
# Current
class Aggregate:
    def __init__(self, field: str, ...) -> None: ...

# Should be — F expression is valid: Count(F("distinct_col"))
class Aggregate:
    def __init__(self, field: str | F, ...) -> None: ...
```

```python
# python/ormpi/expr.pyi
# Public stubs for ormpi query expressions.
# Python 3.12+ only — no "from __future__ import annotations".

from typing import Any, Self

# ── Operand type alias ────────────────────────────────────────────────────
# Used to type __init__ of _FExpr and the attribute types.

type _Operand = F | _FExpr | int | float | str | bytes | None

# ── _FExpr — internal binary expression node ──────────────────────────────

class _FExpr:
    """Internal: a binary (or unary) arithmetic expression built from F objects.

    Not part of the public API — returned by F arithmetic operators.
    Supports further chaining: ``F("x") + 1 + 2``.
    """
    lhs: _Operand
    op:  str
    rhs: _Operand

    def __init__(self, lhs: _Operand, op: str, rhs: _Operand) -> None: ...
    def __repr__(self) -> str: ...

    # Forward operators (self op other)
    def __add__(self,      other: _Operand) -> _FExpr: ...
    def __sub__(self,      other: _Operand) -> _FExpr: ...
    def __mul__(self,      other: _Operand) -> _FExpr: ...
    def __truediv__(self,  other: _Operand) -> _FExpr: ...
    def __mod__(self,      other: _Operand) -> _FExpr: ...
    def __pow__(self,      other: _Operand) -> _FExpr: ...

    # Reverse operators (other op self)
    def __radd__(self,     other: _Operand) -> _FExpr: ...
    def __rsub__(self,     other: _Operand) -> _FExpr: ...
    def __rmul__(self,     other: _Operand) -> _FExpr: ...
    def __rtruediv__(self, other: _Operand) -> _FExpr: ...
    def __rmod__(self,     other: _Operand) -> _FExpr: ...

    # Unary
    def __neg__(self) -> _FExpr: ...
    def __pos__(self) -> _FExpr: ...
    def __abs__(self) -> _FExpr: ...

# ── F — field reference ───────────────────────────────────────────────────

class F:
    """Reference to a model field for use in expressions and updates.

    Examples::

        # Atomic increment
        await Post.objects.filter(pk=1).update(views=F("views") + 1)

        # Expression in annotation
        await Order.objects.annotate(profit=F("revenue") - F("cost"))

        # Negation
        await Score.objects.annotate(deficit=-(F("target") - F("actual")))
    """
    name: str

    def __init__(self, name: str) -> None: ...
    def __repr__(self) -> str: ...

    # Forward operators
    def __add__(self,      other: _Operand) -> _FExpr: ...
    def __sub__(self,      other: _Operand) -> _FExpr: ...
    def __mul__(self,      other: _Operand) -> _FExpr: ...
    def __truediv__(self,  other: _Operand) -> _FExpr: ...
    def __mod__(self,      other: _Operand) -> _FExpr: ...
    def __pow__(self,      other: _Operand) -> _FExpr: ...

    # Reverse operators (left operand is a plain number/string)
    def __radd__(self,     other: _Operand) -> _FExpr: ...
    def __rsub__(self,     other: _Operand) -> _FExpr: ...
    def __rmul__(self,     other: _Operand) -> _FExpr: ...
    def __rtruediv__(self, other: _Operand) -> _FExpr: ...
    def __rmod__(self,     other: _Operand) -> _FExpr: ...

    # Unary
    def __neg__(self) -> _FExpr: ...
    def __pos__(self) -> _FExpr: ...
    def __abs__(self) -> _FExpr: ...

# ── Q — filter combinator ─────────────────────────────────────────────────

class Q:
    """Filter condition combinator supporting ``&``, ``|``, ``~``.

    Examples::

        Q(name="Alice") | Q(name="Bob")
        ~Q(active=False)
        Q(age__gte=18) & Q(country="US")

    ``Q`` objects can be passed as positional arguments to ``filter``/``exclude``,
    or combined before passing::

        Author.objects.filter(Q(name="Alice") | Q(name="Bob"))
    """
    def __init__(self, **kwargs: Any) -> None: ...

    def __and__(self,    other: Q) -> Q: ...
    def __or__(self,     other: Q) -> Q: ...
    def __invert__(self)          -> Q: ...
    def __rand__(self,   other: Q) -> Q: ...
    def __ror__(self,    other: Q) -> Q: ...
    def __repr__(self)             -> str: ...

# ── Aggregate functions ───────────────────────────────────────────────────

class Aggregate:
    """Base class for all SQL aggregate functions.

    Args:
        field: The field name (string) or an ``F`` expression to aggregate.
               Examples: ``Count("id")``, ``Sum(F("revenue"))``.
        distinct: When ``True``, only count/sum distinct values.
        filter: An optional ``Q`` filter applied before aggregating.
        output_field: Optional field instance specifying the result type.
    """
    def __init__(
        self,
        field: str | F,
        *,
        distinct: bool = False,
        filter: Q | None = None,
        output_field: Any = None,
    ) -> None: ...

class Count(Aggregate):
    """SQL COUNT aggregate.  Returns an ``int``.

    Example::

        result = await Author.objects.aggregate(total=Count("id"))
        result["total"]   # int
    """
    ...

class Sum(Aggregate):
    """SQL SUM aggregate."""
    ...

class Avg(Aggregate):
    """SQL AVG aggregate."""
    ...

class Max(Aggregate):
    """SQL MAX aggregate."""
    ...

class Min(Aggregate):
    """SQL MIN aggregate."""
    ...
```

## Circular import guard

`_core.pyi` now imports from `expr.pyi`, and `expr.pyi` imports nothing from `_core.pyi`.
`fields.pyi` imports nothing from `_core.pyi` or `expr.pyi`.
The import graph is a DAG with no cycles:

```
models.pyi  →  _core.pyi  →  expr.pyi   (Q, F, Aggregate)
                           →  fields.pyi (Field, CharField, …)
```

`expr.pyi` is the leaf — it has no ormpi imports. This is intentional.

## Design notes

### Why `__await__` returns `Generator[Any, None, list[M]]`

The `Generator` protocol is how Python's `__await__` works under the hood. The three
parameters are `YieldType` (irrelevant for consumer code, always `Any`), `SendType`
(always `None`), and `ReturnType` (the value of `await expr` — here `list[M]`).

Type checkers understand that `result = await qs` produces `list[M]` when `__await__`
is declared this way.

### Why `Manager` duplicates `QuerySet` methods

`Manager` is a different class than `QuerySet` — it doesn't inherit from it. The public
surface is duplicated in the stub to give precise types. Both classes map to Rust
implementations that share internal logic but have separate Python-level type surfaces.

### Why `**kwargs: Any` stays on `filter`/`exclude`

ORM lookup kwargs (e.g., `name__icontains="alice"`, `age__gte=25`) are field-name-based
strings combined with lookup types at runtime. There is no Python typing construct that
can validate these without a type-checker plugin or code generation. `**kwargs: Any` is
the accepted pattern (used by Django stubs, SQLAlchemy, etc.) for this scenario.
