# Task 11.2 — Simplify Auto Primary Key (Remove AutoField Classes)

## Objective

Replace the three `AutoField` / `BigAutoField` / `SmallAutoField` PyO3 classes with a single
`auto_increment: bool` keyword argument on `IntegerField` and `BigIntegerField`.
The model registry's implicit PK injection should use `BigIntegerField(primary_key=True,
auto_increment=True)` instead of `BigAutoField()`.

## Rationale

`AutoField` is a Django-ism that exists because Django's field system predates common
integer-field conventions. In ormpi, a primary key column is just an integer column with
`primary_key=True` and `auto_increment=True`. There is no need for a separate class.
The user API becomes cleaner:

```python
# Old — Django-style
class Post(Model):
    id = BigAutoField(primary_key=True)   # redundant class

# New — explicit and obvious
class Post(Model):
    id = BigIntegerField(primary_key=True, auto_increment=True)

# Or just omit id entirely — ormpi injects the same thing automatically
class Post(Model):
    title = CharField(max_length=200)
```

### `to_column_def()` — Backend-Aware Auto-Increment DDL

```rust
impl FieldDef {
    pub fn to_column_def(&self, backend: DatabaseBackend) -> ColumnDef {
        let col_name = Alias::new(self.db_column());
        let mut col = ColumnDef::new(col_name);

        match &self.field_type {
            FieldType::Integer => {
                if self.auto_increment {
                    match backend {
                        DatabaseBackend::Sqlite   => col.integer(),
                        DatabaseBackend::Mysql    => col.integer(),
                        DatabaseBackend::Postgres => col.integer(),  // overridden below
                    };
                } else {
                    col.integer();
                }
            }
            FieldType::BigInteger => {
                match backend {
                    DatabaseBackend::Postgres if self.auto_increment => {
                        // Postgres: use BIGSERIAL (sea-query ColumnType::BigInteger + auto_increment)
                        col.big_integer();
                    }
                    _ => { col.big_integer(); }
                }
            }
            // ... other types unchanged
            _ => { /* handled elsewhere */ }
        }

        if self.primary_key   { col.primary_key(); }
        if self.auto_increment {
            col.auto_increment();   // sea-query handles per-backend syntax
        }
        if self.not_null()    { col.not_null(); }
        if self.unique && !self.primary_key { col.unique_key(); }

        col
    }
}
```

sea-query's `ColumnDef::auto_increment()` emits:
- SQLite: `INTEGER PRIMARY KEY AUTOINCREMENT`
- MySQL: `BIGINT NOT NULL AUTO_INCREMENT`
- Postgres: `BIGSERIAL` (serial alias, equivalent to `BIGINT DEFAULT nextval(...)`)

## PyO3: Add `auto_increment` kwarg to `IntegerField` and `BigIntegerField`

```rust
// ormpi-py/src/fields.rs

// For IntegerField and BigIntegerField only — other fields don't support this
macro_rules! impl_integer_field_class {
    ($cls:ident, $ftype:expr) => {
        #[pyclass(name = stringify!($cls))]
        pub struct $cls {
            pub inner: FieldDef,
        }

        #[pymethods]
        impl $cls {
            #[new]
            #[pyo3(signature = (
                *,
                null = false,
                unique = false,
                primary_key = false,
                db_index = false,
                db_column = None,
                default = None,
                editable = true,
                auto_increment = false,   // ← NEW
            ))]
            fn new(
                null: bool,
                unique: bool,
                primary_key: bool,
                db_index: bool,
                db_column: Option<String>,
                default: Option<PyObject>,
                editable: bool,
                auto_increment: bool,
            ) -> Self {
                Self {
                    inner: FieldDef {
                        name: String::new(),
                        attname: String::new(),
                        field_type: $ftype,
                        null,
                        unique,
                        primary_key,
                        db_index,
                        db_column,
                        default: default.map(DefaultValue::PyObject),
                        editable,
                        auto_increment,
                    }
                }
            }
        }
    }
}

impl_integer_field_class!(PyIntegerField, FieldType::Integer);
impl_integer_field_class!(PyBigIntegerField, FieldType::BigInteger);
impl_integer_field_class!(PySmallIntegerField, FieldType::SmallInteger);
```

## Rust: Update Implicit PK Injection

In the model registry's `__init_subclass__` hook, when no primary key field is found,
inject a `BigIntegerField` instead of the old `BigAutoField`:

```rust
// ormpi-py/src/models.rs — inject_auto_pk()
fn inject_auto_pk() -> FieldDef {
    FieldDef {
        name: "id".to_string(),
        attname: "id".to_string(),
        field_type: FieldType::BigInteger,
        null: false,
        unique: false,
        primary_key: true,
        db_index: false,
        db_column: None,
        default: None,
        editable: false,
        auto_increment: true,   // ← key flag
    }
}
```

The resulting DDL on each backend:
- **SQLite**: `id INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT`
- **MySQL**: `id BIGINT NOT NULL AUTO_INCREMENT, PRIMARY KEY (id)`
- **Postgres**: `id BIGSERIAL PRIMARY KEY`

## Migration Engine: Remove AutoField Variant Handling

The `AutoDetector` and `MigrationOperation` logic that compares field types must no longer
recognize `AutoInteger` / `AutoBigInteger` / `AutoSmallInteger` variants. Because the
implicit PK is now a `BigInteger` with `auto_increment=True`, the field diffing logic
simply compares `FieldType::BigInteger` like any other integer field, plus checks the
`auto_increment` flag for changes.

```rust
// ormpi-core/src/migrations/detector.rs
fn field_changed(old: &FieldDef, new: &FieldDef) -> bool {
    old.field_type != new.field_type
        || old.null != new.null
        || old.unique != new.unique
        || old.auto_increment != new.auto_increment  // ← must compare this too
        || old.default != new.default
}
```
