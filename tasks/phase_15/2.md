# Task 15.2 — Fix `DoesNotExist` and `MultipleObjectsReturned` Exception Types

## Failing Tests

```
TestGet::test_get_does_not_exist
TestGet::test_model_does_not_exist_subclass
TestGet::test_multiple_objects_returned
TestDeleteEdgeCases::test_re_fetch_after_delete_raises
```

Errors:
```python
# test expects:  pytest.raises(DoesNotExist)
# actual raised: Exception("Author.DoesNotExist: Author matching query does not exist.")

# test expects:  pytest.raises(Author.DoesNotExist)
# actual raised: Exception("Author.DoesNotExist: Author matching query does not exist.")

# test expects:  pytest.raises(MultipleObjectsReturned)
# actual raised: Exception("get() returned more than one Author: 2 objects returned")
```

## Root Cause

`QuerySet.get()` in Rust raises `pyo3::exceptions::PyException` for both error cases:

```rust
// queryset.rs — get() method
Python::with_gil(|py| match rows.len() {
    0 => Err(pyo3::exceptions::PyException::new_err(format!(
        "{}.DoesNotExist: {} matching query does not exist.",
        state.model_name, state.model_name
    ))),
    1 => ...,
    n => Err(pyo3::exceptions::PyException::new_err(format!(
        "get() returned more than one {}: {} objects returned",
        state.model_name, n
    ))),
})
```

`PyException` is the base `Exception` class, not `DoesNotExist` or `MultipleObjectsReturned`.
Tests use `pytest.raises(DoesNotExist)` and `pytest.raises(Author.DoesNotExist)` which do
not catch a plain `Exception`.

## Fix — `ormpi-py/src/query/queryset.rs`

Raise the proper exceptions by looking up the model class and calling
`DoesNotExist`/`MultipleObjectsReturned` on it.

```rust
// In get() — after fetching rows, replace the error arms:
Python::with_gil(|py| match rows.len() {
    0 => {
        // Raise model-specific DoesNotExist (e.g. Author.DoesNotExist)
        let exc_msg = format!(
            "{} matching query does not exist.",
            state.model_name
        );
        if let Some(cls) = &model_class {
            if let Ok(does_not_exist) = cls.bind(py).getattr("DoesNotExist") {
                return Err(PyErr::from_value(
                    does_not_exist.call1((exc_msg,))
                        .unwrap_or_else(|_| py.None().into_bound(py))
                ));
            }
        }
        // Fallback: raise ormpi.exceptions.DoesNotExist
        let exc = py
            .import("ormpi.exceptions")
            .and_then(|m| m.getattr("DoesNotExist"))
            .and_then(|e| e.call1((exc_msg,)))
            .map_err(|e| e)?;
        Err(PyErr::from_value(exc))
    }
    1 => match &model_class {
        Some(cls) => row_to_instance(py, &rows[0], cls),
        None => Ok(py.None()),
    },
    n => {
        // Raise ormpi.exceptions.MultipleObjectsReturned
        let exc_msg = format!(
            "get() returned more than one {}: {} objects returned",
            state.model_name, n
        );
        let exc = py
            .import("ormpi.exceptions")
            .and_then(|m| m.getattr("MultipleObjectsReturned"))
            .and_then(|e| e.call1((exc_msg,)))
            .map_err(|e| e)?;
        Err(PyErr::from_value(exc))
    }
})
```

Also verify that `ormpi/exceptions.py` has `MultipleObjectsReturned` defined.

## Fix — `python/ormpi/exceptions.py`

Ensure both exception classes exist:

```python
class DoesNotExist(Exception):
    """Raised when get() finds no matching object."""

class MultipleObjectsReturned(Exception):
    """Raised when get() finds more than one matching object."""
```

## Fix — `python/ormpi/models.py`

Model-specific `DoesNotExist` is already attached in `__init_subclass__`:

```python
cls.DoesNotExist = type(
    "DoesNotExist",
    (DoesNotExist,),
    {"__module__": cls.__module__},
)
```

Add `MultipleObjectsReturned` here too so `Author.MultipleObjectsReturned` is available
(matches Django's pattern and makes test assertions cleaner):

```python
cls.MultipleObjectsReturned = type(
    "MultipleObjectsReturned",
    (MultipleObjectsReturned,),
    {"__module__": cls.__module__},
)
```

Import `MultipleObjectsReturned` at the top of `models.py`:

```python
from ormpi.exceptions import DoesNotExist, MultipleObjectsReturned
```
