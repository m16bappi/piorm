# Task 3 — Drop-Based Rollback for `OrmpiTransaction`

## Background

The doc mandates drop-based rollback as a correctness guarantee:

> **Drop-based rollback** — uncommitted `OrmpiTransaction` rolls back
> automatically on drop (spawns Tokio local task for async `ROLLBACK`).
>
> This means: **forgetting to call `rollback()` is not a bug** — the transaction
> rolls back automatically when it goes out of scope.

Currently `OrmpiTransaction` has no `Drop` implementation. If a transaction is
created and then dropped without calling `commit()` or `rollback()` (e.g. due
to an early return or a panic), the sqlx `Transaction` inside is dropped too —
sqlx itself will attempt to roll back, but this happens at the sqlx level
without the ORM being aware or updating its `TransactionState`. The
`PyTransaction` wrapper (`Arc<Mutex<Option<OrmpiTransaction>>>`) compounds this
because the inner `Option` may hold the transaction long after the Python object
is garbage-collected, depending on reference counting.

---

## Scope

Files to modify:

- `ormpi-core/src/transaction.rs` — add `Drop` impl with async rollback
- `ormpi-py/src/transaction.rs` — add `Drop` for `PyTransaction` (fires the
  Rust-side drop via the `Arc`)

## Design

```rust
impl Drop for OrmpiTransaction {
    fn drop(&mut self) {
        if self.state != TransactionState::Open {
            return; // already committed or rolled back — nothing to do
        }
        // Mark as rolled-back so any concurrent accessor (if somehow racing)
        // will see the correct state.
        self.state = TransactionState::RolledBack;

        // Extract the handle.  We need ownership to call `.rollback()`.
        // Replace with a dummy value using std::mem::replace.
        // Then spawn a fire-and-forget task for the async ROLLBACK.
        // Using tokio::spawn here is correct because Tokio's runtime is
        // always present (we require it for the Python async runtime).
        let handle = std::mem::replace(
            &mut self.handle,
            TransactionHandle::Dropped, // new sentinel variant
        );
        tokio::spawn(async move {
            match handle {
                TransactionHandle::Sqlite(t) => { let _ = (*t).rollback().await; }
                TransactionHandle::Mysql(t)  => { let _ = (*t).rollback().await; }
                TransactionHandle::Postgres(t) => { let _ = (*t).rollback().await; }
                TransactionHandle::Dropped => {}
            }
        });
    }
}
```

Add a `Dropped` sentinel variant to `TransactionHandle` so the `Drop` impl can
take ownership of the inner transaction without causing a second drop.

The `TransactionState` enum gets a new variant `Dropped` or reuses
`RolledBack` — using `RolledBack` is sufficient and avoids an extra variant.

For `PyTransaction`, ensure that when the Python object is garbage-collected
(i.e. `__del__` fires), the inner `Arc<Mutex<Option<OrmpiTransaction>>>` has
its `Option` taken, which triggers `OrmpiTransaction::drop` if the transaction
is still open.

## Test Cases

### Unit tests — `ormpi-core/src/transaction.rs`

**TC-3.1 — Drop rolls back an open transaction**
```rust
#[tokio::test]
async fn drop_rolls_back_open_transaction() {
    let pool = make_test_pool().await;
    sqlx::query("CREATE TABLE IF NOT EXISTS drop_test(id INT)")
        .execute(pool_conn(&pool)).await.unwrap();

    {
        let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
        txn.execute_raw("INSERT INTO drop_test VALUES (1)").await.unwrap();
        // drop without commit
    }

    // Give the spawned rollback task time to run
    tokio::time::sleep(std::time::Duration::from_millis(50)).await;

    let count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM drop_test")
        .fetch_one(pool_conn(&pool)).await.unwrap();
    assert_eq!(count, 0, "dropped transaction must have rolled back");
}
```

**TC-3.2 — Drop after commit does NOT roll back**
```rust
#[tokio::test]
async fn drop_after_commit_does_not_rollback() {
    let pool = make_test_pool().await;
    sqlx::query("CREATE TABLE IF NOT EXISTS drop_commit(id INT)")
        .execute(pool_conn(&pool)).await.unwrap();

    {
        let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
        txn.execute_raw("INSERT INTO drop_commit VALUES (42)").await.unwrap();
        txn.commit().await.unwrap(); // explicit commit
        // drop happens here — should NOT roll back the already-committed data
    }

    tokio::time::sleep(std::time::Duration::from_millis(50)).await;

    let count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM drop_commit")
        .fetch_one(pool_conn(&pool)).await.unwrap();
    assert_eq!(count, 1, "committed row must survive drop");
}
```

**TC-3.3 — Drop after explicit rollback does NOT double-rollback**
```rust
#[tokio::test]
async fn drop_after_explicit_rollback_no_double_rollback() {
    let pool = make_test_pool().await;
    let txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    txn.rollback().await.unwrap();
    // state is now RolledBack; drop should be a no-op
    // verified by the absence of a panic / error log
}
```

### Integration test — `__tests__/transactions/test_drop_rollback.py`

**TC-3.5 — Python: transaction garbage-collected without commit rolls back**
```python
@pytest.mark.asyncio
async def test_py_transaction_gc_rollback():
    import gc
    author = await Author.objects.create(name="Orig", email="orig@test.com")

    async def leaky_txn():
        txn = await ormpi.begin()
        await txn.execute_raw(
            f"UPDATE authors SET name='Leaked' WHERE id={author.pk}"
        )
        # txn goes out of scope without commit or rollback

    await leaky_txn()
    gc.collect()  # force Python GC

    # Allow async rollback task to complete
    import asyncio
    await asyncio.sleep(0.1)

    refetched = await Author.objects.get(pk=author.pk)
    assert refetched.name == "Orig", "GC-collected transaction must roll back"
```

**TC-3.6 — `atomic()` exception path rolls back and subsequent pool queries work**
```python
@pytest.mark.asyncio
async def test_atomic_exception_rollback_pool_recovers():
    with pytest.raises(ValueError):
        async with ormpi.transaction.atomic() as txn:
            await Author.objects.create(name="ShouldNotExist", email="x@test.com")
            # atomic.__aexit__ calls txn.rollback() on exception
            raise ValueError("force rollback")

    count = await Author.objects.filter(email="x@test.com").count()
    assert count == 0
    # Pool should be healthy for subsequent queries
    assert await Author.objects.count() >= 0
```
