# Task 14.1 — `base.rs`: `frozen` PyModel + `_field_bits` Registration

## Objective

Two changes to `ormpi-py/src/model/base.rs`:

1. Add `frozen` to the `#[pyclass]` macro on `PyModel` so that Python subclasses can
   safely declare `__slots__` without hitting PyO3's RefCell layout conflict.
2. Populate `_field_bits` (a `dict[str, int]` bitmask map) on each model class at
   registration time, so the new bitmask dirty-tracking in Task 14.2 and Task 14.3 has
   data to read.

This task has no runtime behaviour change — it is purely a prerequisite that unblocks the
rest of Phase 14.

---

## Background: Why `frozen` is Required

PyO3 adds a hidden `RefCell` tracking slot to every non-frozen `#[pyclass]` for runtime
borrow checking. Python's `__slots__` mechanism allocates a fixed-size object based on the
C struct layout declared in `tp_basicsize`. When a Python subclass tries to add its own
`__slots__`, Python computes the new `tp_basicsize` as parent size + slot count. If the
parent has an unexpected extra slot (the RefCell), the size calculation is wrong and Python
silently reverts to `__dict__` on the subclass — the `__slots__` declaration is ignored
without any error.

Adding `frozen` removes the RefCell. `PyModel` holds no mutable Rust fields at all (it is
an empty struct `{}`), so `frozen` is semantically correct.

## Change 1 — Add `frozen` to `PyModel`

**File:** `ormpi-py/src/model/base.rs`

```rust
// Before
#[pyclass(name = "Model", subclass)]
pub struct PyModel {}

// After
#[pyclass(name = "Model", subclass, frozen)]
pub struct PyModel {}
```

No other changes to `PyModel` or its `#[pymethods]` block are needed.

## Change 2 — Populate `_field_bits` in `_register_model_class`

**File:** `ormpi-py/src/model/base.rs`, function `_register_model_class`

After `model_def` is fully built and `ModelRegistry::global()` is written, and before the
function returns `Ok(())`, insert:

```rust
// ── Assign _field_bits for bitmask dirty tracking ─────────────────────
//
// Builds {"field_name": 1 << index} using the canonical field order from
// model_def.fields (an IndexMap — insertion-ordered).  This dict is
// stored as a ClassVar on the Python class so that __setattr__ in
// models.py and extract_dirty in instance.rs can both read it.

let field_bits_dict = PyDict::new_bound(py);
for (i, name) in model_def.fields.keys().enumerate() {
    field_bits_dict.set_item(name, 1u64 << i)?;
}
cls.setattr("_field_bits", field_bits_dict)?;
```

Place this block **after** the existing `cls.setattr("_ormpi_pk_field", ...)` line and
**before** the `cls.setattr("objects", ...)` line so the ordering mirrors the logical
sequence (pk field → bit map → manager).

### Why `1u64 << i`?

`u64` gives 64 clean bits with zero Python overhead for models up to 64 fields (the
overwhelming majority of real-world models). For models with more than 64 fields, Python's
arbitrary-precision integer takes over transparently — bitwise OR and AND still work
correctly, they just operate on a `PyLongObject` instead of a small int. No guard is
needed; the semantics are identical.

### Field ordering guarantee

`model_def.fields` is an `IndexMap<String, FieldDef>`. `IndexMap` preserves insertion
order. Insertion order in `_register_model_class` follows the Python class `__dict__`
iteration order, which is declaration order in CPython 3.7+. The auto-injected `id` field
is always inserted first when no explicit PK is declared (it uses `IndexMap::insert` at
the start of the loop). This means bit assignments are stable across process restarts as
long as the model definition does not change — important for any future serialisation.

## Verification

After this task, the following must hold in a Python shell:

```python
import ormpi
from ormpi.models import Model
from ormpi.fields import CharField, IntegerField

class Article(Model):
    title = CharField(max_length=200)
    views = IntegerField(default=0)

# _field_bits is set on the class
assert hasattr(Article, "_field_bits")
bits = Article._field_bits

# Every declared field + auto-id has a unique power-of-two bit
assert bits["id"]    == 1        # 1 << 0
assert bits["title"] == 2        # 1 << 1
assert bits["views"] == 4        # 1 << 2

# All bits are distinct (no two fields share a bit)
values = list(bits.values())
assert len(values) == len(set(values))

# No model instance has __dict__ after __slots__ is added in Task 14.2
# (cannot verify yet — this task only sets up the class-level data)
```
