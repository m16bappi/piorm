# Task 14.3 — `instance.rs`: Update Helpers, Save, Delete, Refresh

## Objective

Update `ormpi-py/src/model/instance.rs` to read and write the new slot-based instance
layout (`_values`, `_dirty` int bitmask, `_adding`, `_db`) instead of the old
`_ormpi_values` dict, `_ormpi_dirty` set, and `_ormpi_state` dict.

Five functions change: `extract_values`, `extract_dirty`, `get_is_adding`, and the
post-operation state writes inside `save()` and `refresh_from_db()`.

**Prerequisite:** Tasks 14.1 and 14.2 must be complete. The Python class must already
have `_field_bits` set (Task 14.1) and the Rust `PyModel` must be `frozen` before any
`__slots__` subclass will accept the new `setattr` calls correctly.

## Change 1 — `extract_values`

Rename the attribute from `_ormpi_values` to `_values`. Logic is otherwise identical.

```rust
/// Extract `_values` as `HashMap<String, OrmpiValue>` from a model instance.
pub(crate) fn extract_values(
    instance: &Bound<'_, PyAny>,
) -> PyResult<HashMap<String, OrmpiValue>> {
    let dict = instance
        .getattr("_values")?          // ← was "_ormpi_values"
        .downcast_into::<PyDict>()?;
    let mut map = HashMap::new();
    for (k, v) in dict.iter() {
        let key: String = k.extract()?;
        let val = py_to_ormpi_value(&v)?;
        map.insert(key, val);
    }
    Ok(map)
}
```

## Change 2 — `extract_dirty`

Replace the PySet-based implementation with a bitmask-based one. Read `_dirty` as `u64`,
then iterate `_field_bits` on the class to recover dirty field names.

```rust
/// Extract dirty field names from the `_dirty` integer bitmask on a model instance.
///
/// Reads `_dirty` (u64) from the instance and `_field_bits` (PyDict) from the class,
/// then returns the set of field names whose bit is set.
pub(crate) fn extract_dirty(instance: &Bound<'_, PyAny>) -> PyResult<HashSet<String>> {
    let dirty_mask: u64 = instance.getattr("_dirty")?.extract()?;

    // Fast path: nothing is dirty — skip the class lookup entirely.
    if dirty_mask == 0 {
        return Ok(HashSet::new());
    }

    let field_bits = instance
        .get_type()
        .getattr("_field_bits")?
        .downcast_into::<PyDict>()?;

    let mut dirty = HashSet::new();
    for (name, bit) in field_bits.iter() {
        let bit: u64 = bit.extract()?;
        if dirty_mask & bit != 0 {
            dirty.insert(name.extract::<String>()?);
        }
    }
    Ok(dirty)
}
```

### Import change

`PySet` is no longer needed. Remove it from the `use` statement at the top of the file:

```rust
// Before
use pyo3::types::{PyDict, PySet, PyTuple};

// After
use pyo3::types::{PyDict, PyTuple};
```

## Change 3 — `get_is_adding`

Replace the nested dict lookup with a direct flat slot read.

```rust
/// Read `_adding` bool directly from the instance slot.
fn get_is_adding(instance: &Bound<'_, PyAny>) -> PyResult<bool> {
    match instance.getattr("_adding") {
        Ok(v) => v.extract::<bool>().or(Ok(true)),
        Err(_) => Ok(true),   // conservative default during construction
    }
}
```

## Change 4 — Post-save state writes inside `save()`

The `Python::with_gil` block at the end of `save()` currently does:

```rust
// OLD
let values_dict = instance
    .getattr("_ormpi_values")?
    .downcast_into::<PyDict>()?;
values_dict.set_item(&model_def.pk_field, value_to_py(py, &pk))?;
instance
    .getattr("_ormpi_dirty")?
    .call_method0("clear")?;
let state = instance
    .getattr("_ormpi_state")?
    .downcast_into::<PyDict>()?;
state.set_item("adding", false)?;
state.set_item("db", &using)?;
```

Replace with:

```rust
// NEW
let values_dict = instance
    .getattr("_values")?                          // ← was "_ormpi_values"
    .downcast_into::<PyDict>()?;
values_dict.set_item(&model_def.pk_field, value_to_py(py, &pk))?;

instance.setattr("_dirty", 0u64)?;               // ← was set.clear()
instance.setattr("_adding", false)?;             // ← was state dict set_item
instance.setattr("_db", &using)?;               // ← was state dict set_item
```

Four separate getattr+downcast+method chains become four flat setattr calls. The total
number of Python C-API round-trips drops from ~9 to ~5.

```rust
let values_dict = instance
```

Replace with:

```rust
    .downcast_into::<PyDict>()?;
// ... set_item loop — unchanged ...
instance.setattr("_dirty", 0u64)?;               // ← was _ormpi_dirty.clear()
```

## `json_to_py` consolidation (bonus cleanup)

`refresh_from_db` uses a local `json_to_py(py, serde_json::Value)` function. The
`row_to_instance` path in `queryset.rs` uses `convert::ormpi_value_to_py`. These are two
parallel conversion paths that can drift. Replace the `json_to_py` call in
`refresh_from_db` with a fetch that returns `OrmpiValue` from the core layer, then pass
it through `crate::convert::value_to_py`. This is a quality-of-life cleanup and should
be done as part of this task rather than left for later.

Concretely, if `ormpi_core::model::executor::fetch_instance` returns
`Vec<(String, serde_json::Value)>` today, update the call site to use
`Vec<(String, OrmpiValue)>` if the core layer supports it, or keep the local conversion
but route through `value_to_py` for consistency. The key rule: **one conversion path for
all field values**.

## Verification

After this task (with Tasks 14.1 and 14.2 also in place):

```python
article = Article(title="Hello", views=0)

# _dirty is set after construction via __init__ kwargs
assert article._dirty == (Article._field_bits["title"] | Article._field_bits["views"])

await article.save()

# After save: dirty cleared, adding flipped, db set
assert article._dirty == 0
assert article._adding == False
assert article._db == "default"

# After refresh: dirty cleared, values updated
article.title = "Updated"
assert article._dirty & Article._field_bits["title"]
await article.refresh_from_db()
assert article._dirty == 0
```
