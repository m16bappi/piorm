# Task 14.4 — `queryset.rs`: 1-Allocation `row_to_instance`

## Objective

Update `ormpi-py/src/query/queryset.rs` so that `row_to_instance` makes exactly one heap
allocation per row (the `_values` dict) instead of three (the old `_ormpi_values` dict,
`_ormpi_state` dict, and `_ormpi_dirty` set). Rename all `_ormpi_*` attribute references
to the new flat slot names.

This is the hottest function in the read path — it runs once per row for every queryset
evaluation. At 50K rows it currently makes 150K bookkeeping allocations; after this task
it makes 50K.

**Prerequisite:** Tasks 14.1, 14.2, and 14.3 must be complete. The Python class must have
`__slots__` in place (Task 14.2) and `frozen` on the Rust base (Task 14.1) before
`setattr("_dirty", 0u64)` will land in the correct slot instead of a `__dict__`.

## Change — `row_to_instance`

**File:** `ormpi-py/src/query/queryset.rs`

```rust
// BEFORE — 3 allocations per row
pub(crate) fn row_to_instance(
    py: Python<'_>,
    row: &OrmpiRow,
    model_class: &PyObject,
) -> PyResult<PyObject> {
    // Allocation 1: call the class → triggers Python __init__ which creates _ormpi_values={}
    let instance = model_class.bind(py).call0()?;

    // Allocation 2: build and assign _ormpi_values dict
    let values = PyDict::new_bound(py);
    for (col_name, ormpi_val) in &row.values {
        let py_val = ormpi_value_to_py(py, ormpi_val);
        values.set_item(col_name, py_val)?;
    }
    instance.setattr("_ormpi_values", &values)?;

    // Allocation 3: _ormpi_state dict
    let state = PyDict::new_bound(py);
    state.set_item("adding", false)?;
    state.set_item("db", py.None())?;
    instance.setattr("_ormpi_state", &state)?;

    // Allocation 4 (in PySet::empty_bound): _ormpi_dirty set
    let dirty = PySet::empty_bound(py)?;
    instance.setattr("_ormpi_dirty", &dirty)?;

    Ok(instance.into())
}
```

```rust
// AFTER — 1 allocation per row
pub(crate) fn row_to_instance(
    py: Python<'_>,
    row: &OrmpiRow,
    model_class: &PyObject,
) -> PyResult<PyObject> {
    // call0() invokes Python __init__(**{}) which sets up the slots:
    //   _values = {}, _dirty = 0, _adding = True, _db = None
    // That __init__ allocates _values={}. We immediately overwrite it below.
    let instance = model_class.bind(py).call0()?;

    // ONLY allocation: build the populated _values dict and assign to slot.
    let values = PyDict::new_bound(py);
    for (col_name, ormpi_val) in &row.values {
        let py_val = ormpi_value_to_py(py, ormpi_val);
        values.set_item(col_name, py_val)?;
    }
    instance.setattr("_values", &values)?;    // ← was "_ormpi_values"

    // Flat slot writes — no extra allocations.
    instance.setattr("_dirty", 0u64)?;        // ← was PySet::empty_bound
    instance.setattr("_adding", false)?;      // ← was state dict set_item
    instance.setattr("_db", py.None())?;      // ← was state dict set_item

    Ok(instance.into())
}
```

### Why call0() still allocates `_values = {}`

`call0()` invokes `Model.__init__(**{})` which runs:

```python
def __init__(self, **kwargs):
    self._values = {}    # ← allocates an empty dict
    self._dirty  = 0
    self._adding = True
    self._db     = None
```

This empty `{}` is immediately replaced by the populated `values` dict two lines later.
The empty dict allocation is unavoidable without deeper changes to `__init__` (see
"Future optimisation" below). In practice one tiny empty dict followed immediately by an
overwrite is negligible — CPython's small-dict allocator reuses the same slab. The
important thing is that the **3 extra allocations** (state dict, dirty set, and old values
dict that used to stay around) are gone.

### `PySet` import

After this change, `PySet` is no longer used in `queryset.rs`. Remove it:

```rust
// Before
use pyo3::types::{PyDict, PySet};

// After
use pyo3::types::PyDict;
```

## Future optimisation (out of scope for Phase 14)

The empty `_values = {}` in `__init__` can be eliminated by adding a Rust-side
`__new__` bypass that constructs the instance without calling `__init__` and directly
populates the slots. This would reduce `row_to_instance` to zero Python-level calls
and pure Rust slot writes. That work is deferred because it requires a more invasive
change to the `PyModel` constructor and is better done after Phase 14 is verified in
production.
