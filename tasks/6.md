# Task 6: Pool Creation Macro in `pool.rs`

## Problem

`piorm-core/src/pool.rs` `PiormPool::connect` (lines 19–48) repeats the same pool options configuration for all three backends. The only differences are the `PoolOptions` type and the `PiormPool` variant constructed:

```rust
// pool.rs lines 19–47
match config.backend {
    DatabaseBackend::Sqlite => {
        let pool = sqlx::sqlite::SqlitePoolOptions::new()
            .max_connections(opts.max_connections)
            .min_connections(opts.min_connections)
            .acquire_timeout(opts.acquire_timeout)
            .connect(&url)
            .await?;
        Ok(PiormPool::Sqlite(pool))
    }
    DatabaseBackend::Mysql => {
        let pool = sqlx::mysql::MySqlPoolOptions::new()
            .max_connections(opts.max_connections)
            .min_connections(opts.min_connections)
            .acquire_timeout(opts.acquire_timeout)
            .connect(&url)
            .await?;
        Ok(PiormPool::Mysql(pool))
    }
    DatabaseBackend::Postgres => {
        let pool = sqlx::postgres::PgPoolOptions::new()
            .max_connections(opts.max_connections)
            .min_connections(opts.min_connections)
            .acquire_timeout(opts.acquire_timeout)
            .connect(&url)
            .await?;
        Ok(PiormPool::Postgres(pool))
    }
}
```

Adding a new pool option (e.g. `idle_timeout`, `connection_timeout`) currently requires editing three identical lines.

## Fix

Introduce a `connect_pool!` macro that expands the repeated option chain, and reduce the `connect` method body to three macro calls.

### New code for `piorm-core/src/pool.rs`

Add the macro before `impl PiormPool` and replace the match body:

```rust
/// Build a sqlx pool with the standard Piorm options and wrap it in the given `PiormPool` variant.
///
/// Usage: `connect_pool!(SqlitePoolOptions, Sqlite, &url, opts).await?`
macro_rules! connect_pool {
    ($options_ty:path, $variant:ident, $url:expr, $opts:expr) => {
        <$options_ty>::new()
            .max_connections($opts.max_connections)
            .min_connections($opts.min_connections)
            .acquire_timeout($opts.acquire_timeout)
            .connect($url)
            .await
            .map(PiormPool::$variant)
    };
}

impl PiormPool {
    /// Create a pool from a `DatabaseConfig`.
    pub async fn connect(config: &DatabaseConfig) -> crate::Result<Self> {
        use sqlx::{mysql::MySqlPoolOptions, postgres::PgPoolOptions, sqlite::SqlitePoolOptions};

        let url = config.connection_url();
        let opts = &config.pool;

        let pool = match config.backend {
            DatabaseBackend::Sqlite   => connect_pool!(SqlitePoolOptions, Sqlite,   &url, opts)?,
            DatabaseBackend::Mysql    => connect_pool!(MySqlPoolOptions,  Mysql,    &url, opts)?,
            DatabaseBackend::Postgres => connect_pool!(PgPoolOptions,     Postgres, &url, opts)?,
        };
        Ok(pool)
    }

    // ... rest of impl unchanged
}
```

Adding a future option like `idle_timeout` now requires a single-line change inside the macro.
