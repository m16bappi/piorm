# Task 8: Unify Duplicate `value_to_py` / `ormpi_value_to_py` Functions

## Problem

Two near-identical `OrmpiValue → PyObject` conversion functions exist in different files:

**`ormpi-py/src/convert.rs` — `value_to_py`** (the high-quality version):
```rust
// convert.rs lines 7–64
pub fn value_to_py(py: Python<'_>, value: &OrmpiValue) -> PyObject {
    match value {
        OrmpiValue::Date(d) => py.import_bound("datetime")
            .and_then(|m| m.getattr("date"))
            .and_then(|cls| cls.call1((d.year(), d.month(), d.day())))
            .map(|o| o.into())
            .unwrap_or_else(|_| d.to_string().into_py(py)),   // real Python datetime.date
        OrmpiValue::Json(j) => py.import_bound("json")
            .and_then(|m| m.getattr("loads"))
            .and_then(|loads| loads.call1((j.to_string(),)))
            .map(|o| o.into())
            .unwrap_or_else(|_| j.to_string().into_py(py)),  // parses to dict/list
        // ...
    }
}
```

**`ormpi-py/src/query/queryset.rs` — `ormpi_value_to_py`** (the degraded version):
```rust
// queryset.rs lines 174–195
pub(crate) fn ormpi_value_to_py(py: Python<'_>, value: &OrmpiValue) -> PyObject {
    match value {
        OrmpiValue::Date(d)     => d.to_string().into_py(py),    // ← string, not datetime.date
        OrmpiValue::Time(t)     => t.to_string().into_py(py),    // ← string
        OrmpiValue::DateTime(dt) => dt.to_string().into_py(py),  // ← string
        OrmpiValue::Json(j)     => j.to_string().into_py(py),    // ← string, not parsed
        // ...
    }
}
```

The degraded version in `queryset.rs` returns strings where the canonical version returns proper Python objects (`datetime.date`, `datetime.datetime`, parsed JSON dicts). Any instance loaded via `QuerySet` gets string dates; any instance loaded via `save()` or `refresh_from_db()` gets proper `datetime.date` objects. This is a silent inconsistency.

Additionally, `convert.rs::value_to_py` does not handle `OrmpiValue::Time` (missing arm). That gap should be filled.

## Fix

### Step 1 — Fill missing `Time` arm in `convert.rs`

```rust
// convert.rs — add after the Date arm (line 23):
OrmpiValue::Time(t) => {
    py.import_bound("datetime")
        .and_then(|m| m.getattr("time"))
        .and_then(|cls| cls.call1((t.hour(), t.minute(), t.second())))
        .map(|o| o.into())
        .unwrap_or_else(|_| t.to_string().into_py(py))
}
```

### Step 2 — Add `DateTime` handling to `convert.rs`

The existing `DateTime` arm (lines 31–46) only passes year/month/day/hour/minute/second. Add microseconds for full fidelity:

```rust
OrmpiValue::DateTime(dt) => {
    py.import_bound("datetime")
        .and_then(|m| m.getattr("datetime"))
        .and_then(|cls| {
            cls.call1((
                dt.year(), dt.month(), dt.day(),
                dt.hour(), dt.minute(), dt.second(),
                dt.nanosecond() / 1000, // microseconds
            ))
        })
        .map(|o| o.into())
        .unwrap_or_else(|_| dt.to_string().into_py(py))
}
```

### Step 3 — Delete `ormpi_value_to_py` from `queryset.rs`

Delete `queryset.rs` lines 174–195 entirely.

### Step 4 — Replace every call site in `queryset.rs`

Change all calls from `ormpi_value_to_py(py, v)` to `crate::convert::value_to_py(py, v)`:

```rust
// queryset.rs — every occurrence:
// Before:
ormpi_value_to_py(py, v)
// After:
crate::convert::value_to_py(py, v)
```

Affected lines (search for `ormpi_value_to_py`): lines ~161, ~183, ~212, ~224, ~228, ~239, and inside `hydrate_with_select_related`.

## Files Changed

- `ormpi-py/src/convert.rs` — add `Time` arm, improve `DateTime` microseconds
- `ormpi-py/src/query/queryset.rs` — delete `ormpi_value_to_py`, replace all call sites
