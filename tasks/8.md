# Task 8 — Savepoint Name Safety + Savepoint Depth Tracking

## Background

### Problem 1 — Collision-prone savepoint names

`ormpi-py/src/lib.rs` generates savepoint names using subsecond nanoseconds:

```rust
let nanos = SystemTime::now()
    .duration_since(UNIX_EPOCH)
    .map(|d| d.subsec_nanos())
    .unwrap_or(0);
let sp_name = format!("sp_{:08x}", nanos);
```

`subsec_nanos()` returns a value in `0..1_000_000_000` (30 bits), encoded as
8 hex digits. On modern hardware two savepoints created within the same
nanosecond will share the same name — a silent correctness bug. A concurrent
test suite or a tight loop absolutely hits this.

### Problem 2 — No depth counter on `OrmpiTransaction`

The doc describes savepoints as the automatic nesting primitive:

> `transaction()` called on a `DatabaseTransaction` issues `SAVEPOINT` — Never
> issues nested `BEGIN`.

`OrmpiTransaction` currently has no internal savepoint counter.  This means:

- Concurrent calls to `create_savepoint` on the same transaction can generate
  the same name.
- There is no way to validate that a `RELEASE SAVEPOINT` or
  `ROLLBACK TO SAVEPOINT` references a savepoint that actually belongs to this
  transaction.

### Problem 3 — Savepoints not tracked for validation

If `rollback_to_savepoint(txn, "sp_nonexistent")` is called with a name that
was never created, the database emits an error — but the Python caller gets
only a generic `RuntimeError`. There is no pre-flight validation.

---

## Scope

Files to modify:

- `ormpi-core/src/transaction.rs` — add `savepoint_depth: u32` counter and
  a `HashSet<String>` of active savepoint names
- `ormpi-py/src/lib.rs` — replace `subsec_nanos` with a per-transaction
  atomic counter for savepoint naming
- `python/ormpi/transaction.py` — no change required if Rust side is fixed,
  but update savepoint name generation if it exists in Python

## Design

### Rust counter-based naming

```rust
pub struct OrmpiTransaction {
    pub handle: TransactionHandle,
    pub alias: String,
    pub state: TransactionState,
    savepoint_counter: u32,             // NEW
    active_savepoints: HashSet<String>, // NEW
}

impl OrmpiTransaction {
    pub fn next_savepoint_name(&mut self) -> String {
        self.savepoint_counter += 1;
        format!("sp_{:04}", self.savepoint_counter)
    }

    pub async fn create_savepoint(&mut self) -> crate::Result<String> {
        let name = self.next_savepoint_name();
        self.execute_raw(&format!("SAVEPOINT {name}")).await?;
        self.active_savepoints.insert(name.clone());
        Ok(name)
    }

    pub async fn release_savepoint(&mut self, name: &str) -> crate::Result<()> {
        if !self.active_savepoints.contains(name) {
            return Err(OrmpiError::TransactionError(
                format!("No active savepoint named '{name}'"),
            ));
        }
        self.execute_raw(&format!("RELEASE SAVEPOINT {name}")).await?;
        self.active_savepoints.remove(name);
        Ok(())
    }

    pub async fn rollback_to_savepoint(&mut self, name: &str) -> crate::Result<()> {
        if !self.active_savepoints.contains(name) {
            return Err(OrmpiError::TransactionError(
                format!("No active savepoint named '{name}'"),
            ));
        }
        self.execute_raw(&format!("ROLLBACK TO SAVEPOINT {name}")).await?;
        // Savepoint remains active after ROLLBACK TO (can be re-used)
        Ok(())
    }
}
```

The `create_savepoint` / `release_savepoint` / `rollback_to_savepoint` free
functions in `lib.rs` are updated to delegate to these new methods instead of
generating ad-hoc SQL.

## Test Cases

### Unit tests — `ormpi-core/src/transaction.rs`

**TC-8.1 — Savepoint names are unique within a transaction**
```rust
#[tokio::test]
async fn savepoint_names_are_unique() {
    let pool = make_test_pool().await;
    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    let n1 = txn.create_savepoint().await.unwrap();
    let n2 = txn.create_savepoint().await.unwrap();
    let n3 = txn.create_savepoint().await.unwrap();
    assert_ne!(n1, n2);
    assert_ne!(n2, n3);
    txn.rollback().await.unwrap();
}
```

**TC-8.2 — Release savepoint succeeds for an active savepoint**
```rust
#[tokio::test]
async fn release_active_savepoint_succeeds() {
    let pool = make_test_pool().await;
    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    let sp = txn.create_savepoint().await.unwrap();
    txn.release_savepoint(&sp).await.unwrap();
    txn.commit().await.unwrap();
}
```

**TC-8.3 — Release unknown savepoint returns error**
```rust
#[tokio::test]
async fn release_unknown_savepoint_returns_error() {
    let pool = make_test_pool().await;
    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    let err = txn.release_savepoint("sp_ghost").await.unwrap_err();
    assert!(err.to_string().contains("sp_ghost"));
    txn.rollback().await.unwrap();
}
```

**TC-8.4 — `rollback_to_savepoint` rolls back data without ending transaction**
```rust
#[tokio::test]
async fn rollback_to_savepoint_partial_rollback() {
    let pool = make_test_pool().await;
    pool_exec(&pool, "CREATE TABLE IF NOT EXISTS sp_tbl(v INT)").await;
    pool_exec(&pool, "INSERT INTO sp_tbl VALUES (1)").await;

    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    txn.execute_raw("INSERT INTO sp_tbl VALUES (2)").await.unwrap();
    let sp = txn.create_savepoint().await.unwrap();
    txn.execute_raw("INSERT INTO sp_tbl VALUES (3)").await.unwrap();

    txn.rollback_to_savepoint(&sp).await.unwrap();
    txn.commit().await.unwrap();

    let count: i64 = pool_scalar(&pool, "SELECT COUNT(*) FROM sp_tbl").await;
    // rows: 1 (pre-existing) + 2 (before savepoint) = 2; row 3 rolled back
    assert_eq!(count, 2);
}
```

**TC-8.5 — Counter increments sequentially across multiple savepoints**
```rust
#[tokio::test]
async fn savepoint_counter_increments() {
    let pool = make_test_pool().await;
    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    let names: Vec<_> = (0..5)
        .map(|_| txn.next_savepoint_name())
        .collect();
    // Names should be sp_0001, sp_0002, ... (or similar sequential scheme)
    for (i, name) in names.iter().enumerate() {
        assert!(name.contains(&(i + 1).to_string()),
            "Expected sequential savepoint name, got {name}");
    }
    txn.rollback().await.unwrap();
}
```

**TC-8.8 — `atomic()` nested block partial rollback via savepoint**
```python
@pytest.mark.asyncio
async def test_nested_atomic_savepoint_partial_rollback():
    async with ormpi.transaction.atomic() as outer:
        await Author.objects.create(name="Outer", email="o@test.com")
        try:
            async with ormpi.transaction.atomic():
                await Author.objects.create(name="Inner", email="i@test.com")
                raise ValueError("inner fails")
        except ValueError:
            pass  # savepoint rolled back, outer continues

    assert await Author.objects.filter(email="o@test.com").count() == 1
    assert await Author.objects.filter(email="i@test.com").count() == 0
```

**TC-8.9 — Three-level nesting: middle rollback preserves outer and inner-inner**
```python
@pytest.mark.asyncio
async def test_three_level_nesting():
    async with ormpi.transaction.atomic():
        await Author.objects.create(name="L1", email="l1@test.com")
        try:
            async with ormpi.transaction.atomic():
                await Author.objects.create(name="L2", email="l2@test.com")
                async with ormpi.transaction.atomic():
                    await Author.objects.create(name="L3", email="l3@test.com")
                raise ValueError("L2 fails after L3 committed to SP")
        except ValueError:
            pass

    assert await Author.objects.filter(email="l1@test.com").count() == 1
    assert await Author.objects.filter(email="l2@test.com").count() == 0
    assert await Author.objects.filter(email="l3@test.com").count() == 0
```

## Acceptance Criteria

- [ ] Savepoint names are generated via a per-transaction atomic counter —
  no `SystemTime` / `subsec_nanos` used.
- [ ] `OrmpiTransaction` tracks active savepoints in a `HashSet`.
- [ ] `release_savepoint` and `rollback_to_savepoint` return
  `Err(TransactionError)` for unknown savepoint names (pre-flight validation).
- [ ] TC-8.1 through TC-8.5 pass under `cargo test -p ormpi-core`.
- [ ] TC-8.6 through TC-8.9 pass under `pytest`.
- [ ] No `subsec_nanos` or `SystemTime` remains in savepoint name generation.
- [ ] `cargo clippy -p ormpi-core -- -D warnings` passes.
