# Task 19.1 — Fix Aggregate Type Identity (`Count`, `Sum`, `Avg`, `Max`, `Min`)

## Failing Tests

```
TestAggregate::test_count
TestAggregate::test_sum
TestAggregate::test_avg
TestAggregate::test_max
TestAggregate::test_min
TestAggregate::test_count_distinct
TestAggregate::test_multiple_aggregates
TestAggregate::test_aggregate_on_filtered_qs
```

Error:
```
TypeError: Expected an aggregate function (Count, Sum, Avg, Max, Min)
```

## Root Cause

Same type-identity problem as Q objects (Task 15.1). `ormpi.expr.Count` and
`ormpi._core.Count` are **different Python type objects** because `expr.py` re-exports
them under a different module path.

Verified:
```python
from ormpi._core import Count as CC
from ormpi.expr import Count as EC
assert CC is EC   # FAILS
```

`extract_aggregate_expr()` in `query/aggregate.rs` uses `obj.downcast::<PyCount>()` which
checks against the Rust-registered `_core.Count` type. When the user imports
`from ormpi.expr import Count`, they get a different type object, so the downcast fails.

## Fix — Same approach as Task 15.1

### Fix 1 — `python/ormpi/expr.py`

Remove the `try/except ImportError` fallback (already done in Task 15.1). The
unconditional import ensures `ormpi.expr.Count` IS `ormpi._core.Count`.

If Task 15.1 is already implemented, this fix is already in place.

### Fix 2 — `ormpi-py/src/query/aggregate.rs`

As a belt-and-suspenders fix, change `extract_aggregate_expr` to use
`extract::<PyRef<T>>()` instead of `downcast::<T>()`:

```rust
pub(crate) fn extract_aggregate_expr(obj: &Bound<'_, PyAny>) -> PyResult<AggregateExpr> {
    if let Ok(c) = obj.extract::<pyo3::PyRef<PyCount>>() {
        return Ok(c.inner.clone());
    }
    if let Ok(s) = obj.extract::<pyo3::PyRef<PySum>>() {
        return Ok(s.inner.clone());
    }
    if let Ok(a) = obj.extract::<pyo3::PyRef<PyAvg>>() {
        return Ok(a.inner.clone());
    }
    if let Ok(m) = obj.extract::<pyo3::PyRef<PyMax>>() {
        return Ok(m.inner.clone());
    }
    if let Ok(m) = obj.extract::<pyo3::PyRef<PyMin>>() {
        return Ok(m.inner.clone());
    }
    Err(pyo3::exceptions::PyTypeError::new_err(
        "Expected an aggregate function (Count, Sum, Avg, Max, Min)",
    ))
}
```

`extract::<PyRef<T>>()` uses the extract protocol which is more forgiving of class
identity differences than `downcast`.
