# Task 22.3 — Replace Brittle String-Based Type Detection in `py_to_value`

## Problem

`py_to_value` (currently `py_to_ormpi_value`) detects Python object types by
comparing class name strings:

```rust
let type_name = obj.get_type().name()
    .map(|n| n.extract::<String>().unwrap_or_default())
    .unwrap_or_default();

if type_name == "_FExpr" {
    // handle F() expression
}
```

Issues:
1. **Breaks on subclassing**: If Python code subclasses `_FExpr`, `type_name` will be
   the subclass name, not `"_FExpr"`, and the branch is silently skipped.
2. **Breaks on renaming**: Any Python-side refactor of `_FExpr` to another name
   silently breaks expression support without a compile error.
3. **Class name collisions**: Unrelated Python classes named `_FExpr` (from other
   modules) would incorrectly match.

The same fragility applies if the pattern is used elsewhere (e.g. for detecting
datetime objects, model instances).

## Fix

### Step 1 — Use `hasattr` for structural duck-typing on `_FExpr`

Instead of matching on the class name, check for the attributes that define the
`_FExpr` protocol (`lhs`, `op`, `rhs`):

```rust
// Detect F() expression by its protocol (lhs, op, rhs attributes)
let is_fexpr = obj.hasattr("lhs").unwrap_or(false)
    && obj.hasattr("op").unwrap_or(false)
    && obj.hasattr("rhs").unwrap_or(false);

if is_fexpr {
    let lhs_obj = obj.getattr("lhs")?;
    let op_obj  = obj.getattr("op")?;
    let rhs_obj = obj.getattr("rhs")?;
    // ...
}
```

This is duck-typed, subclass-safe, and rename-tolerant.

### Step 2 — Use `is_instance_of` for model instance detection

Model instances are detected by checking for a `.pk` attribute. Make this more robust:

```rust
// Before: implicit check via successful .getattr("pk")
// After: explicit is-model-instance check

// Check if the object is a PyInstance by looking for both `pk` and `_meta`
// which all ormpi model instances have.
let is_model_instance = obj.hasattr("pk").unwrap_or(false)
    && obj.hasattr("_meta").unwrap_or(false);
```

### Step 3 — (Optional) Cache the `_FExpr` class once

If performance of `hasattr` checks is a concern (called on every filter value), cache
the `_FExpr` class as a Python-side singleton accessible via `ormpi._expressions._FExpr`
and use `obj.is_instance(fexpr_cls)?`:

```rust
// One-time setup at configure() time
let fexpr_cls = py.import_bound("ormpi._expressions")?
    .getattr("_FExpr")?
    .into_py(py);

// At conversion time
if obj.is_instance(fexpr_cls.bind(py))? { ... }
```

Implement only if `hasattr` checks prove to be a bottleneck in profiling.

### Step 4 — Remove the `type_name` variable

After replacing the string check with `hasattr`, the `type_name` variable becomes
unused. Remove it along with the `get_type().name()` extraction chain entirely.

## Acceptance Criteria

- [ ] `py_to_value` does not reference `type_name` or any class-name string comparison
- [ ] `_FExpr` detection uses `hasattr("lhs") && hasattr("op") && hasattr("rhs")`
- [ ] Subclasses of `_FExpr` are correctly detected
- [ ] Model instance detection uses `hasattr("pk") && hasattr("_meta")`
- [ ] All Python tests that exercise F() expressions pass
- [ ] `cargo clippy -p ormpi-py` passes cleanly
