# Task 22.5 — Dead Code & Unused Import Cleanup in `ormpi-py`

## Problem

`ormpi-py` accumulates unused imports and dead code as features are added and refactored.
This slows compilation, misleads readers, and may hide logical errors.

## Audit Procedure

```bash
# Full dead-code and unused-import sweep
RUSTFLAGS="-D dead_code -D unused_imports -D unused_variables -D unused_mut" \
    cargo check -p ormpi-py 2>&1 | grep "warning:"

cargo clippy -p ormpi-py --all-targets -- \
    -W clippy::unused_imports \
    -W clippy::dead_code \
    -W clippy::unused_variables \
    2>&1 | grep "warning:"
```

## Known Targets

### A — `lib.rs` unused imports after `json_to_py` move (task 22.4)

After moving `json_to_py` to `convert.rs`, the `serde_json` import and
`PyTuple`, `PyList`, `PyString` imports in `lib.rs` may become unused. Confirm and
remove.

### B — `model/instance.rs` imports after `py_to_ormpi_value` move (task 22.1)

```rust
// model/instance.rs — likely unused after move
use std::collections::{HashMap, HashSet};
use pyo3::types::{PyDict, PyList, PyTuple};
use ormpi_core::value::{FExprNode, FExprOp, OrmpiValue};
```

If `py_to_value` is moved to `convert.rs`, these imports may only be needed there.
Remove from `instance.rs` if no other code in that file requires them.

### C — `routing.rs` — verify all exported functions are called

```rust
// routing.rs
pub(crate) fn resolve_database_alias(...) -> ...
pub(crate) fn resolve_read_alias(...) -> ...
```

Check that both functions are called from `model/base.rs` or `query/queryset.rs`. If
either is unused, remove.

### D — `db/connections.rs` — audit exported functions

Verify every `pub` or `pub(crate)` function in `db/connections.rs` has at least one
caller outside itself. Remove dead exports.

### E — `fields/` module — unused FieldDef construction helpers

Some field constructors in `fields/scalar.rs`, `fields/temporal.rs`, etc. may build
`FieldDef` fields that are always overridden by Python-side defaults. Audit whether
the Rust-side defaults matter or are always overwritten.

### F — `query/iter.rs` — verify iterator is used

If `PyQuerySetIterator` or related iterator types are defined but the Python async
iteration protocol is handled differently, check whether the Rust iterator code is
actually invoked.

## Fix Process

1. Run the audit commands above and collect all warnings
2. For each unused item, determine if it is:
   - Truly dead → remove
   - Public API used by Python callers → mark with `#[allow(dead_code)]` +
     comment `// Used by Python via PyO3`
   - Test helper → move under `#[cfg(test)]`
3. After cleanup, re-run `cargo clippy` to confirm zero warnings

## Acceptance Criteria

- [ ] `cargo check -p ormpi-py` emits zero `dead_code` / `unused_imports` warnings
- [ ] Removed items are confirmed unused (not just not referenced in Rust — also not
      accessible via PyO3 `#[pyfunction]` or `#[pymethods]`)
- [ ] `cargo build -p ormpi-py` and `cargo test -p ormpi-py` pass cleanly
