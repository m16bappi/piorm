# Task 22.7 — Standardize `FExprOp` String Matching in `py_to_value`

## Problem

`py_to_value` (after task 22.1 rename) maps F()-expression operator strings to
`FExprOp` using a hand-rolled `match`:

```rust
let op = match op_s.as_str() {
    "+" => FExprOp::Add,
    "-" => FExprOp::Sub,
    "*" => FExprOp::Mul,
    "/" => FExprOp::Div,
    "%" => FExprOp::Mod,
    other => return Err(pyo3::exceptions::PyValueError::new_err(
        format!("Unknown F() operator: {}", other)
    )),
};
```

This duplicates the operator ↔ string mapping that already needs to exist in the
Python side when constructing `_FExpr` objects. If a new operator is added to
`FExprOp`, this match must be updated manually — with no compile-time reminder.

Additionally, `FExprOp` has no `Display` implementation, so if a value needs to be
round-tripped back to a string (e.g. for error messages, logging, or serialization),
there is no standard way to do it.

## Fix

### Step 1 — Implement `TryFrom<&str> for FExprOp`

Move the operator-string mapping into `ormpi-core/src/value.rs` as a standard trait:

```rust
// ormpi-core/src/value.rs

use std::fmt;

impl fmt::Display for FExprOp {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let s = match self {
            FExprOp::Add => "+",
            FExprOp::Sub => "-",
            FExprOp::Mul => "*",
            FExprOp::Div => "/",
            FExprOp::Mod => "%",
        };
        write!(f, "{s}")
    }
}

#[derive(Debug)]
pub struct UnknownOperator(pub String);

impl fmt::Display for UnknownOperator {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "Unknown F() operator: {}", self.0)
    }
}

impl std::error::Error for UnknownOperator {}

impl TryFrom<&str> for FExprOp {
    type Error = UnknownOperator;

    fn try_from(s: &str) -> Result<Self, Self::Error> {
        match s {
            "+" => Ok(Self::Add),
            "-" => Ok(Self::Sub),
            "*" => Ok(Self::Mul),
            "/" => Ok(Self::Div),
            "%" => Ok(Self::Mod),
            other => Err(UnknownOperator(other.to_string())),
        }
    }
}
```

### Step 2 — Update `py_to_value` to use `TryFrom`

```rust
// convert.rs (after task 22.1)
let op_s: String = op_obj.extract()?;
let op = FExprOp::try_from(op_s.as_str())
    .map_err(|e| pyo3::exceptions::PyValueError::new_err(e.to_string()))?;
```

The error message is identical, but now the mapping is authoritative in `ormpi-core`
and `ormpi-py` has zero knowledge of which operators exist.

### Step 3 — Use `Display` in error messages and SQL generation

Anywhere `FExprOp` needs to be rendered (e.g. in `query/evaluate.rs` for F-expression
SQL building), use `op.to_string()` or `format!("{op}")` instead of a separate match.

### Step 4 — Add exhaustiveness test in `ormpi-core`

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn fexpr_op_roundtrip() {
        let ops = [FExprOp::Add, FExprOp::Sub, FExprOp::Mul, FExprOp::Div, FExprOp::Mod];
        for op in ops {
            let s = op.to_string();
            let parsed = FExprOp::try_from(s.as_str()).expect("roundtrip failed");
            assert_eq!(op, parsed);
        }
    }

    #[test]
    fn fexpr_op_unknown_returns_error() {
        assert!(FExprOp::try_from("^").is_err());
    }
}
```
