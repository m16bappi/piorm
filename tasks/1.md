# Task 1 — Remove `unsafe transmute` from `OrmpiTransaction::begin`

## Background

`ormpi-core/src/transaction.rs` currently extends the lifetime of the sqlx
`Transaction<'_, DB>` to `'static` via `std::mem::transmute`:

```rust
// SAFETY: Pool lives in the global registry (process lifetime).
let txn: sqlx::Transaction<'static, sqlx::Sqlite> =
    unsafe { std::mem::transmute(txn) };
```

The doc explicitly flags this as unsafe unsoundness to eliminate:

> **Remove `unsafe transmute`** — hold the pool alive separately and let sqlx
> own the transaction lifetime, no `'static` extension needed.

The correct fix is to clone the `OrmpiPool` (which is `Clone`) into the
`OrmpiTransaction` so that the struct itself keeps the pool alive, making the
borrow trivially valid for the struct's own lifetime.

---

## Scope

Files touched:

- `ormpi-core/src/transaction.rs` — primary change
- `ormpi-core/src/pool.rs` — no changes expected; `OrmpiPool: Clone` already
- `ormpi-py/src/transaction.rs` — verify `PyTransaction` still compiles after
  the struct layout change

---

## Implementation Notes

Replace the `TransactionHandle` enum's inner type from
`Box<sqlx::Transaction<'static, DB>>` to a design that ties the transaction
lifetime to the enclosing struct. Because sqlx transactions borrow from their
pool, the cleanest approach is:

1. Store a `_pool: OrmpiPool` field in `OrmpiTransaction` to keep the pool
   alive for the struct's lifetime.
2. Use an enum variant that stores the transaction with its natural (non-static)
   lifetime, or use `Box<dyn …>` / dynamic dispatch if the mixed-lifetime enum
   proves awkward. An alternative that avoids lifetime parameters entirely is to
   store a raw `sqlx::pool::PoolConnection<DB>` and issue `BEGIN` manually via
   `execute_raw`, which is what SeaORM does internally.
3. Remove every `unsafe { std::mem::transmute(txn) }` call.
4. No `unsafe` blocks should remain in `transaction.rs` after this task.

**TC-1.4 — execute_raw runs inside the transaction connection**
```rust
#[tokio::test]
async fn execute_raw_inside_transaction() {
    let pool = make_test_pool().await;
    sqlx::query("CREATE TABLE IF NOT EXISTS t1(id INTEGER)")
        .execute(pool_conn(&pool))
        .await
        .unwrap();
    let mut txn = OrmpiTransaction::begin(&pool, "default").await.unwrap();
    txn.execute_raw("INSERT INTO t1 VALUES (1)").await.unwrap();
    txn.rollback().await.unwrap();
    // Row should not be visible after rollback
    let count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM t1")
        .fetch_one(pool_conn(&pool))
        .await
        .unwrap();
    assert_eq!(count, 0);
}
```

### Integration test — `__tests__/transactions/test_begin_commit.py`

**TC-1.6 — Python begin/commit round-trip still works after Rust refactor**
```python
@pytest.mark.asyncio
async def test_begin_commit_no_transmute_regression():
    txn = await ormpi.begin()
    assert txn.is_open
    await txn.commit()
    assert not txn.is_open
```

**TC-1.7 — Rollback isolation is preserved**
```python
@pytest.mark.asyncio
async def test_rollback_isolation():
    author = await Author.objects.create(name="Before", email="b@test.com")
    txn = await ormpi.begin()
    # Raw insert via the transaction (will be rolled back)
    await txn.execute_raw(
        f"UPDATE authors SET name='Inside' WHERE id={author.pk}"
    )
    await txn.rollback()
    refetched = await Author.objects.get(pk=author.pk)
    assert refetched.name == "Before"
```
