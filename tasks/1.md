# Task 1: Macro-Based `QueryBackend::build_*` in `backend.rs`

## Problem

`piorm-core/src/backend.rs` contains 8 methods in `QueryBackend`, each a 3-arm match block that is structurally identical — only the method name and return type differ. This is pure boilerplate.

```rust
// backend.rs lines 49–111: 8 methods, all identical pattern
pub fn build_select(&self, stmt: &SelectStatement) -> (String, Values) {
    match self.0 {
        DatabaseBackend::Sqlite   => stmt.build(SqliteQueryBuilder),
        DatabaseBackend::Mysql    => stmt.build(MysqlQueryBuilder),
        DatabaseBackend::Postgres => stmt.build(PostgresQueryBuilder),
    }
}

pub fn build_insert(&self, stmt: &InsertStatement) -> (String, Values) {
    match self.0 {
        DatabaseBackend::Sqlite   => stmt.build(SqliteQueryBuilder),
        DatabaseBackend::Mysql    => stmt.build(MysqlQueryBuilder),
        DatabaseBackend::Postgres => stmt.build(PostgresQueryBuilder),
    }
}

// … build_update, build_delete: same pattern, returns (String, Values)

pub fn build_table_create(&self, stmt: &TableCreateStatement) -> String {
    match self.0 {
        DatabaseBackend::Sqlite   => stmt.to_string(SqliteQueryBuilder),
        DatabaseBackend::Mysql    => stmt.to_string(MysqlQueryBuilder),
        DatabaseBackend::Postgres => stmt.to_string(PostgresQueryBuilder),
    }
}

// … build_table_alter, build_table_drop, build_index_create: same pattern, returns String
```

## Fix

Introduce two internal macros — `build_query_stmt!` (for statements that return `(String, Values)` via `.build(...)`) and `build_ddl_stmt!` (for DDL that returns `String` via `.to_string(...)`). Each method collapses to a one-liner macro call.

### New code for `piorm-core/src/backend.rs`

Replace the entire `impl QueryBackend` block (lines 48–112) with:

```rust
// ── Internal dispatch macros ──────────────────────────────────────────────────

/// Dispatch a sea-query DML/DQL statement builder to the correct dialect.
/// Returns `(String, Values)`.
macro_rules! build_query_stmt {
    ($backend:expr, $stmt:expr) => {
        match $backend {
            DatabaseBackend::Sqlite   => $stmt.build(SqliteQueryBuilder),
            DatabaseBackend::Mysql    => $stmt.build(MysqlQueryBuilder),
            DatabaseBackend::Postgres => $stmt.build(PostgresQueryBuilder),
        }
    };
}

/// Dispatch a sea-query DDL statement builder to the correct dialect.
/// Returns `String`.
macro_rules! build_ddl_stmt {
    ($backend:expr, $stmt:expr) => {
        match $backend {
            DatabaseBackend::Sqlite   => $stmt.to_string(SqliteQueryBuilder),
            DatabaseBackend::Mysql    => $stmt.to_string(MysqlQueryBuilder),
            DatabaseBackend::Postgres => $stmt.to_string(PostgresQueryBuilder),
        }
    };
}

/// Wraps sea-query builders to provide a unified interface.
#[derive(Debug, Clone, Copy)]
pub struct QueryBackend(pub DatabaseBackend);

impl QueryBackend {
    pub fn build_select(&self, stmt: &SelectStatement) -> (String, Values) {
        build_query_stmt!(self.0, stmt)
    }

    pub fn build_insert(&self, stmt: &InsertStatement) -> (String, Values) {
        build_query_stmt!(self.0, stmt)
    }

    pub fn build_update(&self, stmt: &UpdateStatement) -> (String, Values) {
        build_query_stmt!(self.0, stmt)
    }

    pub fn build_delete(&self, stmt: &DeleteStatement) -> (String, Values) {
        build_query_stmt!(self.0, stmt)
    }

    pub fn build_table_create(&self, stmt: &TableCreateStatement) -> String {
        build_ddl_stmt!(self.0, stmt)
    }

    pub fn build_table_alter(&self, stmt: &TableAlterStatement) -> String {
        build_ddl_stmt!(self.0, stmt)
    }

    pub fn build_table_drop(&self, stmt: &TableDropStatement) -> String {
        build_ddl_stmt!(self.0, stmt)
    }

    pub fn build_index_create(&self, stmt: &IndexCreateStatement) -> String {
        build_ddl_stmt!(self.0, stmt)
    }
}
```

The `impl QueryBackend` block shrinks from ~64 lines to ~26 lines. The macros are `macro_rules!` — zero runtime cost, no external dependencies.
